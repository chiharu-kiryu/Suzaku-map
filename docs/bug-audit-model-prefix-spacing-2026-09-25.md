## N52：中文模型候选在解析和合并时丢失字面空白

此前本地中文转换已经保留字面缩进，但模型链路仍有两处独立裁剪：

1. [提供器](../src/languages/model.rs) 对 CJK 的本地转换前缀先做 `trim`，英文却
   保留完整前缀。请求要求精确保留 `local_conversion`，响应检查却允许删除其空白。
2. [IBus 混排](../src/ime/candidate_mix.rs) 和 [独立引擎](../src/ime/core_engine.rs)
   合并模型结果时，仅为英文保留前缀，其余语言再次裁剪返回正文。

先加入回归，修复前分别失败：

- 前缀检查把 `  你好` 缩成 `你好`。
- 两种 HTTP 协议共用的回归在 compatible 分支收到 `  你好，合成测试。`，最终却
  返回 `你好，合成测试。`。
- 独立引擎输入 `  nihao`，本地首选为 `  你好`，正确模型回复
  `  你好新的朋友。` 合并后却变成 `你好新的朋友。`。

相同裁剪还会破坏长候选的「精确前缀 + 有界新增正文」预算锚点。新增长中文用例
检查修复后仍能显示、选择并精确提交，不通过放大上限掩盖问题。

## 修复范围

- 已有 CJK 本地转换前缀按完整原文校验，包含前导、重复和 Unicode 横向空白；
  无内容判断仍可忽略空白，但不拿裁剪后的字符串代替真实前缀。
- 两个候选合并入口均保留与本地首选完全匹配的返回前缀。英文沿用原有原文保护；
  只有模型额外添加的末尾填充空白会被清理。
- 内置 HTTP 提供器拒绝丢失前缀的返回，不自动补回模型漏写的字，不扩大候选预算。
  自定义提供器的既有转换能力和接口不变；合并层不会裁剪它们正确携带的本地前缀。
- 未转换的拼音/罗马音仍可由模型转换，不把所有原始字母强制锁成 CJK 前缀。
  本地首选、原文选项、已锁定选择、防抖、取消、模型授权和隐私边界不改变。
- 日文仅验证提供器对传入本地前缀的同等保护；不修改其离线分词/空白规则，不宣称
  完成任意中日英混合文本或真实模型质量验收。原生回填仍拒绝控制字符。

## 长草稿测试的观察修正

初版原生用例两次停在长草稿建立阶段，还未走到模型采用，不能计作通过。新增用例
一次同步发送 161 个键后才读取订阅；宿主为避免慢客户端阻塞输入，会断开写不完的
订阅。只看旧订阅的最后快照，会把观察停止误判为输入被截断。

在另一个私有总线中关闭模型、复现同一键入突发后，只新建只读订阅，不重新输入：
旧订阅确认 EOF 且停在 110 字符，新订阅立即读到完全一致的 162 字符草稿。由此确认
本次失败来自夹具未及时读取，不是宿主丢字。新用例改为每个键之后处理已有通知；
不加固定等待、不重发事件、不放大队列或超时，也不修改产品的慢订阅断开策略。
