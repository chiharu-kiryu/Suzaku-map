## 实际路径与隔离

[运行器](../scripts/test-linux-apps.sh) 的 `popup` 使用新建的 **800×600 Xvfb**、
私有 D-Bus/IBus/无障碍总线、独立配置和合成文档。系统组件为 IBus `1.5.29-2`、
GTK3 `3.24.41-4ubuntu1.3`、AT-SPI `2.52.0-1build1`，目标应用为 GNOME Text
Editor `46.3-0ubuntu2`；字体/缩放固定为夹具默认值，模型联想关闭。

[弹窗测试](../scripts/test-linux-candidate-window.py) 启动发行版提供的
`/usr/libexec/ibus-ui-gtk3`。只读取该自有进程 PID 的无障碍树，用标签实际坐标产生
XTest 鼠标事件；不调用无障碍“执行”接口，不直接伪造 Engine.CandidateClicked。
旁观私有 Panel 的实际点击信号，随后检查宿主状态和编辑器保存的精确正文。
短种子经过实体按键路径；长 Unicode 种子通过已有的带版本面板替换通道建立草稿，
提交仍必须经过实际 Enter 或弹窗鼠标点击，不能直接设置应用正文。

## N41：码点数量有界，不代表弹窗宽度有界

0.6.2 默认把最多 160 个码点的草稿尾部放在辅助行。系统 GTK3 弹窗的该标签不会
自动换行。实测 160 个 `W`、汉字、emoji，宽度分别为 **1995 / 2155 / 2795 像素**，
连 1920 像素屏幕也容纳不下，位于右侧的控件因此不可达。新增 800×600 检查在旧
实现上明确失败；不是只读取协议字符串长度后推测布局正常。

修复在既有 160 码点上限外，为预览尾部增加 **48 显示列**预算：宽字符计两列，
零宽字符计零列，其他字符计一列。截断处不展示脱离已省略基字符的零宽附加符号。
字符宽度是保守估计，不是对任意字体的像素测量或完整字素簇排版承诺。

只有预览发生缩短并显示省略号。宿主草稿、候选正文、伴随镜像和最终提交均保留
完整文本；模型 256 码点草稿预算与 160 码点已提交上下文预算不变。
行内兼容模式仍保留完整预编辑，不改变其已记录的客户端切框确认风险。

修复后三种测试弹窗宽度为 **690 / 690 / 710 像素**。在 800×600 屏幕普通位置和
光标接近右下边缘时都完整可见；Enter 和点击原文候选均提交完整的 160 字符文本。
这不代表 640 像素屏幕、任意超大字体、其他 DPI 或其他原生候选 UI 已通过。

## 29 组实际弹窗回归

- 中英日 × 两个候选：6 组文字点击与精确提交。
- 首/次页 × 两个行位：4 组页内索引对应，检查候选与角标不串入正文。
- 滚轮、上下页及首末页边界：1 组连续操作，不自动提交也不夺取编辑器焦点。
- 首/次页 × 中/右键：4 组不改变草稿或提交。
- Esc / 删至空：2 组真实窗口关闭、正文保持为空。
- 三类长文本 × Enter/文字点击 × 普通/右下边缘位置：12 组窗口范围与完整提交。

原生协议测试的预览专项从 5 组扩展到 **13 组**，两种草稿模式分别运行，覆盖
48 列/全宽 24 字符边界、emoji、重音组合、160 码点上限与混合文本。
每个案例都以实际 CommitText 核验完整原文，而不是只验证预览。

## 外部限制：系统左侧序号栏不是候选文字区

点击候选正文能传出正确的页内索引，但这版本的 GTK3 弹窗点击左侧 `²` 时，
首/次页都传出 `(16, 1, 0)`，而不是第二项的 `(1, 1, 0)`。Suzaku 最多 12 项候选，
安全拒绝无效索引，不清稿、不误提交其他文字。不能把它改为钳制到某个合法候选。

对应 [IBus 1.5.29 候选区源码](https://github.com/ibus/ibus/blob/1.5.29/ui/gtk3/candidatearea.vala)
中，序号标签的回调仍使用循环变量，候选正文回调则使用每项复制的索引；与本轮
两页实测一致。未修改系统组件，也未宣称所有 IBus 版本或 GNOME Shell 存在此问题。
暂时点击候选正文提交，或数字键采用后再 Enter。

下面是**额外的严格失败复现**，不在 29 组受支持门禁内；当前系统返回非零退出码，
没有“允许已知失败”开关，不将该路径计入通过：

```bash
SUZAKU_POPUP_QA_LABELS=1 bash scripts/test-linux-apps.sh popup
```
