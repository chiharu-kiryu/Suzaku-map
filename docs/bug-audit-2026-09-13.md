  Xvfb 回归覆盖模型、端点、协议、部署范围、密钥变量引用与语言变化，另验证不变配置、

  转换文本仍限 160。保留完整前缀、控制字符/响应体/截断校验与现有模型 token 预算。
  原生回归确认 160/256 字符草稿同时产生词与句候选，采用后继续编辑、点击/Enter 提交均不截断。

  状态机与真实面板状态都验证两种顺序、旧快照等待、恢复文本和无自动发送。

## N01：独立面板切换提供器没有清理旧提交上下文

触发过程：独立面板完成一次提交 → 留下新的当前草稿 → 同语言下修改模型/端点并重载 → 发起下一次预测。

- 期望：保留当前可编辑草稿，但旧提供器会话的提交上下文应清空。
- 实际：下一次请求的 `context_before_cursor` 仍是 `AUDIT_OLD_PROVIDER_CONTEXT`。
- 影响范围：**独立编辑引擎**；原生宿主已经实现了相应清理，不能由宿主测试通过推断面板也安全。
  用户若切换到已授权的云提供器，旧上下文也可能随下一次请求进入新服务。
  本轮没有向云端发送数据，也没有发现绕过云端授权的证据。

根因：面板 [`apply_native_settings`](../src/bin/panel.rs#L388) 仅切换语言和重新配置预测器；
[`reconfigure_model_provider`](../src/bin/panel/composition.rs#L65) 不清除已提交文本。
引擎 [`request_prediction`](../src/ime/core_engine.rs#L694) 随后读取最近 160 个提交字符作为上下文。
对照原生宿主 [`apply_settings`](../src/ime_host.rs#L109)，其 scope / endpoint / model /
protocol / api_key_env 变化会调用 `clear_prediction_context`，两条路径的边界处理不一致。

复现文件：[面板诊断测试](../src/bin/panel/functional_network_audit_test.rs)。
测试先保存关闭 LLM 的私有配置，再执行真实设置重载，最后用内存适配器捕获下一次请求；
测试端点不被访问。断言失败内容：

```text
N01: the new provider received the old standalone commit context: "AUDIT_OLD_PROVIDER_CONTEXT"
```

修复验收建议：统一两条配置路径的提供器身份边界；保留当前草稿、清除旧提交上下文并使旧结果失效。
温度等非身份偏好变化则不要无理由清稿。

## N02：模型输入和输出的长度预算互相冲突

触发过程：英文连续草稿达到 160–256 个字符，模型需要保留完整前缀并补完末尾的词或句子。

- 期望：请求应能产生可接受的补全；超出能力预算时应明确回退，避免发出必然无法使用结果的请求。
- 实际：测试中的 160 字符草稿确实送入预测器，但合法的完整前缀续写被丢弃，最终状态为 `Unavailable`。
- 本地字面候选仍保留；不是全部输入失效，也不是模型自身不会补全。

根因：[`request_prediction`](../src/ime/core_engine.rs#L683) 允许最长 256 字符草稿；
英文 [`useful_candidate`](../src/languages/model.rs#L319) 要求完整前缀并排除原样返回；
[`structured_candidate_texts`](../src/languages/model.rs#L448) 与
[`merge_model`](../src/ime/candidate_mix.rs#L193) 却把**完整候选文本**限制为 160 字符。
前缀本身已达到 160 时，任何真正续写都会超过输出上限。
这导致不必要的推理和等待；若使用计费服务，也可能产生无效请求费用。

复现文件：[引擎与同步诊断测试](../tests/functional_network_audit.rs)，
`audit_model_request_must_allow_a_valid_completion`。
草稿由 `note ` 重复 31 次再加 `  hel` 组成，原文与请求前缀均确认是 160 字符；
内存模型将末词补成 `helioseismology`，结果被过滤。

```text
N02: model was queried for a 160-character prefix, then its valid extension was rejected; status=Unavailable
```

修复验收建议：统一输入/输出预算，或用有界末尾窗口补全后无损拼回前文；
继续保留回复大小、前缀和控制字符校验。不要通过无限放宽模型回复来绕过问题。
超过 256 字符后的有界离线回退是另一项既有设计限制，不算本轮新增问题。

## N03：接受纯空格草稿，却没有可提交的字面候选

触发过程：屏幕键盘/伴随通道将一个 ASCII 空格作为原生草稿写入 → 按 Enter。
这不是「空草稿上的实体空格键应该被截获」；问题发生在宿主**已经确认接受非空草稿**之后。

- 期望：提交一个空格并清空该草稿，保持接受文本和最终提交的契约一致。
- 实际：宿主接受替换并镜像 `seed=' '`，但 Enter 返回未处理，没有 `CommitText`，草稿仍为一个空格。
- 因而目标应用可以自行处理该回车，而 Suzaku 的预编辑未结束；本轮没有假定目标应用会执行何种动作。

根因：伴随通道 [`T` 替换动作](../src/linux/ibus_companion.inc.c#L87) 接受可打印空白；
分词得到空扩展后，[`compose_candidates_with_plugin`](../src/ime/core_engine.rs#L733)
提前返回，连字面候选也没有生成。核心提交返回 `NoCandidate`，
最终 [`suzaku_ibus_engine_commit`](../src/linux/ibus_engine_bridge.c#L252) 返回 `FALSE`，没有清稿。

复现文件：[核心断言](../tests/functional_network_audit.rs) 与
[IBus 回归入口](../scripts/test-native-sync.py) 的 `check_whitespace_commit`（原诊断名 `audit_whitespace_commit`）。
私有 IBus 实测：

```text
N03: Enter escaped to the target app instead of committing the accepted draft; handled=False, seed=' ', commits=[]
```

修复验收建议：让已接受的非空草稿（包括纯空格）有无损提交路径；覆盖单个/多个空格及删词后只剩空白的草稿。
不要顺手改变空草稿下实体空格、数字字段或密码字段的原有直通策略。

## N04：中间快照被合并后，屏幕键盘无法结束等待

最小事件序列（同一宿主、字段、语言）：

1. 当前原生草稿 `hel`，版本 10。
2. 屏幕键盘发送替换 `hell`；用户又点 `o`，面板恢复草稿变为 `hello`。
3. 宿主应用 `hell`，产生版本 11；随后实体 Backspace 把草稿退回 `hel`，产生版本 12。
4. 面板的「只保留最新状态」邮箱合并掉版本 11，只观察到版本 12，并收到步骤 2 的成功 ACK。

期望：识别为无法确认中间状态/外部编辑冲突，保留恢复草稿并明确提示恢复；
不能静默重放 `hello` 覆盖实体键盘刚做的编辑。

实际：两种 ACK/快照顺序都留下 `draft='hello'`、`ready=false`、`settled=false`，
但 `blocked=false`。在宿主文本没有再次改变、字段也不重置的情况下，
在途状态无法结束，后续屏幕键盘点击只继续积存在本地，冲突恢复提示也不触发。
不是整个进程死锁，也没有证据表明发生了跨字段写入。

根因：[`NativeTyping::observe`](../src/bin/panel/native_typing.rs#L52)
只在新文本等于发送文本时结束在途；文本若恰好退回原始 `base`，也不会标记冲突。
[最新状态邮箱](../src/bin/panel/native_sync.rs#L111) 合并中间帧是允许的正常行为，
但 [`flush_native_typing`](../src/bin/panel/native_sync.rs#L237) 缺少该分支的恢复出口。

复现文件：[同步状态机诊断测试](../tests/functional_network_audit.rs)，
`audit_coalesced_frame_must_not_leave_keyboard_waiting_forever`。
结果同时列出 `frame before ACK` 与 `ACK before frame` 两条失败序列。

修复验收建议：为已确认写入但匹配快照不可见的情况设置有界确认/冲突恢复状态；
验证 ACK/快照乱序、同值回退、拒绝、断连和换字段；始终保留未确认文本且不自动重放不确定写入。
