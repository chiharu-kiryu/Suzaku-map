# 安装版人机工程学实测 · 第一轮（2026-09-25）

用户明确要求实际安装后开始测试。安装源码为 **0.6.8 / `85f5d77`**，四个程序使用
`--locked --offline --release --all-features` 构建；初次实测没有改动产品代码或重新发布。
文末记录随后按用户要求完成的修复；它们不属于已发布的 0.6.8 标签。
环境为 Ubuntu 24.04 amd64、GNOME 46 / X11、IBus、1920×1080 桌面，沿用青龙主题、
100% 窗口比例、隐藏系统标题栏、英文模式和关闭 LLM 的设置。

这里区分操作正确性、桌面兼容性和易用性发现，**不把自动化通过视为人体工学或真人
长期舒适度验收**。没有统计真人速度、错误率、疲劳或触摸屏表现。

## 真实 GNOME 桌面补验

专用 GTK TextView 窗口连接已安装宿主，走真实 XTest → GTK → IBus 事件链，没有用
直接调用输入法的按键处理方法来代替应用输入。逐次检查焦点属于这个进程创建的窗口或
其真实子窗口；焦点离开便停止，只释放测试按下的键。所有文字都是合成样本。

**9 组通过：**

1. 英文同时出现词和句候选，未提交前应用正文不变。
2. 数字采用候选，立即 Backspace 精确恢复原拼写。
3. Tab / Shift+Tab 前后导航，不离开草稿或应用。
4. Shift+Enter 采用补全而不提交，随后可撤回。
5. 数字保持按下 700 毫秒只采用一次，松开后可正常撤回。
6. Space 保持连续草稿，Enter 只提交一次准确的 `hello world`。
7. 空草稿数字直通，草稿内 Alt+数字输入字面数字，Esc 只取消草稿。
8. Shift 大写正确，不更改 Caps/Num Lock。
9. 多次连续输入及双空格保真，取消后没有正文泄漏。

这部分只验证**英文/标准快捷键**；中文与主键区方案的本轮物理应用覆盖属于上面的
隔离回归，不能称为已通过所有真实 GNOME 桌面组合。LLM 始终关闭，不代表模型体验。

初始检查误把 GTK 从顶层转移到自身文本子窗口的焦点判为外部跳转，输入前中止。
读回 X11 父子关系后，限定允许同一自有顶层的后代，不放宽为任意窗口；重新检查通过。
另一处夹具先对原文候选做无变化采用，再错误期待 Backspace 撤回；改为先导航到真实
补全后验证。两项是测试判定修正，不是产品修复，失败不计入通过数。

95 次按键到草稿观察的中位时间为 13.81 毫秒，最大值 701.68 毫秒；包括主动保持
按键、轮询和调度，最大值对应长按。这**不是**输入时延基准或真人打字速度。

- 托盘激活/释放后稳定回到 Rime，宿主没有被重复启动。

  屏幕可完整展示；鼠标可以切换分类。
- 工具条空白处拖动：主面板从 `(59, 52)` 移到 `(139, 92)`，反向拖回原位。
- 面板从 900×246 收缩为 92×92 青龙悬浮球，点击后恢复原位置及尺寸。
- 托盘完整退出后，宿主保持停止，跨过 2 秒重试间隔未自行重启；重开安装版面板
  会自动启动服务，仍保持原 Rime。结束时新版面板与宿主正常运行。

## 初次实测发现（修复前）

### E01：设置缺少键盘焦点导航（优先）

真实快捷键页中，Tab 和右方向键没有移动控件焦点；前后 620×600 截图的差异为零。
[设置按键分支](../src/bin/panel/input.rs) 当时处理搜索、Esc 和滚动，没有设置按钮/
分类的焦点遍历及 Enter/Space 激活路径。因此 F1 能找到说明，但不能只用键盘切换方案。

后续应补可见焦点、Tab/Shift+Tab 遍历、分类和选项方向键导航、Enter/Space 确认，
明确搜索框按键归属。本轮没有实现这些交互，也没有改变用户快捷键方案。

### E02：顶部缩放控件窄，需兼顾目标与间隔

100% 视图中缩放控件明显小于正文和设置项；[布局基准](../src/ime/gpu/panel_scene.rs)
为 15.6×20，横向间距 3.2，再应用响应比例。已有命中扩展，不能把可见尺寸直接当成
全部点击范围。本轮鼠标操作成功，没有确认误触回归；这是尺寸/视觉检查发现的摩擦项，
没有触屏或真人误触率数据。后续应同时检查目标大小、邻近控件歧义和缩小时的下限。

### E03：系统窗口标题残留调试内容和过时说明

实际标题仍有长调试串、候选/草稿/提交摘要，以及 `1–4`、`D degrade`、`R reset`，
与原生 IBus 的 1–6 连续输入说明不一致。[标题生成器](../src/bin/panel/helpers.rs)
可直接确认；隐藏系统标题栏也不妨碍窗口管理器取得标题。后续应使用简洁的应用/模式
标题，不把输入正文放进系统标题，详细诊断留在明确的调试入口。

以上是初次实测的历史状态，不宣称已发布的 0.6.8 有完整键盘可访问性或已完成人体工学验收。
