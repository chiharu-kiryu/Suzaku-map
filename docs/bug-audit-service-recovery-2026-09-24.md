## N43：持续重试被默认启动配额终止

[服务生成器](../src/bin/suzaku_tool.rs) 原来写入 `Restart=always` 与
`RestartSec=1`，但没有为总线暂时不可用的情况设置启动限额策略。原生宿主在无法
连接 IBus 时正常报告失败并退出，短时间内重复失败会消耗服务管理器的启动配额。
`Restart=always` 不会绕过该配额；耗尽后即使时间窗口过去，自动重试也不会自行恢复。
见 [systemd 255 的单元启动限额说明](https://github.com/systemd/systemd/blob/v255/man/systemd.unit.xml)。

本轮在一次性 Ubuntu 24.04 容器内使用真实 systemd `255.4-1ubuntu8.17`、IBus
`1.5.29-2`、真实宿主和注册命令。管理器读回的默认值为 **10 秒 / 5 次**。旧策略
负向对照实测：五次宿主启动均因总线未就绪失败，服务进入以下终止状态：

```text
ActiveState=failed
SubState=failed
MainPID=0
NRestarts=5
Result=exit-code
Restart=always
RestartUSec=1s
StartLimitIntervalUSec=10s
StartLimitBurst=5
```

再启动私有 IBus，继续观察 6 秒、越过原 10 秒窗口，状态和重试计数不再变化，
宿主始终不可连接。这里 `NRestarts` 是排队的自动重启次数，不代表第六个宿主已启动。
本版本的 `Result` 保留上一次进程的 `exit-code`，并非必须显示 `start-limit-hit`；
门禁以实际失败状态、计数及总线恢复后的不再重试共同判断，不依赖单个错误枚举。

## 修复及生效范围

- 在生成的 `[Unit]` 中设置 `StartLimitIntervalSec=0`，避免因短期失败耗尽该服务的
  启动次数配额；保留 `Restart=always`，以覆盖总线断开时宿主正常退出的情况。
- 重试间隔从 1 秒改为 **2 秒**，持续等待但不快速循环；停止时限仍为 5 秒。
- 显式停止仍取消重试。没有增加 enable 调用，不覆盖用户关闭自启或屏蔽服务的选择。
- 不拉起或重启桌面 IBus，不抢回当前输入法，不重放未完成的草稿或不确定的提交。

持续重试也适用于永久启动错误，错误本身仍需依据日志修正，用户可主动停止服务。
这不是对任意启动故障的自动修复。变更作用于 **新版工具明确注册生成的服务文件**；
仅构建、替换二进制或安装新版包不会自动重写已有用户服务。后续需要重新注册时，先
完成输入、释放或退出 Suzaku，再用新版工具执行明确的注册动作。隔离审计阶段未替
用户执行；本机补验阶段已按用户授权重新注册。

## 真实管理器门禁

```bash
bash scripts/test-linux-service.sh
```

[运行器](../scripts/test-linux-service.sh) 只读挂载构建目录和测试脚本，创建一次性
Ubuntu 24.04 容器。依赖只安装在容器内部；下载完成后断开容器网络，再执行检查。
不挂载个人 HOME、桌面总线、Docker socket、宿主 cgroup 树或其他可写主机目录；
不使用 privileged 模式、host PID/cgroup 命名空间或个人设备。

真实 systemd 需要可写的 cgroup。[测试启动器](../scripts/test-linux-service.py)
仅用容器的 SYS_ADMIN 能力、容器级 AppArmor 关闭设置重挂载其 **私有 cgroup 子树**，
确认 PID 1 和当前进程位于该命名空间根后才操作。准备完成即降为 uid 1000，并断言
effective/permitted capabilities 均为零；服务管理器、IBus、宿主和测试均以该用户运行。
宿主个人会话、键盘和图形显示完全不接入。

注册时只有桌面探测/切换命令使用既有合成替身，以免需要 GNOME；**服务文件由真实
注册 CLI 生成**，随后由真正的 systemd 用户管理器加载和执行，并非用替身模拟重试。
管理器只加载自有最小 target 树，使用私有 D-Bus、IBus、配置及合成输入。
输入检查走原生 IBus 上下文，不等同于实际 GTK/浏览器正文检查。

五组检查包括：

1. 旧策略负向对照：真实复现配额耗尽，IBus 恢复后仍失败。
2. 冷启动时 IBus 长时间缺席：至少六次自动重试后才启动 IBus，宿主自行就绪，
   无需额外的服务 start/restart 命令。
3. 正常输入草稿期间停止 IBus，保持缺席至至少六次自动重试后恢复。宿主自行
   就绪、身份更新、草稿为空；显式重新选择输入目标后可以输入新草稿，旧宿主
   标识搭配新版本号仍被拒绝，正确的新请求只提交一次新文本。
4. IBus 保持运行时主动停止宿主服务，观察超过重试间隔，不能被自动拉回。
5. IBus 不可用、服务正在等待重试时主动停止；再恢复 IBus，服务仍保持停止。

目标激活后先等待真实上下文及焦点稳定，再开始合成输入，避免把 IBus 初始异步
FocusIn 清理误认为下一次按键结果；新旧目标和实际提交载荷的断言保持严格。

### 未通过项目及后续边界

1. **宿主恢复不等于恢复活动输入源。** 本机停止旧宿主，以及后续故意终止新宿主时，
   IBus 均曾报告 `No global engine`。新服务虽然自动恢复就绪，输入源选择并未自动
   修复；测试根据事前实际记录的 Rime 进行显式恢复并读回确认。这里不能宣称完整
   的桌面无感恢复，已有草稿也不应自动重放。
2. **密码诊断探针在 GNOME 中的退出恢复不稳定。** `linux_ime_probe --password`
   一次在恢复阶段报 stage 10；另一次返回成功但随后读回为 `xkb:us::eng`，而非
   测试前的 Rime。紧随其后的首次托盘激活也被系统切回；离开该状态后，不再运行
   密码探针的独立托盘激活/释放/退出检查均通过。该密码探针不计为桌面验收通过。
   [GNOME 46 的密码用途处理](https://github.com/GNOME/gnome-shell/blob/46.0/js/ui/status/keyboard.js)
   会暂时禁用 IBus 输入源并重载选择；结合探针在清理前没有复原字段用途的代码，
   异步恢复时序是待修方向，不应误报为普通英文输入或托盘始终无法激活。
   后续密码自动检查应继续使用隔离会话，不能直接反复扰动个人桌面。

以上两项没有在本次安装操作中修复，已明确记录，不以此前容器/单测结果覆盖。
