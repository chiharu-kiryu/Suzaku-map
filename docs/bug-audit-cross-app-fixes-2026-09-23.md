# 跨应用草稿与数字兼容修复 · 第二十五轮（2026-09-23）

修复 [第二十四轮](bug-audit-cross-apps-2026-09-23.md) 确认的两项实际应用问题，
对应 [功能网络](functional-network.md) 的 F08/F10–F14/F29。
基线 `0.6.1` / `b0300ee94a94e43d78632ef081adfd54b980eefa`；**N39/N40 仍是未发布的
工作区修复**，未更新个人安装，也未提交或推送。

## N39：默认不把未确认草稿交给应用缓存

旧模式向应用发送行内预编辑。Qt/Chrome 切框时可自行确认该缓存，Suzaku 即使
不发送 CommitText，也无法保证仅在 Enter/点击时落字。已有 IBus 调用本来就使用
`IBUS_ENGINE_PREEDIT_CLEAR`，因此仅再次指定 CLEAR 不能解决；见
[IBus 1.5.29 的实现](https://github.com/ibus/ibus/blob/1.5.29/src/ibusengine.c)。

现在默认采用**候选区草稿**：

- 草稿、选中候选、撤回、联想和伴随面板镜像仍在原来的原生会话中。
- 原生候选窗辅助行显示 `Suzaku · 草稿`；长文本显示末尾 160 个 Unicode 字符，
  加省略号，仅缩短预览，不截断草稿或最终提交。
- 不向目标应用发送预编辑更新，包括无必要的空预编辑；避免应用缓存草稿，或
  将空更新解释为删除当前选区。Enter/候选点击仍使用一次完整 CommitText。
- 取消、Reset、失焦清空所属会话与候选区，旧文字既不落入旧框，也不跟到新框。
- Compose 未完成时仍保留已有草稿的预览及组合提示。

可见变化是未确认文字从目标正文移到候选区/伴随面板；本轮不是对 Qt、Chrome 或
系统 IBus 安装文件打补丁，也不在切框后回删目标应用正文。

保留高级兼容开关：宿主启动环境 `SUZAKU_IBUS_INLINE_PREEDIT=1` 恢复旧行内预览。
**该选项会重新允许客户端自行确认草稿**，不能与默认模式的切框保证混淆；默认不启用，
设置后需重新启动自有宿主。非 `1` 值仍使用默认模式。上一轮 N38 的完整空预编辑清理
在行内模式仍保留。原生诊断程序同时识别候选区预览和行内预编辑，不因默认模式变化
误报输入法没有草稿。

## N40：空草稿上的数字直接交还应用

旧实现先将第一个数字作为草稿起笔，随后的数字就进入候选槽位逻辑。遇到没有正确
传达数字用途的客户端，`12.5` 变成 `1.`，浏览器最终显示为 `1`。

现在没有草稿时，普通数字和小键盘数字交给应用，因此 `2026`、`12.5` 及外部数字
编辑不会凭空启动候选。**已有草稿时 1–6 仍选候选，空槽仍不偷偷插入数字**；Alt+数字
仍可显式加入可编辑草稿，Compose 的字面结果也保留。修饰键、语言、数字选词和空格
不断流的原规则不变。没有修改键盘布局、Caps Lock 或数字键映射。

这解决了已复现的数字吞键，但**没有修复应用缺少 ContentType 的外部事实**：
用途未知的框仍是普通文本框，字母起笔、显式 Alt 数字和面板输入仍可能形成公开草稿。
不能将数字直通当成整个框已获得密码/隐私保护；敏感输入仍应使用可信输入法。

## 验证入口与新增断言

```bash
bash scripts/test-linux-apps.sh cross
bash scripts/test-linux-apps.sh gtk
bash scripts/test-linux-ci.sh ibus
SUZAKU_IBUS_INLINE_PREEDIT=1 bash scripts/test-linux-ci.sh ibus
bash scripts/test-linux-ci.sh ui
```

跨应用使用 Chrome 153.0.8010.52、Qt 5.15.13 和 Qt 6.4.2 的标准字段，Qt 两版各测
同步/异步模式，共五种配置。每种 23 组，合计 **115 组**；默认模式每次都验证没有
引擎预编辑更新、候选区有草稿且提交后隐藏、正文在确认前不变。
特别新增选区上的取消不删原文，以及各普通文本框先输入数字再正常选词。

测试已删除“允许已知限制”的放行路径；旧 `SUZAKU_APP_QA_ALLOW_KNOWN_LIMITS` 不再
改变结果。切框写入旧文、吞数字、正文不匹配、预览失踪均直接失败。应用运行器清除
继承的行内开关，明确测试默认模式；原生协议测试分别覆盖两种模式。

原生同步测试保留两种客户端预编辑提交设置 × 六种结束方式，共 12 组；默认模式
断言无非空客户端预编辑，行内模式继续检查 N38 清空。另加 5 组空格、Unicode、
160 字符边界、超长草稿的预览/无损提交；已有三语、异步模型、隐私、过期动作与
IPC 检查仍执行。模型使用自有合成服务，不加载或请求真实模型。

## 本轮实测结果

- Chrome/Qt 五种配置的 **115 组**严格工作流通过，没有已知限制豁免。
- GNOME Text Editor/Zenity 的 **8 组**真实 GTK 工作流通过。
- 默认候选区、显式行内两种模式的完整原生 IBus 测试均通过；每种包含新增 5 组
  预览/完整提交、12 组同步清理，以及中英日输入、受控模型、隐私与过期请求回归。
- **826 项**常规 Rust 测试通过，24 项需要专用环境的测试默认忽略；另行执行的
  **16 组**隔离面板测试与 **1 组**程序入口测试全部通过。
- 全功能及仅 GPU 两种严格 Clippy、格式、脚本静态检查通过。

仍不代表 Firefox/Electron、原生 Wayland、所有 Qt 应用/网页编辑器或密码面板注入
已经验收；本轮未重新打包、安装或运行远端 CI。
