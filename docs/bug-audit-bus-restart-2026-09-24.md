## 隔离与复验

```bash
bash scripts/test-linux-apps.sh bus-restart
```

[运行器](../scripts/test-linux-apps.sh) 创建独立的 1920×1080 Xvfb、D-Bus/IBus、
无障碍总线、配置、运行目录和合成文档。使用 IBus `1.5.29-2`、GNOME Text Editor
`46.3-0ubuntu2`、发行版 GTK3 系统候选面板，以及仓库构建的 Suzaku 宿主/伴随面板。
模型联想关闭，采用默认的候选区草稿模式；不发送真实输入或模型请求。

[专项脚本](../scripts/test-linux-bus-restart.py) 复用实际按键、应用保存与弹窗观察器。
所有输入经过 XTest，候选点击落在真实上标字形；无障碍接口只观察自有系统面板。
Compose 映射只作用于自有 Xvfb 键盘。停止操作只针对脚本直接启动并持有的进程对象，
不按名称停止任何桌面进程，也不操作用户 systemd 单元。

## 13 组检查

- **总线未就绪：1 组。** 在私有 IBus 尚未启动时运行宿主，及时以失败状态退出，
  不留下宿主就绪套接字。之后启动总线和宿主能够正常输入。
- **守护进程退出：9 组。** 英文、中文、日文各覆盖普通草稿、数字采用后的可编辑
  候选，以及尚未完成的 Compose。向自有守护进程发送 SIGTERM，检查下述完整链路。
- **守护进程强制退出：3 组。** 英文的同样三种状态以 SIGKILL 强制结束自有守护
  进程，执行相同严格检查，不把正常退出路径代替异常断开。

12 组断连/恢复都保持 **同一个实际编辑器和同一个 Suzaku 伴随面板**运行：

1. 断连前，系统弹窗与伴随面板显示当前候选，但保存的应用正文为空。
2. 总线退出后，宿主结束、移除自身通信端点，旧订阅收到 EOF；实际候选窗消失。
3. 应用正文仍为空，未完成输入不被确认。新的 `literal` 按键直接进入应用，
   不因模型、候选或未完成的旧 Compose 被吞掉。
4. 显式重启自有总线、宿主和系统候选面板，再重新选择 Suzaku。原应用和伴随
   面板不重启，也不人为重建它们的输入上下文。新宿主标识变化、语言设置保留、
   草稿为空；已输入的 `literal` 正文保持不变。
5. 清空合成文档并键入 `fresh`，原应用与伴随面板均收到新候选，没有旧组合残留。
   将旧宿主标识与新版本号组合发送候选提交请求，必须被拒绝；正文、候选、版本
   和焦点均不改变。
6. 8 组以实体 Enter 提交，4 组以真实候选上标点击提交。检查点击信号的索引/按钮、
   完整正文、只提交一次、候选窗关闭及应用焦点不变。

正文断言依据当前语言的完整候选载荷；例如日文的 `fresh` 可转换为 `fれsh`，
不能假定所有语言都提交英文字母。伴随面板窗口标题中的预览也是所选候选，
与原始拼音/罗马音种子不同。

## 夹具调试与边界

开发测试时排除了三种夹具误判，均不是产品修复：

- 本测试固定使用临时目录中的文件系统套接字，IBus 退出后该文件可能仍在，
  直接重绑会报地址占用。脚本先确认自有进程已结束、观察连接已断开、端点确为
  套接字且连接被拒绝，再删除这一个自有端点；遇到仍活跃的监听者则失败。
- 系统面板的无障碍树出现早于其启动时选择 US。提前激活 Suzaku 会被这次迟到
  的默认选择覆盖。现在观察真实的全局引擎变更信号，再显式激活；不强制抢回
  输入法，不把启动阶段的默认切换解释成恢复失败。
- 中文/日文候选预览可能与字母种子不同。观察器按原生快照中的所选完整候选
  检查面板，同时独立检查原始种子、实际应用正文和提交结果，没有放宽断言。

宿主和输入法重新激活由测试明确执行。本轮没有运行私有或个人 systemd 管理器，
因此不能将这些结果表述为自动服务恢复已验收。源码生成的服务已有 `Restart=always`，
但重试限速、长时间总线不可用、登录/注销及桌面启动顺序仍需要独立验证。
草稿仍在内存中；断连丢弃旧草稿是既有边界，不承诺自动保存或崩溃恢复。
