# 快捷键：连续输入与主键区方案

0.6.7 起提供，0.7.2 增加保留草稿的中英切换快捷键，针对 Linux / IBus；
源码提交和标签不会更新正在运行的安装版。

0.6.8 的[安装版人机工程学实测](ergonomics-audit-2026-09-25.md)补验了真实 GNOME 英文
操作和隔离中英按键链。随后补上下面的设置页键盘导航（纳入 0.6.9），
已更新本机安装；不等同于完整的屏幕阅读器可访问性或真人舒适度验收。

## 入口与默认行为

面板获得键盘焦点时，`F1` 打开「设置 → 快捷键」，`Ctrl+,` 打开设置。
这些不是系统全局热键，不会从其他应用抢走焦点，也不修改 GNOME 绑定、键盘映射或锁定状态。
组合输入尚未结束时，面板不执行这些命令。

### 快速切换中英文（0.7.2）

`Ctrl+Shift+Space` 在 **已激活 Suzaku 的普通 IBus 输入框**中切换 English ↔ 中文拼音，空草稿也可用，
标准与主键区方案都支持。从日文模式按下则进入 English；日文仍可由托盘「输入语言」选择。
这是 Suzaku 内部输入语言切换，不是切换系统输入法、界面语言或翻译目标语言。
在面板按 `F1`，可在快捷键页查看对应说明。

- **保留未提交草稿，不自动上屏**。保存成功后使用新语言重算词句候选，清除旧语言的
  候选选中、采用撤回及模型上下文；普通空格仍继续写，只有明确提交才上屏。
- 后台保存期间仍可继续输入，成功时保留当时最新的草稿。候选提示区显示当前模式及
  保存进度/失败提示；保存失败维持原语言、草稿和采用撤回，外部配置不被旧状态覆盖。
- 长按只切一次；先松 Ctrl/Shift 也不会把仍按住的空格变成连写。松开空格后可再次
  切换；上一保存任务尚未完成时不排队补切，等待提示后再操作。
- 焦点离开、Esc/Reset 清稿、明确提交、停用、销毁、进入隐私字段或开始 Compose 会放弃未完成切换。
  未完成的 Compose 不触发切换；密码/数字字段及失焦目标不接管此快捷键。
- 仅识别精确 Ctrl+Shift+Space，允许 Caps Lock / Num Lock，但不修改锁状态或键位；
  Alt、AltGr、Super 等额外修饰键不触发。若桌面或应用提前截获该组合，仍可从托盘切换。

快捷键与托盘复用有界异步保存；只有这个键盘切换入口保留草稿，托盘明确选另一语言的
既有清稿行为不变。没有新增系统全局监听、任意快捷键重绑定或跨语言自动识别。

### 设置页键盘操作（0.6.9）

- `Tab` / `Shift+Tab`：依次前进/后退，包含分类、搜索、可操作设置、关闭及保存重试。
  跳过只读快捷键说明、被折叠或筛掉的选项；屏幕外的焦点会自动滚入视野。
- 方向键：在同一行左右移动、向相邻行上下移动；**只移动焦点，不修改选项**。
- `Enter` / `Space`：确认焦点处的按钮或选项，长按不重复确认。选择快捷键方案仍需
  宿主确认保存，失败按原流程回退。
- `Ctrl+F`（macOS 为 `Command+F`）聚焦搜索；直接键入文字也可搜索。搜索框中的空格
  是搜索文本，不触发选项。组合输入的预编辑期间，按键仍交给当前输入法。
- 非搜索状态的 `PageUp` / `PageDown`、`Home` / `End` 滚动页面；`Esc` 关闭设置。

这些只在 Suzaku 自己的窗口中生效，不改变 IBus 草稿里的 Tab/空格/数字行为。

旧配置与新安装都默认使用「标准按键」。在快捷键页选择「主键区 (Alt)」后，增加
下面的 QWERTY 主键区别名；原按键仍可用。原生输入法服务需要运行且支持该设置。
同一页可搜索、查看按键说明；英文、中文等已有八种界面语言均可使用。

| 操作 | 标准按键（始终保留） | 主键区方案增加 |
| --- | --- | --- |
| 上 / 下一候选 | Shift+Tab / Tab，方向键 | Alt+K / Alt+J |
| 上 / 下一页（每页 6 项） | PageUp / PageDown | Alt+H / Alt+L |
| 采纳当前候选，继续编辑 | Shift+Enter；1–6 采纳页内对应项 | Alt+;（分号） |
| 撤回刚才的选词 | 立即按 Backspace | — |
| 继续写，不提交 | Space | — |
| 提交到目标应用 | Enter / 点击候选提交 | — |
| 取消当前草稿 | Esc | — |
| 字面数字 | Alt+0–9 / 数字小键盘；空草稿数字直通应用 | — |
| 中英切换并保留草稿（0.7.2） | Ctrl+Shift+Space；空草稿也可用 | — |

例如英文输入 `hel`，浏览到 `hello` 后按 `Alt+;`，再按空格，得到可继续编辑的
`hello `。中文 `nihao` → `你好` 同样可继续写，仍只有明确提交才上屏。
直接按一次 Backspace 可以撤回刚才的采纳；继续键入、换候选或结束输入后不再恢复旧选词。

物理键盘上的数字选词、Shift+Enter（含小键盘）及 Alt+分号，长按只采纳一次，松开后
可立即再次使用。先松修饰键也不会把仍按住的 Enter 变成提交。导航、字母、空格和删除
仍可长按连发；快速分开点按不会被时间防抖吞掉。详见 [N49 长按审计](bug-audit-shortcut-repeat-2026-09-24.md)。

## 冲突与边界

- 主键区别名只在 **IBus 有非空草稿、当前输入目标有效且不是隐私字段** 时生效。
  独立面板的文本编辑器仍使用编辑器按键；本轮没有把这些别名扩展成全局命令。
- 只匹配精确的 Alt 组合。Shift、Ctrl、Super、AltGr、按键释放和未完成的 Compose
  不会触发别名；Caps Lock / Num Lock 不妨碍正常别名，程序不更改它们。
- 空草稿时 Alt 组合交还应用。若应用在输入过程中也需要同名 Alt 快捷键，切回标准方案。
  某些桌面会先拦截 Alt 组合，Suzaku 无法处理未送达 IBus 的事件。
- QWERTY 主键区只是一个预设，不是针对所有键盘布局的人体工学结论；按逻辑键名匹配，
  不是固定物理键位。尚无任意重绑定、按应用配置或左右手专用预设。
- 主键区别名不会直接提交、切语言、开关 LLM 或操作剪贴板。采纳后草稿发生变化，
  仍按既有设置触发自动联想；快捷键不绕过模型启用或云端授权限制。
- 长按保护需要客户端提供非零物理键码和释放事件；键码为 `0` 的合成输入保留逐事件
  语义。焦点/隐私/清稿边界清除旧按键状态，不把上一字段的长按带入新字段。

## 保存与兼容

`suzaku-ime/settings.json` 的 `shortcut_profile` 取 `standard` 或 `home-row`，缺省为
`standard`，不合法的值拒绝加载。面板通过原生宿主的窄补丁保存，避免覆盖语言、模型或
云端授权；存在未重载的外部修改时拒绝覆盖。旧宿主不支持该补丁时保留原设置并提示错误。
保存失败回退未再次编辑的选项；较晚返回的确认不会覆盖更新的选择。

切换方案本身保留草稿、选中候选、撤回状态、Compose 和正在运行的预测。设置会进入
配置备份，不包含输入内容。八种界面语言不表示八种原生输入法支持；原生能力范围见
[IBus 候选说明](ibus-candidates.md)与[已知限制](known-limitations.md)。
