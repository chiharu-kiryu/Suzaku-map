# 长句本地末尾窗口 · 第四十五轮（2026-09-25）

状态：0.6.8 之后的未发布开发改动；保留上一轮人机工程学修改。本轮不修改个人
输入源、配置或模型，不安装、不提交、不推送。所有输入均为测试自有文本。

## 改动与边界

原先 IBus 的本地候选与自动模型请求共用 256 个 Unicode 码点的整稿门槛，超过后
即使只有末尾一个 `hel` / `nihao` 待补全，也只剩原文。N53 只修正了门槛以内的
搜索提前结束，本轮是上层有界续写能力，不是继续加大拼音搜索或模型请求。

- [引擎](../src/ime/core_engine.rs) 对超过 256 码点、至多 8192 UTF-8 字节的中英草稿
  使用[局部窗口](../src/languages/draft.rs)。英文按完整词边界取末尾至多 256 码点，
  中文在已有汉字/明确中文标点之后取有限片段；前文原样拼回，不重新转换。
- 中文空格/撇号不是可冻结的边界，不能把超长未转换拼音随意截开。含 Han 的 URL、
  路径、邮箱及下划线标识符也不能通过隐藏语法变成假拼音。无安全窗口则保留原行为；
  日文没有扩展，未知拼写不伪造词句。
- 词、句和完整原文沿用现有有限词表与候选上限。长候选在镜像协议中正文/标签均
  携带完整内容，[混排](../src/ime/candidate_mix.rs)按 JSON 转义后的大小预留原文，
  再保留放得下的候选。靠减少项数满足原有消息预算，不截断正文或提高通道上限。
- 中文 IBus 标签省略相同长前缀，展示少量上下文与末尾差异；实际候选及提交文字
  没有省略号。整体改写开头的候选仍从开头展示，避免掩盖改写。
- 模型仍按完整草稿的 256 码点预算取消/停止请求；没有发送裁剪后的局部稿、读取
  外部应用上下文、调用真实模型、扩充词库或改变 Space/数字/Enter 的职责。

这不是任意长拼音全文转换、整篇模型理解或通用语法质量承诺。超过 8192 字节的
原生草稿仍完整保留、可提交，但镜像隐藏；接近消息预算时可用候选会减少。

## 回归与调试记录

- [长稿核心回归](../tests/long_draft_completion.rs)：中英独立/IBus 两种策略，跨越
  256 码点、数千字节、Unicode/空白/转义前缀，词句候选、连续采用、完整提交，
  URL/标识符与超长拼音保护，候选数限制、镜像帧可解析、中文预览差异。
- [模型回归](../tests/ime_prediction.rs)：局部候选可用时仍不请求模型，缩短后恢复；
  仅受控内存提供器。原生夹具继续保留待返回/已返回模型跨长度边界的取消检查。
- [原生链路](../scripts/test-native-sync.py)：原 20 组扩充为 32 组键入/伴随回填，
  数字采用、立即退格还原、Space 后继续写和单次 Enter 全文提交；保留未转换连续
  拼音 257→256 的限长恢复。各候选区标签与镜像逐项对应，不使用显示文本提交。
- [实际 GTK 编辑器](../scripts/test-linux-apps.py)：长稿场景由 4 个扩充为 8 个，
  包括 5000 字节英文和已有长中文前缀。建立前缀后用 XTest 实体键完成续写/采用/
  撤回/提交，检查应用正文、保存状态和磁盘文本。
- 开发时新增含 Han 的 URL 负向样例先失败：局部切分隐藏了 URL 语法。补充当前
  token 的路径/标识符守卫后回归通过。候选预算测试也区分一般词句覆盖与极长草稿
  的合理减项，不要求最大长度下仍保留所有备选短句。
- 首次完整原生检查停在长稿读取：同步测试观察器整词结束才读取，多份大帧可填满
  有界订阅缓冲；夹具改为每键处理后及时读取，不改变宿主的非阻塞/慢读者断连策略。
  真实面板的独立读取与重连机制未更改，既有慢读者安全测试仍保留。

## 验证结果

- 最终完整离线、全特性 Rust 回归：**886 通过、0 失败、27 默认忽略**。其中新增
  长稿 6 项，异步预测由 15 增至 16 项；已有中文 11 项、英文 5 项保持通过。
- 私有 D-Bus/IBus 默认候选区模式与显式内联模式，最终完整流程均通过；各含
  **32 组**长稿采用/撤回/续写和 **1 组**超长连续拼音删短恢复，原有模型取消、
  72 组字节边界及 8 组异步模型限长检查保持通过。
- 私有 Xvfb 中真实 GTK 编辑器 **11 组**通过，长稿组含 **8 个场景**；保存文件
  与完整候选正文一致。原生 UI **17 项**通过。本轮未做个人桌面安装验收。
- 全特性全目标及仅 GPU 面板两套严格 Clippy 通过；格式、Python 语法、打包脚本
  语法/ShellCheck、审计文档打包清单、202 条审计链接、图源正文一致性和 diff 空白检查通过。
- 失败记录：首次命令遗漏项目所需的 GPU 特性导致编译失败，之后使用既有全特性
  配置；Clippy 指出一处可用 `?` 简化的分支，修正后复跑通过。第一次 GTK 新增
  中文场景结束后没有恢复测试语言，后续英文 Tab 断言失败，补上夹具语言恢复后
  完整重跑通过。第一次内联原生测试在末尾密码探针阶段私有 IBus 连接关闭；长稿
  组已通过，停止并发图形测试后相同产品代码完整重跑通过。该次断连根因未确定，
  不宣称本轮修复了新的总线缺陷，未放大超时或跳过检查。
