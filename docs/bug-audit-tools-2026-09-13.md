## N05：自动语音回填没有绑定采集开始时的输入上下文（修复前）

复现序列：

1. 原生输入框 A：`host=…0001`、`context=1`、`revision=10`，草稿为 `alpha draft`。
2. 在语音工具开始采集，模拟桥返回 `hello world`，自动回填开启。
3. 899 ms 时尚未稳定，不发送；随后切换到输入框 B：`context=2`、`revision=11`，
   B 的草稿为 `beta draft`。
4. 到达 900 ms 稳定阈值时，再推进正常转写轮询。

期望：停止/暂停这次自动回填，保留转写供用户明确采用；不要将 A 的采集自动移到 B。

实际排入动作队列的请求是：

```text
A00000000-0000-0000-0000-000000000001 11 Tbeta draft hello world
```

`T` 是替换预编辑，不是最终提交。请求绑定的是 **B 的最新版本 11**，因此通常的旧版本拒绝
不能阻止这个错误目标；问题发生在动作构造前，不是宿主忽略版本检查。
同样复现于宿主重启后出现新目标，以及断连后切到另一个输入框。

根因：

- [`VoiceTranscriptProgress` / `start_voice_capture`](../src/bin/panel/voice.rs) 记录转写、
  稳定时刻和来源代次，没有记录开始采集时的本地/原生绑定、宿主与输入框。
- [`receive_native_frame`](../src/bin/panel/native_sync.rs) 更换当前原生快照时，
  没有取消或解绑仍在等待首次自动回填的语音采集。
- [`poll_voice_bridge_at`](../src/bin/panel/voice.rs) 达到阈值后直接调用插入；
  [`native_insert_text`](../src/bin/panel/native_sync.rs) 拼接的是此时最新目标的草稿。
  回填请求上的来源代次用于防止 ACK 清除新转写，不能替代开始采集时的目标绑定。

已通过的对照：原输入框未变、同框候选更新、关闭自动回填、隐私框拒绝，以及切换后用户
明确手动采用转写。正常成功回填仍只发送一次；本轮没有发现隐私框被写入。

建议修复边界：对**首次自动回填之前**也保存并验证采集上下文；换宿主、换输入框或失去
连接时暂停自动采用并保留来源。不要禁止用户在新目标中明确手动采用，也不要让仅候选更新
误取消同一输入框的转写。接入真实麦克风之前，应先覆盖这条边界。

## N06：独立编辑器回填使用错误的词边界（修复前）

语音和手写的本地回填方法都先看 `seed_text.ends_with(' ')`，再调用按 `caret_index`
插入的 `insert_text`。草稿末尾和光标前后不是同一位置。

以下均插入合成词 `world`；光标索引按字符计数，从 0 开始，表格中的原始空格需保留。

| 原草稿 | 光标 | 期望 | 实际（两种工具相同） |
| --- | --- | --- | --- |
| `hello there ` | 5，`hello` 后 | `hello world there ` | `helloworld there ` |
| `hello there` | 6，空格后 | `hello world there` | `hello  worldthere` |
| ` there` | 0 | `world there` | ` world there` |
| `hello` + U+00A0 | 6，末尾 | 原分隔符后直接接 `world` | 额外插入一个 ASCII 空格 |
| `hello` + U+3000 | 6，末尾 | 原分隔符后直接接 `world` | 额外插入一个 ASCII 空格 |

这不是候选识别质量问题：测试直接提供合法的合成词，错误发生在已经选择结果后的回填阶段。
不会提交到外部应用，但会改变正在编辑的词边界，要求用户手动修正。

根因位置：[`insert_voice_transcript`](../src/bin/panel/voice.rs)、
[`insert_handwriting_candidate`](../src/bin/panel/handwriting.rs)。
[`PanelChromeState::insert_text`](../src/ime/gpu/types.rs) 正确按光标插入；
工具切换的 `blur_input` 也不将光标移到末尾，不能假设回填总是在草稿末尾。

空草稿、普通英文末尾追加、末尾已有 ASCII 空格均通过。
原生回填对 U+00A0/U+3000 使用 `char::is_whitespace`，两种工具均没有额外补空格，
进一步确认了本地和原生路径的差异。

建议修复边界：统一工具回填的文本插入规则，检查光标前后字符、尊重现有 Unicode 分隔符，
保留原草稿前缀和后缀；不要通过一律把光标移到末尾来掩盖问题。

## 已实施的修复

- N05：开始采集时记录本地/原生目标；原生目标绑定宿主及输入框编号，不绑定候选刷新版本。
  接收换框、失焦、隐私字段或断连通知，以及进入/离开原生镜像时立即检查；稳定计时轮询前
  再检查一次。目标改变就停止采集，保留已显示及尚未轮询的转写，并提示显式采用。
  回到旧框或恢复连接不会重新启动这次采集；正常同框候选刷新仍可自动回填一次。
- N06：[统一插入规则](../src/ime/tool_text.rs) 同时用于原生追加和独立面板的语音/手写
  回填，按字符光标检查左右边界，保留原文和 Unicode 空白；不在常见闭合标点前、开括号后
  强加空格。光标停在新插入文字之后、为旧后缀补的空格之前，不再跳到全文末尾。
- 回填仍只进入草稿/预编辑，不会直接提交；原有来源代次、ACK 确认与拒绝后保留来源的
  规则继续生效。Linux 语音仍是模拟桥，这次没有接入真实录音。

隔离回归扩展到 46 个场景：18 个语音目标/手动采用场景，以及 28 个本地与原生回填场景。
还补了不依赖图形环境的共享插入规则测试，涵盖字符索引、越界光标、空结果、Unicode 空白
和标点邻接。两项原诊断不再是“已知失败”，已加入 `test-linux-ci.sh ui` 的必跑列表。
