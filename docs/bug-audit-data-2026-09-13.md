## N10 · P2：配置文件软链接与不同运行目录导致运行期恢复保护漏检

涉及 F43 / F47 / F49。只在非默认路径组合中复现，不能据此说普通桌面的运行锁都失效。

必要条件：

1. 真实 Linux IBus 宿主通过 `SUZAKU_IME_CONFIG` 加载一个**文件软链接**，链接位于
   与真实配置不同的目录。运行时读取普通 JSON 的这种链接是当前支持的行为。
2. 恢复命令直接操作同一真实配置文件，但使用不同的 `XDG_RUNTIME_DIR`，且没有显式
   指向宿主的自定义端点。这可出现在独立运行环境或手动启动配置中。
3. 宿主仍然存活，执行 `data restore ... --apply`。

期望：因为同一配置正在被宿主使用，恢复应拒绝，磁盘配置保持不变。

实际隔离复现：

```text
N10 file-alias:
  restore_success=true
  live_host_model="synthetic-before"
  disk_model="synthetic-restored"
  shared_settings_replaced=true
```

这不是只构造一个锁对象的单元测试：诊断实际启动私有 D-Bus / IBus 守护进程和项目的
`linux_ime_host`，先通过宿主状态接口确认载入旧配置，再调用真实 `suzaku_tool` 恢复，
最后同时验证宿主进程仍在运行、仍报告旧配置，磁盘却已经被恢复命令替换。
测试没有创建输入上下文或切换全局输入法；联想一直关闭，没有联系任何模型。

### 根因

- [`lock_for_settings`](../src/data/paths.rs) 直接用传入设置路径的父目录定位
  `.suzaku-data.lock`，没有将文件软链接的读取目标纳入锁身份。
- [`DataLease::current_shared`](../src/data/files.rs) 因而让宿主锁住链接目录中的锁文件；
  [`restore`](../src/data/backup.rs) 则锁住真实配置目录中的另一文件。两把锁互不排斥。
- `refuse_legacy_runtime` 只检查调用者运行目录及显式设置的端点，不能兜底发现另一个
  运行目录中的宿主。不同运行目录本身不应让保护同一配置文件的维护锁失去作用。

### 对照结果与影响边界

- 普通真实路径：即使 CLI 使用不同运行目录，仍正确拒绝恢复。
- **目录软链接**：打开的锁文件仍解析到同一个文件，正确拒绝恢复。
- 文件软链接但 CLI 与宿主使用同一运行目录：端点检查正确兜底，拒绝恢复。
- 三种路径的预览均不写配置；停止测试宿主后，独立运行目录中的恢复均能成功。
- 文件软链接 + 不同运行目录的失败已经重复复现，其余对照继续通过。

已确认的是“本应停用宿主后才能执行的恢复，在宿主存活时成功替换文件”，使运行状态与
磁盘配置分离；不是观察到了输入内容丢失、模型上传、提权或云端授权重新启用。
当前普通路径/同一桌面运行目录的对照均通过。

## 已实施的修复

[`DataLease::settings_shared`](../src/data/files.rs) 现在逐层解析文件链接，同时保留所选
链接位置、各中间链接及最终读取目标目录的维护锁。父目录先解析到真实路径并去重，避免
目录别名让同一写锁被重复获取。沿用原来的锁文件名，因此普通路径和既有单路径维护锁
仍与这组锁相互排斥，不依赖两个进程恰好使用同一运行目录。

生命周期内保留整个原始锁集合：沿用现有“原子保存替换指定路径条目”的行为，不改变
软链接保存语义。当宿主保存最外层链接，或 CLI 保存中间链接后，这些路径变成普通文件，
但原来的所有维护锁仍保持到宿主退出。既保护当前文件，也不会提前放开原来的目标。

配置写锁使用同样的路径集合，避免不同别名的写入绕过前一轮 N08 的串行化保护。
所有锁仍是非阻塞尝试；失败时释放已经取得的部分锁，不升级进程持有的共享锁。
获取后再检查解析结果：如果出现未覆盖的新目标则拒绝，而不是沿新目标无锁执行。

循环、过长链、保留锁文件目标、无法解析的目标父目录会明确报错。普通新配置目录仍可
创建；若仅目标文件尚未创建、其父目录已存在，可以先保护对应目录，不擅自创建配置文件。

边界：此修复保护已解析的链路及 Suzaku 自身原子保存产生的替换。外部手动把链接或父目录
重新指向另一处时，应先停止 Suzaku，修改后重新启动，不把链接改向当作运行期热切换接口。
不声称能阻止不配合的外部程序改链接、替换锁文件或制造任意文件系统竞态。
备份/恢复仍拒绝最终组件是软链接的源/目标，恢复应使用真实路径并先停止相关进程。

  两个配置都保持原字节。目录权限仅在测试临时目录内调整，由守卫恢复。

  云端授权撤销测试也通过。
