## N37：外部提交结束后，旧发送仍可追加上屏并清掉下一段草稿

优先级 P2。[IBus 桥](../src/linux/ibus_engine_bridge.c) 在实体 Enter/小键盘 Enter、
IBus 原生候选条点击或独立面板的 `C` 字面发送成功后，只清理草稿，没有更换伴随
`context`。此前已接入、尚未结束的另一条 `C` 请求仍能交付，追加旧文本，并清掉
新一轮草稿。仅检查旧 `A` 的修订号，不能撤销已接入的 `C`。

屏幕键盘还有关联的异步风险：上一笔替换等待确认时，用户已从外部提交、又输入相同
文字；面板只收到合并后的末帧。如果末帧恰好等于上一笔替换文字，只比较文本可能把
旧的排队按键当成仍可续写。提交边界必须在宿主发布的目标标识里保留下来。

## 修复前证据

[私有原生夹具](../scripts/test-native-sync.py) 先接入未结束的旧 `C`，以后接入的
查询作为接收屏障，再独立完成提交、写入下一段合成草稿，最后结束旧请求。英中日
× 16 种操作 × 空/非空草稿共 **96 组**；修复前 **15 组失败、81 组对照通过**。

```text
en/enter/typed=True: context_changed=False, reply=b'1', commits=['hel', 'synthetic old send en '], new_draft_retained=False
ja/native click/typed=True: context_changed=False, reply=b'1', commits=['日本語', 'synthetic old send ja '], new_draft_retained=False
AUDIT: N37 81/96 commit target cases passed
```

每组失败均在真实私有 IBus 对象上观察到预期提交之后又出现旧请求的 CommitText，
且新草稿被清掉。全部文字、配置与接收对象是测试创建的，不涉及真实用户输入。

## 修复及边界

- 实体 Enter/小键盘 Enter、原生候选条主按钮点击、独立 `C` 发送，只有**成功实际
  提交**后才结束旧操作目标，在清空快照发布前推进 `context`。新接入的明确发送仍
  可用；未结束的旧发送被拒绝，不再破坏新草稿。
- [伴随动作通道](../src/linux/ibus_companion.inc.c) 的带版本 `A … K` 提交保留原有
  目标及确认机制。这类提交的键盘续写已由面板自己的确认/快照保护管理，不能无差别
  清掉点击后立即输入的新字符。`A … X/T/N` 的现有连续编辑行为也不变。
- 空草稿的 Enter/原生点击、释放事件、应用快捷键、无效/非主按钮点击、旧引擎事件
  与非法发送均不更换当前目标。Space、数字采用和 Shift+Enter 仍只是编辑，不提交。
- 不重建 Rust 宿主会话：已实际提交的候选历史仍按原始载荷保留，不插入额外分隔。
  迟到的上一段模型结果不能复活候选，新一段联想继续可用。
- 不改变协议格式、词库和模型授权，也不扩展独立 `C` 文本对模型提交历史的记录范围；
  本轮的精确模型历史检查针对原生/伴随候选提交，不能等同于采集应用周边文字。

## 新增回归

- **96 组原生场景**：上述四种外部提交入口与伴随提交，以及 Shift+Enter、Space、
  数字采用、Enter 释放/Control/Alt、非主按钮/非法索引、旧对象 Enter/点击、非法
  `C` 发送。覆盖三语与空/非空草稿，检查准确提交载荷、目标、响应、重新输入草稿的
  完整性及新发送恢复。15 组原失败场景与 81 组对照均保留。
- **8 组模型时序场景**：Enter/小键盘 Enter/原生点击/伴随提交 × 请求在途/结果已
  就绪。回环模拟服务以事件控制回复，验证原文或明确选中的模型候选只提交一次，
  下一请求精确保留两段已提交载荷，旧候选不复活。共用上一轮取消模型夹具，并等待
  实际 CommitText 信号；Unix 响应不能代替另一条 D-Bus 通道的信号到达。
- **12 组面板场景**：在 [面板回归](../src/bin/panel/native_action_audit_test.rs) 中，
  鼠标/触摸 × 确认先/快照先 × 正常替换确认/外部提交为空/外部提交后重输相同文字。
  先发送 `hell`、排队 `x` 并按住 `y`，然后合并中间帧。外部提交后旧字符和按压不
  发送、不复活；空状态正确收起并能被新草稿唤出，新按键仍正常发送。正常确认对照
  则继续得到 `hellxy`，不丢掉同目标的连续输入。

全部接入现有 Linux 必跑测试组，不增加顶层 Rust 测试计数。原生层使用私有
D-Bus/IBus/XDG，窗口层使用私有 Xvfb 和合成快照/动作队列；两层测试不等于一次
真实目标应用的窗口联动验收。未连接真实模型或云服务，不宣称覆盖所有桌面环境。
