## 补齐失败诊断

生产命令执行器有意丢弃子进程 stderr；仅凭旧日志无法分辨“读取当前引擎失败”与
“切换失败”。现在给[私有激活夹具](../scripts/test-native-sync.py)增加
[诊断包装器](../scripts/fixtures/trace-native-ibus.sh)：

- 仍调用实际 IBus CLI，保留原 stdout 和退出码，只把命令参数、stderr 和退出码记入
  该轮私有目录。仅允许 engine 子命令；不收集按键、草稿或个人输入。
- 必须具有隔离标记、无桌面显示、真实的私有 runtime 路径及匹配的 IBus 地址；
  拒绝自递归、缺失程序和非绝对程序路径。缺少隔离标记的原生测试仍必须失败。
- 失败、超时或最终输入源检查失败时附带最多 16 KiB 诊断；正常通过时不输出这份日志。
- 没有给生产释放操作增加重试，也没有把 CLI 错误改成成功。

无显示器时，IBus CLI 可能在实际切换后因布局操作返回非零；本机诊断已看到这种情况，
现有控制器会读回实际输入源确认结果，相关原生回归仍通过。
[IBus 1.5.29 的 CLI 实现](https://github.com/ibus/ibus/blob/1.5.29/tools/main.vala)
也显示切换与布局操作是不同步骤。这不是已确认的本次失败根因，不能据此吞掉所有非零退出。

另增加显式的重复验证入口（默认 10 轮，范围 1–20）：

```sh
SUZAKU_NATIVE_ACTIVATION_ONLY=1 bash scripts/test-linux-ci.sh ibus
SUZAKU_NATIVE_ACTIVATION_ONLY=1 SUZAKU_NATIVE_ACTIVATION_REPEATS=20 bash scripts/test-linux-ci.sh ibus
```

普通完整 CI 仍按原流程运行，不以“重复到成功”代替失败。
