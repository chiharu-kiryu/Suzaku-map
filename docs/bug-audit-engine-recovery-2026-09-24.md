## N44：宿主就绪后，全局输入源仍可能为空

systemd 重启宿主只解决了进程可用性。IBus 移除旧组件时可能清掉全局引擎，重建
宿主后并不一定恢复。因此托盘生命周期增加一个独立后台观察器：

- 只有面板接管了本用户已经注册的桌面服务才启动；自定义 socket、私有总线和独立
  非服务宿主不启用。不是新增自启任务，不启动或重启 IBus。
- 只订阅 `GlobalEngineChanged` 和 Suzaku 组件的 `NameOwnerChanged`，记录最近
  观察到的输入源和组件所有者，不订阅按键、应用文本、候选或输入历史。
- 在同一 IBus 连接中观察到旧宿主消失和新宿主出现，且宿主通道就绪后，仅对确切的
  `No global engine.` 状态尝试恢复。通用超时、拒绝访问、异常数据不算“为空”。
- 恢复窗口为 8 秒，最多一次有界切换并读回；较新的输入源选择会取消旧恢复，
  切换前再次处理通知、查询当前引擎。读回任何有效输入源时都不覆盖，包括 GNOME
  在密码框中选出的键盘回退。
- 显式激活、释放、退出先停止观察器，避免与用户操作竞争；失败后按服务归属重建。
  总线断开后丢弃观察历史，不跨 IBus/登录会话猜测原输入源，也不重放旧草稿。

通信使用已有 GIO 依赖及专属线程上下文，无新增 Rust 依赖。原先尝试的 zbus 通道
在真实 IBus 消息上出现唯一名称解析 panic，已撤去；
[IBus 1.5.29 的总线实现](https://github.com/ibus/ibus/blob/1.5.29/bus/dbusimpl.c)
会将自身的常用名称直接作为名称所有者。回归必须使用真实 IBus，普通 D-Bus 替身
不足以证明这项兼容性。

观察器不读取其他应用的字段用途；IBus 1.5 的 `ContentType` 是只写属性，不能
假定它可查询。恢复 Suzaku 后仍由既有原生用途检查处理密码/PIN/PRIVATE，GNOME
已有的有效回退优先；这不是新增的全桌面密码识别或隐藏字段保护。

实现：[恢复控制器](../src/platform/linux_ibus_recovery.rs)、
[GIO 通道](../src/linux/ibus_recovery_bridge.c)、[托盘接入](../src/bin/panel/tray.rs)。

## N45：密码探针退出与桌面保护切换竞争

旧探针在自己的输入框仍为 PASSWORD 时请求恢复输入源，没有清理用途；成功 ACK
也不能保证随后 GNOME 的异步切换不会覆盖它。此前本机出现 stage 10，或成功返回
却从 Rime 变成美式键盘。

[原生探针](../src/linux/ibus_engine_bridge.c) 现在在取得焦点之前记录全局输入源；
无法确认回退目标时不开始切换。退出时先将**自身合成上下文**恢复为 FREE_FORM、
清除隐私 hints、让用途通知完成，再释放焦点并销毁该上下文。恢复原输入源使用有界
调用和读回，2 秒预算内需要连续稳定 350 毫秒；不能确认恢复则失败，不只看 ACK。
切换请求即使超时，也保留清理责任，因为请求可能已经生效。

新增私有 IBus 面板模拟 GNOME 的延迟密码回退/离开密码用途后的恢复。修复前测试在
“没有复原 FREE_FORM”断言失败；修复后同时验证用途清理、原输入源恢复、额外观察期
仍稳定，以及密码探针无提交、无候选。不接触个人密码框或系统候选面板。

## 回归入口与范围

```bash
# 完整私有原生输入回归，包含本轮两项检查
bash scripts/test-linux-ci.sh ibus
SUZAKU_IBUS_INLINE_PREEDIT=1 bash scripts/test-linux-ci.sh ibus

# 开发时仅复跑这两项，仍强制私有总线/运行目录/无显示隔离
SUZAKU_NATIVE_RECOVERY_ONLY=1 bash scripts/test-linux-ci.sh ibus
```

恢复专项使用真实 IBus 与真实新旧宿主，覆盖最新手动输入源、正常焦点/无焦点、
TERM/KILL、停机期间的手动选择、密码/PIN/PRIVATE 中有效的桌面回退、主动关闭
观察器后的不恢复。Rust 侧覆盖服务归属、未知来源、过期窗口、手动取消、元数据
队列上限/非法字符串，以及无响应私有连接的取消。原生测试无隔离标记必须拒绝运行。

验证结果：常规 Rust 测试 **833 通过、0 失败、25 忽略**；全功能和 GPU 两套全目标
严格 Clippy 通过。默认候选区草稿与 opt-in inline 两套完整私有 IBus 输入回归通过；
内联模式另复跑新增断言后的恢复专项，确认延迟回退确实发生，以及缺少已知原输入源
时探针以 stage 4 拒绝运行、不擅自激活其他输入法。真实 GTK 应用 **8 组**通过。
恢复 C 通道的 `-Wall -Wextra -Werror` 语法检查、Rustfmt、Python 语法、打包脚本
ShellCheck、源码树 **120 处审计链接**及主图一致性检查通过。链接验证是源码树检查，
不是新分发包验收。结束时只读确认个人宿主仍为原进程、服务运行、当前输入源为 Rime。

上述记录是隔离阶段的结果，不能单独代替 GNOME 本机验收。后续补验如下；日常密码
自动测试仍应优先使用隔离环境，不能把本次明确授权当作持续扰动桌面的许可。

不是新的版本发布，也不是 `.deb` 升级验收。安装前正常退出旧面板，保留约 35 MiB
可回滚副本，位于用户备份目录的 `install-recovery-20260924.*` 子目录；旧程序、
组件/服务文件、两份设置及本轮显式授权的本机检查脚本均保留在那里。

四个安装文件与 release 构建逐字节一致。无需再次注册：已有服务策略和组件路径
已经正确，两者均保持原字节。新面板启动时自行拉起已停服务，保持原 Rime 输入源；
只读注册 verify 通过。真实桌面为 GNOME Shell 46.0 / X11，IBus 守护进程始终未重启。

### 服务与输入源恢复

仅向经进程路径和服务主 PID 校验的 Suzaku 宿主发送信号；用 pidfd 避免 PID 复用，
没有通过额外 start/restart 命令代替自动恢复。

| 场景 | 观察结果 | 自动恢复用时 |
| --- | --- | --- |
| 当前 Rime，宿主 TERM | 实际观察到全局引擎为空；新宿主就绪且自动回到 Rime | 2.076 秒 |
| 当前 Rime，宿主 KILL | 同样观察到短暂空引擎，随后自动回到 Rime | 2.123 秒 |
| Suzaku 激活并持有合成草稿，宿主 TERM | 原输入上下文连接保留，新宿主恢复 Suzaku；旧草稿无提交 | 2.160 秒 |

第三项只向专门创建的 IBus 上下文发送方法调用，不向个人编辑器注入全局按键。
重启前的合成草稿没有重放；重启后同一上下文输入 `hel`，Tab/Space 后仍未提交，
Enter 只收到一次准确的 `hello `。随后通过托盘释放回 Rime。两种 Rime 场景恢复后
另观察 1 秒，均没有回落为空或切走；服务重试计数实际增加。

### 密码探针与正常流程

- 安装版 `--password` 在真实 GNOME 会话中执行 **2 次**，均无候选、无预编辑、
  无提交，正常返回；每次结束后额外观察 2 秒，始终保持 Rime，没有 stage 10 或
  延迟切到美式键盘。每次随后托盘激活/释放也稳定通过，未出现先前的立即切回问题。
- 普通英文、单词补全、PRIVATE 字段和面板 IPC 四种探针通过，均恢复 Rime。
  这些是独立原生上下文，不等同于实际个人文档正文测试。
- 完整退出新面板后，服务保持 inactive，等待超过 2 秒重试间隔仍没有被观察器或
  服务拉回。再次打开安装版面板后服务自动启动，Rime 保持不变。
- 用同一安装目录的程序，在独立显示/会话中复跑 **8 组真实 GTK 应用检查**通过，
  覆盖连续补全、数字/符号、取消、光标/选区、跨应用、密码框和无焦点伴随面板。
  GTK 正文检查仍属于隔离会话，不混同于上述真实 GNOME 生命周期补验。

结束时面板与宿主正常运行，当前输入源为 Rime。两份配置与备份逐字节一致，保留
青龙主题、隐藏标题栏、英文模式和关闭 LLM；GNOME 输入源列表/MRU、enabled 偏好、
Caps Lock/Num Lock 均与开始时一致。没有下载权重、访问实际模型或向已有文档发送
测试文本。临时检查目录已清理，回滚副本保留。

本轮两项问题在以上本机路径中未再复现；不覆盖登录/注销、原生 Wayland、IBus
整体重启后的自动重新激活或草稿耐久性。没有重新构建分发包、提交/推送或触发远端 CI。
