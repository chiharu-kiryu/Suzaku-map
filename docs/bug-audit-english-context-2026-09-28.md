## N59：上下文归一化把行、标识符和截断残片误认成普通单词

先在[英文质量回归](../tests/english_completion_quality.rs)复现：

- `hello123 ` 被剥掉数字后按 `hello` 匹配，错误提供 `world / there / everyone`。
  符号、路径及域名后空格也受同类过宽归一化影响；句点切分会暴露域名尾部的假单词。
- `good` 换行后输入 `m`，句子匹配把换行当普通空格，强制提示 `morning`，
  挤掉当前行独立输入 `m` 应有的候选。已提交上下文也会跨行参与匹配。
- 最近 160 字符从一个词中间截取时，可能将 `notgood` 的尾部误作独立 `good`。
  用合成的长横向空白稳定复现，不需要修改词库或读取个人输入。

最初九项测试中六项通过、三项失败；单独拆出的截断测试也在修复前失败。
原有 40 组写作正例和新增横向空白/大小写/缩写正例在修复前就已通过，未改其预期。

## 修复与边界

- 本地搭配和有限句子续写只匹配最后一行。LF、CR/CRLF、VT、FF、NEL、Unicode
  行分隔和段落分隔均作为边界；保留前文原始字节，新的当前行仍正常补全。
- 只容许普通括号、引号、逗号和冒号等既有短语包装参与匹配归一化，不再任意剥掉
  数字、符号或结束标点；也不在 token 内的句点处切出一个看似合法的尾词。
- 已提交上下文仍至多 160 个 Unicode 字符，截到一半的 token 不提供搭配依据；
  完整落在预算内的词保留。模型上下文预算及请求构造不改。
- 双空格、制表符、非断行空格、全角空格、大小写和直/弯撇号继续按原文输出。
  保护文本后另起正常短语、删除数字恢复普通词，以及采用/撤回/继续写均有回归。

这不是完整英文语法解析或任意文本分词。只修复已有本地词/句匹配的边界，不增加词库、
模型绑定或运行时 I/O，不改中日解码、快捷键、最终候选/每页数量、偏好或提交语义。
核心引擎的换行回归不表示新增 IBus 原生多行编辑；Enter 及伴随协议控制字符限制不变。
