# GTK 实际应用与预编辑清理审计 · 第二十三轮（2026-09-23）

沿 [功能链路网络](functional-network.md) 的 F10–F14/F29 检查实际应用中的英文
输入闭环。基线为 `0.6.1`、提交 `b0300ee94a94e43d78632ef081adfd54b980eefa`。
本轮确认并修复 **N38：同步 IBus 客户端残留预编辑文字**；修复仍在工作区，
不是已经发布或安装的新版本。

## N38：只隐藏，没有清空客户端的预编辑文字

旧实现结束输入时只调用 `ibus_engine_hide_preedit_text`。本机 IBus `1.5.29-2`
的同步 `PostProcessKeyEvent` 解码路径不支持单独的 hide 事件，打印
`Type 'h' is not supported`，客户端仍可能保留旧草稿。首次在 GTK4 隐藏文本
对话框看到提交后残留的下划线文字，随后在不依赖窗口的真实 IBus 同步客户端中
复现：提交信号已到达，客户端的预编辑仍非空/可见。

修复在既有清理入口发送 **空文本、光标 0、不可见** 的完整更新，而不是只发送
hide。候选列表和辅助提示仍隐藏；不改变空格续写、数字采用、回车提交、隐私策略
或已提交内容。该更新兼容同步和异步客户端，也不要求用户修改系统 IBus。
上游有同类问题记录：[IBus #2596](https://github.com/ibus/ibus/issues/2596)。

[原生夹具](../scripts/test-native-sync.py) 新增 12 组：客户端是否自行管理预编辑
提交 × Enter、Escape、删至空、整词删至空、Reset、FocusOut。检查完整预编辑
状态清空，且仅 Enter 收到一次精确提交。修复前已复现提交后的残留，修复后通过；
测试会先等待初始焦点通知处理完，不把启动阶段未就绪误判为丢字。

## 实际应用：8 组英文工作流

[独立运行入口](../scripts/test-linux-apps.sh) 和 [按键夹具](../scripts/test-linux-apps.py)
使用新建 Xvfb、私有会话总线/IBus、独立配置和合成文档，经过真正的 X11 按键、
GTK 输入模块、Suzaku 引擎，再检查应用保存的正文或对话框返回值。不是直接调用
输入引擎来代替应用键盘输入，也不接管用户当前桌面。

本机应用为 GNOME Text Editor `46.3-0ubuntu2`、Zenity `4.0.1-1build3`，GTK
`4.14.5+ds-0ubuntu0.10`；真实应用检查固定使用 IBus 同步按键模式。

1. 空格保留连续草稿，保存快捷键不提前提交，回车写入准确正文。
2. 词/句候选同时可用，数字采用仍可编辑，退格撤回拼写，再续写提交。
3. Alt 数字和 Shift 标点按字面输入，候选权重/角标不进入正文。
4. Tab 选择、Shift+Enter 采用、退格撤回和 Escape 取消。
5. 在编辑器真实光标处插入，以及替换编辑器选区。
6. 带未完成草稿切换到另一个应用，不携带旧草稿；首次 Enter 只提交输入法
   草稿，再次 Enter 才接受单行对话框，不重复写入。
7. Zenity 的 `--password` 声明密码用途，合成字母/数字不进入伴随快照；回到
   公开编辑器后恢复候选与提交。
8. 启动实际 Suzaku 面板，等待它用系统字体显示原生草稿，确认不夺取编辑器
   焦点，实体按键仍可续写并完整提交。

这 8 组已在本机通过，入口加入 Linux CI；不表示远端 CI 已执行。编辑器保存
非空文件时的末尾换行属于 GtkSourceView，断言明确包含它，不是 Suzaku 增添字符。
测试先用可丢弃的合成按键确认编辑区可接收真实输入，再清空自有测试文档；
不将应用尚未加载完成时的首键行为计入这 8 组工作流验收。

## 必须保留的外部应用隐私限制

Zenity `4.0.1` 的 `--entry --hide-text` 和 `--password` **不是同一用途声明**。
前者在本机只遮住文字，却向 IBus 报告 `FREE_FORM / hints=0`。使用纯合成文本
实测，它会触发普通候选/伴随草稿，因此**不能算作密码保护通过**。其
[对应版本源码](https://github.com/GNOME/zenity/blob/4.0.1/src/entry.c#L140) 只设置
visibility，与观察一致。

Suzaku 无法仅从普通 IBus 事件识别这种未声明的隐私字段。本轮没有修改系统 Zenity，
也没有根据进程名或屏幕内容猜测密码框。输入真实凭据前应切换回可信的原输入法；
关闭模型联想本身并不等于禁止本地候选/面板显示。见 [隐私边界](privacy.md)。

## 复验与边界

```bash
bash scripts/test-linux-apps.sh
bash scripts/test-linux-ci.sh ibus
```

需要 GNOME Text Editor、Zenity、IBus GTK 模块、Xvfb/Xauth、X11/XTest、Python GI。
默认清理合成数据，设置 `SUZAKU_APP_QA_KEEP=1` 可保留失败截图和进程日志；截图
只来自该夹具自有的虚拟显示。`SUZAKU_APP_QA_BIN_DIR` 可指定已构建程序目录。
模型联想明确关闭，不访问实际本地模型/云服务，不打开个人文档或个人配置。

本轮仍不覆盖浏览器/Electron、Qt、GNOME 窗口管理器、原生 Wayland、真实桌面
候选弹窗鼠标点击、不同键盘布局，以及长时间高频输入。Xvfb 中无窗口管理器，
因此不把这次真实 GTK 应用检查称为 GNOME/Wayland 全面验收。
