# Suzaku 0.7.2 · Draft-preserving language shortcuts and responsive settings

For **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**. This remains an Alpha;
keep a fallback input method. Other platforms are not newly release-qualified.

## Highlights

- **Ctrl+Shift+Space switches English ↔ Chinese**, even with an empty draft, in an
  ordinary focused Suzaku IBus field. Both shortcut profiles support it; Japanese
  switches to English and remains selectable in the tray. This is an input-language
  shortcut, not a system input-source, interface-language or translation command.
- **Keep writing across a language change:** after saving succeeds, the latest draft
  is preserved and candidates are rebuilt. Nothing is submitted automatically. Held
  Space switches once, even if Ctrl/Shift are released first. Failed saves keep the
  old language, draft and completion undo; in-flight changes are not queued repeatedly.
- **Responsive settings persistence (N56):** settings reads, writes and file sync run
  in one bounded background worker, outside the input-session lock. The input thread
  publishes only for a live request with a valid deadline and unchanged settings
  baseline. Canceled workers retain their capacity permit until they exit, preventing
  unbounded replacement threads while storage is stalled.
- **Focus and privacy boundaries:** leaving the field, clearing or committing the
  draft, entering privacy mode, starting Compose or destroying the engine abandons
  a pending keyboard language change. Successful changes revoke old-language model
  results and panel actions. Physical Ctrl/Shift presses leave a pending accent intact.
- **Discoverable and testable:** F1 opens the localized shortcut reference. Private
  IBus tests cover language changes and delayed persistence; real GTK keyboard tests
  cover modifier order and held keys without changing desktop bindings or lock state.
- An empty settings response now means **unconfirmed**, rather than incorrectly
  diagnosing an outdated host. A lost acknowledgement does not prove a save failed;
  refresh status before retrying.

Vocabulary, Space continuity, explicit submission and model-consent rules are unchanged.
No arbitrary shortcut rebinding, global key grab, automatic language detection or new
model dependency is introduced. Explicit tray changes to a different language still
clear the draft; the new keyboard path is deliberately draft-preserving.

## Validation and limits

Before the version bump, the unchanged production implementation passed **909 Rust
tests** (27 opt-in tests ignored by default), strict all-feature/all-target Clippy,
both complete private IBus modes, **49 real GTK keyboard groups**, and **17 isolated
window/startup tests**. Both IBus modes include 24 language/profile/draft/lock combinations
and two long Unicode drafts. The controlled slow-I/O gate passes nine existing settings
cases and ten focus-bound keyboard-language cases, including completed Compose and
typing during a pending save. See the [shortcut validation record](../shortcuts.md).

After the version bump, the **0.7.2** full-feature suite again passes **909 tests,
0 failures, 27 opt-in skips**, plus strict Clippy, formatting, the 26-flow focused
language gate and all **19 slow-I/O cases**. All four Linux release programs build;
the CLI reports 0.7.2. Local `.tar.gz` and `.deb` QA packages pass content, checksum,
launcher, offline-audit-link and non-installing smoke checks. These are worktree QA
artifacts, not published assets or a clean-container installation qualification.
Both complete IBus modes, GTK keyboard and window suites above were not rerun after
this metadata/documentation-only version bump; no production logic changed between runs.

Platform metadata, unchanged locked dependencies, Python/CI syntax, added local
documentation links, paired functional-network diagrams and the redacted staged-change
secret scan pass. Bash syntax is checked; ShellCheck is not installed locally and is
not claimed as rerun here. It remains part of remote CI. Release-check logs are retained
locally in `/tmp/sz072.FVUjHE`, separate from the earlier development/failure evidence.

The test-first failure for the missing shortcut and two old assertion failures are
retained: Ctrl+Shift+Space no longer passes through unchanged, and an extra reference
row can exceed a fixed-height large-text viewport. Tests now require the intended
draft-preserving behavior and bounded scrolling, without skipping cases or extending
input/save deadlines. The original N56 reproduction and its separate validation are
recorded in the [settings I/O audit](../bug-audit-settings-io-2026-09-27.md).

The controlled N56 reproduction **does not establish the cause of historical 0.7.0 CI
restoration failures, 0.7.1 empty replies or the later desktop OOM**. Atomic publication
still requires a main-thread rename; this is not a guarantee that every filesystem
operation is nonblocking or that acknowledgements form an end-to-end transaction.
Other platforms retain the synchronous settings FFI.

Local validation uses serial jobs and task-owned systemd scopes with `MemoryHigh=2G`,
`MemoryMax=3G`, `MemorySwapMax=0`; no unrelated processes or desktop limits are changed.
Native Wayland, arbitrary application shortcut conflicts, physical keyboard LEDs and
real-model quality remain outside this release's local acceptance scope.

Rust/lockfile, macOS bundles and Android metadata use **0.7.2**. Bundle build numbers
and the Android version code are **26**; dependency versions are unchanged. A source
commit/tag does not update existing installations or attach binaries to a GitHub Release.
Local checks, remote CI and installation acceptance are separate.

## Install and upgrade

Once matching assets are available, verify `suzaku_0.7.2_amd64.deb` with
`sha256sum -c suzaku_0.7.2_amd64.deb.sha256`, finish/cancel the draft, fully quit Suzaku,
then use `sudo apt install ./suzaku_0.7.2_amd64.deb`. Upgrade the panel and host together
before using the new shortcut. Existing settings, profiles and cloud-consent rules
are retained. Source/user installations must likewise replace matching binaries.
Hosts registered before 0.6.5 still need explicit re-registration for the service retry
policy; see [Linux installation/data](../linux-packaging-data.md).
