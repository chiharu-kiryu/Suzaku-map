# Suzaku 0.5.9 · Linux Alpha input-continuity patch

For **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**. This remains an Alpha;
keep a fallback input method. Other platforms are not release-qualified.

This patch collects functional-network fixes **N24–N28** after 0.5.8. It preserves the continuous
drafting keys, explicit submission, provider consent and no-automatic-replay rules.

## Highlights

- **Translation request gestures (N24):** changing the field or source, cancelling, or reloading
  configuration invalidates a pending Translate press even before a worker request exists. Releasing
  an old mouse/touch gesture cannot translate a different draft. Same-field metadata refreshes remain usable.
- **Tool handoff follow-ups (N25):** after a translation, voice or handwriting replacement is
  acknowledged, screen-keyboard edits continue from that replacement rather than the old source.
  The next write still waits for its matching authoritative snapshot and revision. Newer tool work is
  not cleared by an older acknowledgement; uncertain writes are retained for explicit recovery, not retried.
- **Candidate action follow-ups (N26):** the same acknowledgement/snapshot protection now covers
  word/sentence adoption, selection changes, commits and clearing. A successful commit/clear starts
  the next edit from an empty draft, without bringing back the submitted text or inventing a revision.
- **Continuous panel visibility (N27):** an intermediate empty host snapshot no longer hides a
  companion that already has queued typing. Manual hiding remains respected even when the host is
  temporarily empty; unconfirmed deletion does not prematurely hide a still-nonempty host draft.
  Actual empty, private, unfocused and disconnected states retain their safety boundaries.
- **Literal selection synchronization (N28):** choosing the original spelling with a number key
  publishes the new IBus/companion selection and revision even though the text is unchanged. The
  highlighted candidate now agrees with Enter's actual payload, including later-page literal choices.
  Candidates are not rebuilt or unlocked, and adoption still does not submit text.

## Validation and compatibility

- Feature-enabled regression suite: **823 passed, 0 failed, 24 opt-in tests skipped** by the ordinary
  command. Skipped tests are not counted as passed.
- Private runners passed **16 panel UI groups and 1 executable-startup group**, plus the complete
  native IBus chain. These checks were rerun with the 0.5.9 metadata.
- Strict Clippy passed for both `--all-features --all-targets` and `--features gpu --all-targets`
  with `-D warnings`. Formatting, whitespace and the related Linux scripts' ShellCheck also passed.
- Rust/lockfile, macOS and Android version metadata agree. Staged secret scanning found no leaks;
  all **41 audit-document links** checked in the source tree resolve. Reports are included in the
  explicit Linux documentation package list; this is not a built-package validation.

Regression coverage includes **34** translation-gesture combinations, **6** tool-handoff ordering
cases and **30** shared late-result boundaries, **86** candidate-action/visibility cases, and **12**
literal-selection/continuation cases across English, Chinese and Japanese. These are scenario counts
inside the private suites, not additional top-level Rust test counts.

Panel tests use private Xvfb/D-Bus, synthetic frames and action queues; IBus tests use a private
native host and input contexts. Model tests only use owned loopback fixtures. None operates the
development desktop's input method, a real microphone or model account; they do not establish full
GNOME/Wayland, arbitrary-application or other-platform acceptance.

Rust, macOS bundle and Android app metadata all use **0.5.9**; the bundle build number and Android
version code are **13**. This aligns metadata without expanding native-platform support.

## Install and upgrade

This source patch is not an attached binary package. Once matching release assets are available,
verify `suzaku_0.5.9_amd64.deb` with `sha256sum -c suzaku_0.5.9_amd64.deb.sha256`, fully quit Suzaku,
then install using `sudo apt install ./suzaku_0.5.9_amd64.deb`. Existing configuration is retained.
See [Linux packaging/data](../linux-packaging-data.md) for source builds and package validation.
No package is installed as part of preparing this patch. Fresh distributable packaging and container
installation/upgrade/removal are not rerun for this source commit; local checks do not imply remote
CI has run or release assets exist.

Linux speech remains a simulated bridge, handwriting and offline CJK dictionaries remain limited,
and input/recovery drafts are still in memory. This patch adds no migration, model download, cloud
consent or change to Enter/candidate-click submission.
