# Suzaku 0.6.5 · Linux Alpha service and input-source recovery patch

For **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**. This remains an Alpha;
keep a fallback input method. Other platforms are not release-qualified.

This patch includes the recovery work from audit rounds 29–31, including N43–N45.
Continuous-writing keys, candidate payloads, model behavior and release build settings are
unchanged. Recovery does not replay discarded drafts or unconfirmed sends.

## Highlights

- **N43 — Retry through long IBus outages:** newly registered host units use
  `StartLimitIntervalSec=0`, `Restart=always` and a two-second retry interval. They no longer
  exhaust systemd's default start quota while the bus is unavailable. Explicit stop cancels
  retries, and existing disabled/masked preferences are preserved. Permanent configuration
  errors still need attention; retrying does not fix their cause.
- **N44 — Recover a missing input source after host replacement:** while the panel owns the
  registered desktop host service, a separate observer remembers input-source and host-owner
  metadata. After an observed replacement on the same IBus connection, a ready host and a
  confirmed missing global engine permit one bounded restoration within an eight-second window.
  Newer manual choices and valid desktop fallbacks win. Explicit activation/release/quit stops
  the observer first; IBus disconnection discards its history. Custom/private host endpoints
  and independently launched hosts are not adopted.
- **N45 — Restore safely after password diagnostics:** the native probe snapshots the original
  engine before taking focus, refuses to switch without a known fallback, and resets only its
  own synthetic context's purpose before destroying it. Restoration uses a two-second budget
  and stable read-back, rather than trusting a successful switch acknowledgement alone.
- **Recovery regressions:** private daemon-loss/application checks, isolated real-systemd retry
  checks and production-observer/password-cleanup tests are included in Linux CI. Reports are
  added to the packaging manifest. This changes CI configuration, not the status of a remote run.

The observer does not subscribe to keys, drafts or application text, and does not inspect other
applications' input purpose. Native privacy checks remain in place. Full IBus daemon/session
replacement, login/logout, native Wayland and draft persistence are not covered by the same-bus
automatic input-source recovery guarantee.

## Validation and compatibility

Rerun with **0.6.5** metadata:

- All-feature tests: **833 passed, 0 failed, 25 opt-in tests skipped** by the ordinary command.
  Skipped tests are not counted as passed. The registration suite includes 17 passing tests.
- Strict Clippy passes for both all-feature and GPU-only targets with `-D warnings`.
- The complete private native IBus chain passes in both default candidate-area and opt-in
  inline modes, including the production observer and delayed password-purpose restoration tests.
- **8 real GTK application workflow groups** pass, including continuous input, adoption/undo,
  focus and password boundaries, and the no-focus companion.
- **13 private IBus startup/daemon-loss checks** pass with real GTK input and candidate clicks,
  preserving the same application and companion across explicit recovery.
- Rust formatting, shell lint, Python/YAML syntax, strict recovery-bridge C syntax checks,
  version metadata, 124 source-tree audit links and main-graph parity pass. The rebuilt tool
  reports 0.6.5. Staged secret scanning found no leaks. Source-tree link checks are not
  distribution-package acceptance.

Before the version bump, the same fixes also passed **5 real-systemd recovery checks in two
fresh isolated containers**. With explicit user
authorization, the user-level installation passed GNOME 46/X11 host TERM/KILL and active-draft
recovery in roughly 2.1 seconds, two password probes with stable Rime restoration, tray lifecycle
checks and 8 isolated GTK workflow groups. Configuration and keyboard state were preserved.
Those installed binaries still carry **0.6.4 plus these fixes**; this source release does not
replace them again. See the [installation and recovery audit](../bug-audit-engine-recovery-2026-09-24.md).

Routine native tests use private sessions and synthetic input, not personal documents or real
models. The source-release checks do not repeat the container runs or the personal-desktop
fault injection. Earlier popup, Chrome/Qt and independent UI results remain historical coverage,
not a claim that every suite was rerun for this patch.

Rust/lockfile, macOS bundle and Android app metadata all use **0.6.5**. The bundle build number
and Android version code are **19**. Metadata alignment does not expand platform support.

## Install and upgrade

This source patch is not an attached binary package. Once matching assets are available, verify
`suzaku_0.6.5_amd64.deb` with `sha256sum -c suzaku_0.6.5_amd64.deb.sha256`, fully quit Suzaku,
then install using `sudo apt install ./suzaku_0.6.5_amd64.deb`. Existing configuration is retained.

The N43 retry policy is written only by an explicit `linux-register install` using the new tool.
Replacing binaries or installing a package does not silently rewrite existing user service files.
Finish/cancel input and fully quit first, then register as the desktop user **without sudo**:

```bash
/usr/bin/suzaku-tool linux-register install
/usr/bin/suzaku-tool linux-register verify
```

These paths refer to a `.deb` installation; source/user installations should use their matching
new tool. See [Linux installation and data](../linux-packaging-data.md). Registration preserves
existing autostart choices and does not imply that discarded drafts or a replaced IBus session
will be restored automatically.

Preparing this patch does not build/install distribution packages, publish assets, push commits
or imply remote CI has run. It adds no model download, cloud authorization or data migration.
