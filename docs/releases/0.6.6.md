# Suzaku 0.6.6 · Linux Alpha bilingual input and model responsiveness patch

For **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**. This remains an Alpha;
keep a fallback input method. Other platforms are not release-qualified.

This patch includes audit rounds 32–36, including N46/N47, with Chinese and English input
as the current priority. Japanese and the existing interface/translation languages remain
available. Number-key adoption, one-step completion undo, Space continuity and explicit
Enter/click submission keep their existing meanings.

## Highlights

- **N47 — Separated Chinese Pinyin:** existing dictionary entries now record explicit syllables.
  Joined, space-separated and apostrophe-separated readings match the same words, including
  unfinished-word completion, without stripping invalid boundaries. Required disambiguation
  such as `xi'an` remains distinct from `xian`; unknown text stays available literally.
  This repairs matching, not dictionary size or arbitrary mixed-language conversion.
- **Paired Chinese/English regressions:** 40 authored Chinese examples in four spelling forms
  improve from 43/160 to 160/160 primary conversions; six cases check simultaneous word/sentence
  choices. The existing 40 English scenarios retain word-in-top-three and sentence-on-first-page
  coverage. Twelve native bilingual workflows exercise word/sentence adoption, exact undo,
  re-adoption, continued typing and a single explicit commit. These are fixed regressions,
  not a general language-quality score.
- **N46 — Release obsolete local requests:** changed drafts and cancellation boundaries signal
  in-flight local HTTP candidate/discovery requests. Connected reads/writes check cancellation
  cooperatively, allowing the single worker to take newer work without waiting for the old
  response's full deadline. Partial writes advance safely, incomplete responses are rejected,
  and cancellation does not poison model discovery caches. The original total deadline,
  debounce and replaceable pending slot remain; no per-key threads or automatic retries are added.
- **Lean model requests and output checks:** default requests ask for two complete strings while
  retaining language, draft, local conversion, current-focus context and completion mode.
  Existing response formats remain supported. Generated request-metadata echoes are rejected.
  Translation restates its task, uses smaller contexts for short inputs, and rejects missing
  source question marks without altering the draft; this conservative check is not semantic validation.
- **Broader isolated Linux QA:** added 26 physical-keyboard/layout workflows to CI, Firefox and
  VS Code fixtures, and opt-in local-model workflows that distinguish safe fallback from a
  genuinely model-origin candidate. Synthetic fixtures do not read personal documents or change
  the desktop keyboard layout. The packaging manifest includes all five new audit reports.

## Validation and compatibility

Rerun with **0.6.6** metadata:

- All-feature tests: **853 passed, 0 failed, 27 opt-in tests skipped** by the ordinary serial
  command. Skipped tests are not counted as passed; the explicit runs below cover their named scope.
- Strict Clippy passes for both all-feature and GPU-only targets with `-D warnings`.
- The complete private native IBus chain passes in both default candidate-area and opt-in
  inline modes, including N46's eight obsolete-request boundaries and N47's twelve bilingual
  adoption/undo/continuation workflows. Connected mock requests close in approximately 49–59 ms;
  that is not an end-to-end or real-model latency guarantee.
- **17 opt-in window/entry tests** pass, including translation draft preservation, native gesture
  boundaries, layout/settings behavior and multilingual GPU glyph coverage.
- **26 physical-keyboard/layout workflow groups** and **8 real GTK application workflow groups**
  pass on private X11 sessions; no personal desktop settings or input sources are changed.
- Rust formatting, shell lint, all 14 Python scripts/fixtures, GitHub YAML, JavaScript/JSON fixture
  syntax, version metadata, 149 source-tree audit links and main-graph parity pass. All 36 audit
  reports are listed in the packaging script. The rebuilt tool reports 0.6.6; staged secret
  scanning found no leaks. Source-tree checks are not distribution-package acceptance.

Routine checks use synthetic text, private configurations and mock model responses. This release
pass does not repeat distribution build/install, personal-desktop recovery, Firefox/VS Code,
Qt, stock-popup/lifecycle or real-model QA; earlier results remain the scope of their audit reports.

Earlier audit rounds recorded 23 passing Firefox 156.0 and 14 VS Code
1.138.0 / Electron 42.10.0 workflows on private X11 sessions. Firefox was launched directly
from its installed Snap files; the Snap launcher, native Wayland, arbitrary Electron apps,
terminal editors and hardware keyboard LEDs remain unqualified.

Explicit local CPU `llama3.2:3b` Q4_K_M checks also passed seven application workflows,
including model-only candidate adoption/undo/continuation/commit with a private 5-second budget.
The final seven candidate probes returned valid output in 0.763–1.700 seconds, but the default
1200 ms English run still timed out in two of five cases. These are earlier audit observations,
not a reliable default-budget or general model-quality guarantee. Japanese/Korean translation
still shows semantic omissions or mixed-language output; punctuation checks cannot prove accuracy.

Cancellation closes obsolete connected local I/O, not data already received by a server, and
does not guarantee server-side compute interruption. Connection setup/shared discovery-lock
waits remain bounded by their existing operations. Blocking cloud HTTPS and legacy providers
still finish or time out before discarding results; translation cancellation is unchanged.

Rust/lockfile, macOS bundle and Android app metadata all use **0.6.6**. The bundle build number
and Android version code are **20**. Metadata alignment does not expand platform support.

## Install and upgrade

This is a source commit/tag, not an attached binary package or an installation update.
Once matching assets are available, verify `suzaku_0.6.6_amd64.deb` with
`sha256sum -c suzaku_0.6.6_amd64.deb.sha256`, fully quit Suzaku, then install using
`sudo apt install ./suzaku_0.6.6_amd64.deb`. Existing configuration is retained.

Upgrading from a host registered before 0.6.5 still requires explicit re-registration to receive
the N43 service retry policy; replacing binaries does not silently rewrite user service files.
After upgrading and fully quitting, run the matching new tool as your desktop user, without sudo:

```bash
/usr/bin/suzaku-tool linux-register install
/usr/bin/suzaku-tool linux-register verify
```

These paths refer to a `.deb` installation; source/user installations should use their matching
new tool. See [Linux installation and data](../linux-packaging-data.md). This patch adds no data
migration, model download, cloud consent or automatic model switch. Source checks do not imply
remote CI success or publication of downloadable assets.
