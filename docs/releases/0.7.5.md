# Suzaku 0.7.5 · Bilingual sentence continuity and safer English context

For **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**. This remains an Alpha;
keep a fallback input method. Other platforms are not newly release-qualified.

## Highlights

- **Explanation and learning fallback:** a new independent `clarity` layer adds 58 explicit
  English forms (70 indexed forms including phrase projections), 174 Chinese readings,
  40 contexts and 80 authored sentences per language. A further 再 homophone brings the
  Chinese increase to 175 readings. Totals are **6,004 English forms**, **1,806 Chinese readings**,
  313 / 305 English / Chinese contexts and 590 / 608 authored sentences.
  Earlier ranks, homophone order and Japanese resources remain unchanged.
- **Chinese sentence progress (N58):** adopting and continuing a word retains its matching
  authored sentence, such as `发音 ke yi` → `发音 可以再示范一下吗？`. Long drafts retain
  verified sentence progress within the existing 256-character local window. Bounded homophone
  choices can offer a suitable sentence without rewriting adopted Han text or replacing the
  primary conversion; `zai` still prefers 在, while 再 remains an explicit alternative.
- **English context boundaries (N59):** real line/paragraph boundaries no longer act like spaces
  in local sentence matching. Digits, symbols, domains and clipped context fragments do not
  become false words: `hello123 ` and `example.hello ` no longer imply `hello world`.
  Normal phrases after protected text still complete, and deleting digits restores ordinary
  word suggestions. Literal case, spaces and straight/curly-apostrophe contractions are retained.
- **Continuous input regressions:** 44 authored fallback scenarios per language, 40 standalone
  English forms, eight unfinished Pinyin cases, consecutive Chinese word adoption and English
  short/long context boundaries. Native tests include exact adoption/undo, Space and commits;
  real GTK checks observe both the editor buffer and completed saved text.

Vocabulary remains embedded data, independent of models, hosts and decoders. Local choices
appear immediately while optional model requests are pending or unavailable. These finite
authored examples are not open-ended generation, arbitrary mixed-text parsing or a general
language-quality score. No runtime dictionary import, model installation or extra input-path I/O
is added. Candidate/page limits, model budgets, settings formats, language shortcuts, private-field
behavior and memory-only preferences remain unchanged. Space continues; Enter/click submits.

## Validation and limits

Before the metadata-only version bump, the completed implementation passed **977 Rust tests,
0 failures and 27 opt-in skips**, strict all-feature/all-target Clippy and both complete private
IBus modes. Each native mode includes 16 actual loopback HTTP 503/deadline workflows, three N58
sentence-progress workflows and eight N59 context-boundary workflows. Earlier work passed all
42 real GTK vocabulary workflows; the 2026-10-02 closeout separately rechecked 43 focused Rust
tests, strict Clippy and the complete basic GTK suite including two physical N59 cases.

After the version bump, the complete Rust suite again passed **977 tests, 0 failures and
27 opt-in skips**, and strict all-feature/all-target Clippy passed. All four Linux release
binaries built successfully. The new release panel and host then passed all **42 real GTK
vocabulary and sentence-progress workflows** on a private display, including exact saved text;
these were the release binaries, not the older personal installation or a debug-only check.
Version/build metadata, both macOS plists, Python/Bash syntax, paired functional diagrams and
all **242 source audit links** were checked. Third-party lockfile entries match 0.7.4 unchanged.
ShellCheck and a local full-history Gitleaks scan were not run; neither is included in these results.

Local `.tar.gz` and `.deb` packages passed checksum, manifest, binary-version, launcher,
content and non-installing CLI smoke checks, including **266 tarball / 228 Debian audit
documentation links** (the tarball also checks flattened guides). These are local QA results,
not published assets or clean-container installation acceptance. Release-check logs and
packages are retained in the task-owned `szrelease075.*` directory; the personal installation
was not upgraded.

The [N58 audit](../bug-audit-sentence-progress-2026-09-27.md) and
[N59 audit](../bug-audit-english-context-2026-09-28.md) preserve failed regressions, fixture
corrections, canceled attempts and the distinction between missing temporary logs and confirmed
exit results. No assertions or original 120/240-second native/application deadlines were relaxed.

Builds and native checks run serially with one Cargo job in task-owned user scopes using
`MemoryHigh=2G`, `MemoryMax=3G`, `MemorySwapMax=0`. Personal desktop input and unrelated
processes remain untouched. Local validation, remote CI, clean-container installation and
personal-desktop acceptance are distinct; native Wayland and actual model quality are not
newly qualified by these checks.

Rust/lockfile, macOS bundle versions and Android metadata use **0.7.5**. Bundle build numbers
and the Android version code are **29**; third-party dependency versions are unchanged.
A source commit/tag does not update the installed application or attach GitHub Release assets.
Downloadable Linux packages and checksums are required starting with **0.8.0**, as recorded
in [Linux packaging](../linux-packaging-data.md#从-080-开始的发布要求).

## Install and upgrade

Once matching assets are available, verify `suzaku_0.7.5_amd64.deb` with
`sha256sum -c suzaku_0.7.5_amd64.deb.sha256`, finish/cancel the draft, fully quit Suzaku,
then use `sudo apt install ./suzaku_0.7.5_amd64.deb`. Update panel and host together.
Source/user installations also need rebuilding and reinstalling to use the embedded vocabulary
and continuity fixes. This source release does not upgrade a personal installation or register
services; settings, privacy and explicit cloud-consent rules remain unchanged.
