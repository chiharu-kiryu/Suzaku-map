# Suzaku 0.8.4 · Continuous input reliability and everyday fallback

Release target: **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**.
Suzaku remains an Alpha; keep another input method available. Chinese and
English remain the core, with bounded Japanese Romaji/Kana fallback. Other
platforms are not newly release-qualified by synchronized version metadata.

## Highlights

- **Continuous writing and undo:** clamped candidate navigation and inert
  Backspace no longer discard adopted-word undo or cancel pending prediction.
  Starting and canceling Compose preserves the preceding adoption; actual
  printable edits still invalidate it. Space continues writing and only
  explicit submission commits.
- **Host-owned screen keys:** native screen Backspace and Space use the host's
  authoritative editing/undo semantics instead of guessing replacement drafts.
  Ordered replies, context/revision guards, bounded queues and failure recovery
  protect draft prefixes; uncertain edits are not automatically replayed.
- **X11 click and layout safety:** clicks use coordinates from their own button
  event after a panel move or resize. A narrow vendored winit 0.30.13 patch
  separates button coordinates from motion, preventing extra drag displacement.
  Candidate actions still require the presented layout and exact owning target.
  Provenance, Apache-2.0 license and removal conditions ship with the patch.
- **Bounded input work:** avoid whole-draft decoding whose long-IBus result would
  be discarded, reuse indexed local lookups and keep commit undo history as
  UTF-8 byte checkpoints instead of copying every accumulated prefix. These
  changes do not expand decoder budgets, cap total committed text or establish
  the cause of earlier OOM reports.
- **Everyday fallback:** add coordination/follow-up, hobbies/weekend plans and
  clarification/confirmation examples. Builtin totals are **English 6,134
  indexed forms / 577 contexts / 1,118 sentences; Chinese 2,592 readings /
  571 contexts / 1,140 continuations; Japanese 202 readings / 102 contexts /
  203 continuation records**. Fixed old-content/order guards and first-page
  expectations remain; a new conflicting Chinese reading was replaced rather
  than weakening old candidate reachability.
- **Optional family collections:** EN/ZH/JA data-only family/home packs expand
  the recommended catalog from eleven to fourteen. Explicit install/enable
  applies at the next host/panel startup; old shipped collections remain intact.
  No executable plugin, automatic download or live reload is added.

Vocabulary and prediction remain model-independent. Authored fallback is not
open-ended generation, a complete dictionary or Japanese morphological analysis.
No model weights, credentials or personal input history are bundled.

## Validation and release gate

Before the version-only metadata update, the corrected development snapshot
passed **1,335 all-feature Rust tests**, strict all-target Clippy, formatting,
21 tensor-validator checks and six offline-package manifest checks. The default
Rust invocation leaves **29 explicit/fixture gates ignored**; do not count those
as native, real-model or device acceptance.

The complete isolated GTK vocabulary gate passed **108 workflows** (56 + 52),
including word/sentence adoption, literal Space, exact undo, page-two selection
and saved-text checks. A separate **14-workflow** pack gate passed with all
fourteen recommended packages explicitly loaded in private data. Earlier
eleven-selected-pack logs and every failed attempt remain in the
[development record](../../DEVELOPMENT.md). Synthetic model errors and XTest
keys are not real-model quality, human keyboard or personal-desktop acceptance.

Release preparation synchronizes Rust, macOS and Android to **0.8.4**, with
platform build number **34**. The locked winit version stays 0.30.13 but resolves
to the declared local patch; its complete source and notices must be committed.
Other third-party locked versions are unchanged. No personal installation is
updated by a source push.

After the 0.8.4 metadata update, the same **1,335 Rust tests** pass again with
zero failures/29 dedicated skips, and strict Clippy passes. Formatting,
version/build/dependency consistency, source digest, script/CI syntax, tensor
and diagnostic contracts, source audit links and staged/existing-history
secret scans also pass. Local ShellCheck is unavailable; its required CI gate
is unchanged. Earlier GTK results remain development-snapshot evidence, not
an additional post-version native/device acceptance claim.

**Exact-commit CI and binary package acceptance remain pending at preparation.**
The main-branch CI builds and validates Linux artifacts; the version tag alone
does not publish a GitHub Release. Only attach `.deb`, binary `.tar.gz` and both
SHA-256 files after that same clean commit passes full Ubuntu 24.04 CI,
package-content checks and clean-container installation/upgrade/removal.
Source tags or expiring CI artifacts alone do not complete a version release;
see the [Linux release gate](../linux-packaging-data.md).

The earlier 0.8.3 CI timeout is not relabeled successful and its tag is not moved.
The intermittent IBus daemon abort on the newer local Ubuntu/IBus/GLib stack is
still **unresolved and deferred**. This version does not claim native Wayland,
arbitrary multi-monitor/DPI, macOS/Windows/Android native behavior, real Linux
speech input or broader Japanese long-draft conversion. See
[known limitations](../known-limitations.md).

## Install / upgrade

After approved 0.8.4 assets appear on the GitHub Release, finish or cancel the
current draft, fully quit Suzaku, then verify/install on Ubuntu 24.04 amd64:

```bash
sha256sum -c suzaku_0.8.4_amd64.deb.sha256
sudo apt install ./suzaku_0.8.4_amd64.deb
/usr/bin/suzaku-panel
```

On first installation, explicitly register as the desktop user without sudo:
`/usr/bin/suzaku-tool linux-register install`. Installing the package alone
does not activate an input method or register/start a user service. Upgrade
host and panel together; configuration, cloud consent and user packs remain.

For the tarball, verify
`suzaku-0.8.4-x86_64-unknown-linux-gnu.tar.gz.sha256` and the extracted
`SHA256SUMS`, then run `./bin/panel`. It is not a universal static Linux binary.
Source/user-level installs need their own rebuild/reinstall. See
[installation and data](../linux-packaging-data.md) and [privacy](../privacy.md).
