# Suzaku 0.6.3 · Linux Alpha candidate popup compatibility patch

For **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**. This remains an Alpha;
keep a fallback input method. Other platforms are not release-qualified.

This patch collects functional-network fixes **N41–N42**, stock candidate-window checks and
real input lifecycle coverage after 0.6.2. Continuous drafting, candidate payloads and explicit
submission rules are unchanged. No system IBus files or desktop settings are modified.

## Highlights

- **Bounded draft previews (N41):** the auxiliary draft suffix now fits within 48 display cells
  as well as 160 Unicode code points. Wide characters count as two cells, zero-width characters
  as zero. This avoids tested unwrapped stock popups extending beyond the screen, without
  truncating the actual draft, commit text or model context.
- **Clickable candidate numbers (N42):** superscript numbers share the candidate text's hit
  target. The separate IBus labels are explicitly empty, avoiding the GTK3 IBus 1.5.29 label
  column's invalid click indices. Both pages retain their own 1–6 numbering. Suzaku still
  rejects invalid indices instead of guessing a candidate, and commits never include labels.
- **Unchanged input rules:** physical 1–6 adopts a candidate and keeps writing open; clicking
  its visible number or text submits it. Middle/right clicks do not select or submit.
  Spaces and punctuation continue the draft, and Enter remains explicit submission.
- **Lifecycle coverage:** 21 real GTK workflows cover input-method switching, declared password
  fields, stock-panel resets, companion restarts and explicit host restarts/reactivation.
  Restarting only the companion preserves the running host's draft; host exit or switching
  away clears it. These are regression checks, not a new persistence or auto-recovery feature.

## Validation and compatibility

- Feature-enabled regression suite: **826 passed, 0 failed, 24 opt-in tests skipped** by the
  ordinary command. Skipped tests are not counted as passed.
- Stock GTK3 popup: **46 workflow groups**, including **17 actual superscript-glyph click
  checks**, pass on a private 800x600 display. Long English/CJK/emoji previews remain on-screen
  and commit the full text; clicks resolve to the correct candidate on both pages.
- Input lifecycle: **21 real GTK groups** pass across switching, privacy and process reconnection.
- Application input: **115 Chrome/Qt 5/Qt 6 workflow groups** (including Qt synchronous and
  asynchronous modes), plus **8 GTK groups**, pass with strict focus and literal-number checks.
- Complete private native IBus tests pass in both default candidate-area and opt-in inline modes,
  including exact commits, candidate metadata, invalid-index rejection and diagnostic probes.
- Isolated UI runners pass **16 panel groups and 1 executable-startup group**.
- Strict Clippy passes for both all-feature and GPU-only targets with `-D warnings`. Formatting,
  whitespace, Python/YAML syntax, ShellCheck, source documentation links and graph parity pass.
- Version metadata agrees across Rust/lockfile, macOS and Android; the rebuilt tool reports 0.6.3.
  The three new audit documents are listed for packaging; this is not built-package validation.
- Staged secret scanning found no leaks.

These checks were rerun with the **0.6.3** metadata. Inspection-time reproduction details remain
in the [ordinal compatibility audit](../bug-audit-ordinal-click-2026-09-23.md).

Tests use owned Xvfb/D-Bus/IBus sessions, synthetic fields and temporary application profiles;
model tests only use owned loopback fixtures. They do not interact with personal desktop input,
browser profiles, a real model or microphone. CI includes stock-popup and lifecycle gates;
local validation does not imply remote CI has run.

The stock GTK3 popup checks are not GNOME Shell's native candidate UI or native Wayland
acceptance, and do not cover arbitrary fonts, DPI or all IBus versions. Empty shortcut labels
can leave a small unused gutter in the system panel. Other input methods using the broken
separate column are not repaired. Existing privacy and application-reporting limits remain.

Rust, macOS bundle and Android app metadata all use **0.6.3**; the bundle build number and Android
version code are **17**. Metadata alignment does not expand native-platform support.

## Install and upgrade

This source patch is not an attached binary package. Once matching release assets are available,
verify `suzaku_0.6.3_amd64.deb` with `sha256sum -c suzaku_0.6.3_amd64.deb.sha256`, fully quit Suzaku,
then install using `sudo apt install ./suzaku_0.6.3_amd64.deb`. Existing configuration is retained.
See [Linux packaging/data](../linux-packaging-data.md) for source builds and package validation.
No package is installed as part of preparing this patch. Fresh 0.6.3 distributable packaging and
container installation/upgrade/removal are not rerun for this source commit; a local tag does not
mean release assets exist or an older installation has been updated.

Linux speech remains a simulated bridge; handwriting and offline CJK dictionaries remain limited.
Drafts stay in memory and can be lost on cancellation, focus change, exit or crash. This patch
adds no data migration, model download or cloud authorization.
