# Suzaku 0.8.0 · Offline vocabulary packs and authoring SDK

For **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**. This remains an Alpha;
keep another input method available. Other platforms are not newly release-qualified.

## Highlights

- **Data-only offline packs:** add optional vocabulary without rebuilding or selecting a model.
  Each pack declares its language, topics, version, authors and license. The CLI supports catalog
  filters, export, validation, installation, explicit replacement, enable/disable, removal and
  local candidate previews. Browsing does not download or install anything.
- **Stable startup snapshots:** Linux host and panel load enabled packs before constructing their
  engines, appending to built-ins without replacing old ranks or homophone order. Input events
  do not read package files. Restart **both host and panel** to apply changes; running drafts
  are not hot-reloaded. Corrupt entries are skipped, while a corrupt registry falls back to built-ins.
- **Small authoring SDK:** Python 3.10+ standard library, fluent word/reading/continuation helpers,
  Rust-backed validation and atomic no-overwrite output. Bundled examples cover English/Chinese
  outdoors and astronomy, Japanese rail travel, plus a Chinese gardening SDK example. The Linux
  packages include the SDK and example JSON under `/usr/share/suzaku/` (or `share/suzaku/` in tarballs).
- **Broader built-in fallback:** `digital`, `home` and `errands` add 72 explicit English forms
  (98 indexed additions), 237 Chinese readings, 64 contexts and 128 sentences per language.
  Totals: **6,102 English forms, 2,043 Chinese readings, 377 / 369 contexts and 718 / 736 sentences**.
  Topics include files/calls, household tasks, parcels, library loans, printing and lost property.
- **Linux test compatibility:** borrowed Python IBus payloads survive until C dispatch returns,
  accessibility observation avoids redundant per-snapshot round trips, and Compose fixtures are
  copied into private sessions. These fixes neither change the desktop keymap nor mask warnings.

Packs are a model-independent fallback, not executable plugins, unlimited sentence generation,
automatic learning, a complete Japanese analyzer or a remote marketplace. The first management
entry is the CLI; there is no settings-panel package list yet. Package validation is not signature
verification or a license audit. Authored/imported vocabulary persists locally, but input history
does not; settings backups exclude packs. Do not distribute personal records in a vocabulary pack.

Single packs are limited to 256 KiB, 8 layers and 2,048 indexing units. At most 16 packs may be
installed, with 4,096 enabled extension units per language and a 4 MiB registry. Conflicting contexts
or reading flags fail without replacing the previous registry. Exact duplicates are skipped.
Candidate/page limits, decoder windows, model budgets, cloud consent and memory-only preferences
are unchanged. Space continues writing; Enter or a candidate click submits.

## Validation and release gate

Implementation checks on the local Ubuntu 26.04 development machine passed **992 Rust tests,
0 failures and 27 opt-in skips**. Three additional negative boundary cases brought the package
suite to **15 passing tests**. Strict all-feature/all-target Clippy passed. Package-specific native
IBus checks passed in both default and inline modes, including EN/ZH/JA word/sentence candidates,
labels, numeric adoption, literal Space, exact commits and immutable snapshots after disk damage.
The complete default IBus regression also passed. The preceding errands expansion passed both
full native modes and all **54 real GTK vocabulary workflows** on owned displays.

The original 120/240-second native/application deadlines remain. Historical failures and fixture
corrections are retained in the vocabulary and packaging guides; they are not silently reclassified
as passes. Builds/checks are serial, with one Cargo job and task-owned memory-capped scopes.
These development results do not qualify Ubuntu 26.04 packages, every application, native Wayland
or actual model quality, and do not update the personal installation.

After synchronizing version metadata, the complete source suite passed **995 tests, 0 failures
and 27 opt-in skips**. Metadata/lockfile, formatting, Python/Bash checks, paired diagrams and all
242 source audit links passed; the staged change scan found no secrets. The unchanged third-party
lockfile and increasing platform build numbers were checked explicitly. Strict Clippy also passed
after the bump, together with all 27 editor-observer, Compose/diagnostic and C/Python lifetime checks.

Starting with this version, a tag alone is not a completed binary release. Publish the `.deb`,
binary `.tar.gz` and both SHA-256 files only after **this exact commit's** Ubuntu 24.04 CI,
package-content checks and clean-container installation/upgrade/removal checks pass. Artifacts
must identify the tagged commit and a clean source tree. CI download artifacts are intermediate;
the validated files must be attached to the GitHub Release. See the
[release gate](../linux-packaging-data.md#从-080-开始的发布要求) and the matching GitHub Actions run.

Rust/lockfile, macOS bundles and Android metadata use **0.8.0**. Bundle build numbers and Android
version code are **30**. Third-party dependencies are unchanged; no models or personal data are bundled.

## Install / upgrade

Download all matching files from the 0.8.0 GitHub Release and verify checksums before installation.
Finish or cancel the current draft and fully quit Suzaku, then on Ubuntu 24.04 amd64:

```bash
sha256sum -c suzaku_0.8.0_amd64.deb.sha256
sudo apt install ./suzaku_0.8.0_amd64.deb
/usr/bin/suzaku-panel
```

For a first installation, register the host explicitly as your desktop user, without sudo:
`/usr/bin/suzaku-tool linux-register install`. Installing a package alone does not activate input,
register/start the service or change the current input method. Upgrade host and panel together;
existing configuration and explicit cloud-consent rules remain. Keep original offline-pack JSON
files for recovery; removing the application does not delete the user's pack registry.

For a tarball, verify `suzaku-0.8.0-x86_64-unknown-linux-gnu.tar.gz.sha256`, extract it and verify
the included `SHA256SUMS`. Start `./bin/panel`; use `./bin/suzaku_tool` for management commands.
The tarball is not a static universal Linux build. Source/user-level installations require their
own rebuild/reinstall; pushing this release does not replace the currently installed personal host.

## Try an optional collection

```bash
suzaku-tool pack catalog --language en --topic outdoors
suzaku-tool pack export org.suzaku.en.outdoors ./en-outdoors.json
suzaku-tool pack install ./en-outdoors.json
suzaku-tool pack preview en "please bring your bino"
```

Preview is a fresh local process, not proof that the desktop host has reloaded. Fully restart host
and panel to use the pack in native input. See [pack lifecycle and SDK](../linux-packaging-data.md#离线词库包与制包-sdk),
[vocabulary contract](../../data/lexicons/README.md), [input](../ibus-candidates.md),
[limitations](../known-limitations.md), [privacy](../privacy.md) and [functional network](../functional-network.md).
