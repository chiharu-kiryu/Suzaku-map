# Suzaku 0.6.7 · Linux Alpha shortcuts and lossless Chinese drafts patch

For **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**. This remains an Alpha;
keep a fallback input method. Other platforms are not release-qualified.

This patch includes audit rounds 37–39 (N48/N49) and the first shortcut settings page.
Chinese and English remain the input priorities; Japanese and the existing interface/translation
languages are retained. Space continues the draft; Enter or a deliberate candidate click submits.

## Highlights

- **Context-local shortcuts:** a searchable Shortcuts settings page documents the existing keys
  and offers an optional home-row profile: Alt+J/K navigates candidates, Alt+H/L changes pages,
  and Alt+semicolon adopts a candidate without submitting. Standard keys remain the default.
  In the focused panel, F1 opens the reference and Ctrl+comma opens settings (Cmd+comma on macOS).
  The eight interface languages include the new controls. These are not global activation hotkeys.
- **Safe preference changes:** shortcut settings use acknowledged narrow host patches, conflict
  detection and failure rollback, and are included in configuration backups. Changing just the
  profile preserves the draft, current candidate, one-step undo, Compose and in-flight prediction.
  The aliases apply only to public, nonempty Linux IBus drafts with exact Alt modifiers, not to
  the independent panel editor, password fields, AltGr or unfinished Compose sequences.
- **N49 — One adoption per physical hold:** number choices, Shift+Enter (including the keypad)
  and Alt+semicolon no longer walk through newly generated candidates on key repeat. Immediate
  Backspace retains the original spelling. Release allows another adoption immediately, without
  time-based debounce; releasing Shift first cannot turn held adoption into an Enter submission.
  Navigation, ordinary text, Space, literal digits and deletion still repeat. Focus/reset/privacy
  boundaries clear old key state. Clients with zero keycodes retain discrete-event compatibility.
- **N48 — Lossless Chinese literal boundaries:** conversion preserves literal spacing, quotes and
  non-Pinyin Unicode case around adopted text. `你好  bei jing` becomes `你好  北京`, and
  `'nihao'` keeps its quotes as `'你好'`. Valid horizontal Pinyin separators still work; line/paragraph
  boundaries are not joined as syllables. Word/sentence continuations retain literal padding.
  This is not a larger dictionary, arbitrary mixed-language conversion or native multiline input.
- **Real keyboard coverage:** the private XTest → XKB → GTK → IBus gate now has 44 workflow groups,
  including holds, early modifier release, rapid separate taps, navigation repeat and key-up after
  moving between two real editor windows. Old drafts cannot be replayed through stale actions;
  fresh adoption and exact undo work in both windows. The three new audit reports ship in packages.

## Validation and compatibility

Local release checks against the 0.6.7 sources passed:

- Full-feature Rust tests: **862 passed, 0 failed, 27 ignored**. Opt-in native checks below
  cover additional cases; this does not mean every ignored test was run.
- Strict Clippy for all features/all targets and the GPU-only configuration, Rust formatting,
  and warning-as-error C bridge syntax checks.
- Native IBus checks with both default and inline preedit, **17** window/startup checks,
  and **3** settings-chain checks.
- **44** strict physical-keyboard workflow groups and **21** real-application lifecycle checks,
  using isolated desktop sessions and synthetic documents.
- Shell syntax/lint and Python syntax, version/build metadata, audit links, functional-network
  diagram parity, package audit entries and the rebuilt command-line version.

Binary package building/installation, the wider browser/Qt application matrix and live-model
quality checks were not repeated for this source release. Remote CI is separate from these results.

Earlier N49 testing recorded one failure while clearing/saving an owned synthetic editor document.
Subsequent complete runs, including three consecutive 38-group runs and the expanded 44-group gate,
did not reproduce it. Its cause is **not confirmed or claimed fixed**; strict content assertions and
failure diagnostics remain. See the [focus follow-up](../bug-audit-shortcut-focus-2026-09-24.md).

Routine checks use synthetic text, isolated configurations and mock model responses. Physical
keyboard hardware/LEDs, native Wayland, arbitrary remappers and all application shortcuts remain
unqualified. Local/cloud model capability and latency are unchanged; earlier CPU LLaMA default-budget
timeouts and translation semantic limitations remain. Eight UI languages are not eight native IMEs.

Rust/lockfile, macOS bundle and Android app metadata use **0.6.7**. Bundle build numbers and the
Android version code are **21**. Metadata alignment does not expand platform support.

## Install and upgrade

This is a source commit/tag, not an attached binary package or an installation update.
Once matching assets are available, verify `suzaku_0.6.7_amd64.deb` with
`sha256sum -c suzaku_0.6.7_amd64.deb.sha256`, fully quit Suzaku, then install using
`sudo apt install ./suzaku_0.6.7_amd64.deb`. Existing configuration is retained.

Old settings without `shortcut_profile` default to `standard`; the opt-in value is `home-row`.
Upgrade panel and host together: an older host rejects the new narrow shortcut patch safely.
Use the matching new tool to restore backups containing the new preference. This patch does not
download models, grant cloud consent, change desktop bindings or automatically rewrite user services.

Hosts registered before 0.6.5 still need explicit re-registration for the N43 retry policy. After
upgrading and fully quitting, run the matching new tool as the desktop user, without sudo:

```bash
/usr/bin/suzaku-tool linux-register install
/usr/bin/suzaku-tool linux-register verify
```

These are `.deb` paths; source/user installations should use their corresponding new tool.
See [Linux installation and data](../linux-packaging-data.md). Source checks do not imply remote CI
success or publication of downloadable assets.
