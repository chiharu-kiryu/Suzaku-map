# 0.8.5 Readable long sentence candidates

Suzaku Map 0.8.5 improves native-panel English/Chinese candidate previews for
continuous long drafts. The Linux / IBus Alpha targets Ubuntu 24.04 amd64 with
X11 or GNOME/XWayland. Keep your usual input method available as a fallback.

## Candidate display

- Long sentence candidates with the same already-typed opening now show a
  bounded preview of their differing tails instead of repeating that opening.
- Preview fitting uses the actual numbered card's width, height and text layout,
  including caret-following and bottom-dock layouts, different text sizes and
  later candidate pages. A narrower card can omit more verified shared text
  while retaining the complete changing tail and final printable ASCII token.
- Candidate payloads and absolute selection indices stay intact. Clicking a
  preview submits the full candidate, not its shortened display label; adoption,
  undo, draft continuity and model refresh behavior remain unchanged.
- Short/custom labels, Japanese and unrelated candidates retain their existing
  display. Unsafe boundaries, oversized tails or previews that cannot fit keep
  the prior label. This is not general Unicode word segmentation.

The local vocabularies, model-independent prediction protocol, model providers
and candidate ranking are unchanged from 0.8.4. No model is bundled or required.

## Checks and scope

Development checks cover 105 Rust testcase executions, including three private
native UI cases and a 252-scenario pure-layout matrix within the candidate
action test. They check exact changing tails, source indices, card hit regions,
unchanged full candidate text and exact-once clicks. Strict all-feature/all-target
Clippy and formatting pass. The layout matrix is not physical-window acceptance
on every screen size or with every selectable font.

After updating the version, the full all-feature Rust regression suite passes
1,341 testcase executions with zero failures and 29 dedicated skips; strict
all-target Clippy, formatting, version consistency and source scans pass.

Release assets must come from the exact clean tagged source commit and require
that commit's full CI, Linux package checks and clean Ubuntu 24.04
installation/upgrade/removal gate. A source tag or expiring CI artifact alone
does not complete publication. macOS/Windows
compile checks do not establish native input acceptance on those platforms.

Native Wayland, broader Japanese analysis, real-model quality/latency and the
intermittent upstream IBus daemon abort on newer local stacks remain outside
this patch's fixes. See [known limitations](../known-limitations.md).

## Install or upgrade

Download `suzaku_0.8.5_amd64.deb` and its `.sha256` from the matching
[GitHub Release](https://github.com/chiharu-kiryu/Suzaku-map/releases/tag/v0.8.5).
Finish or cancel any draft and fully quit Suzaku before upgrading.

```bash
sha256sum -c suzaku_0.8.5_amd64.deb.sha256
sudo apt install ./suzaku_0.8.5_amd64.deb
```

Installation alone does not activate an input method. On a first installation,
register as your desktop user, **without sudo**, then open the panel:

```bash
/usr/bin/suzaku-tool linux-register install
/usr/bin/suzaku-tool linux-register verify
/usr/bin/suzaku-panel
```

Use the tray to activate Suzaku or restore your previous input method. Restart
both the host and panel after upgrading; do not mix versions in one session.
Settings and offline-pack registrations are retained. The other two Release
assets, `suzaku-0.8.5-x86_64-unknown-linux-gnu.tar.gz` and its `.sha256`, are an
alternative, not a static universal binary. Verify the archive before unpacking
and its internal file checksums afterward:

```bash
sha256sum -c suzaku-0.8.5-x86_64-unknown-linux-gnu.tar.gz.sha256
tar -xzf suzaku-0.8.5-x86_64-unknown-linux-gnu.tar.gz
cd suzaku-0.8.5-x86_64-unknown-linux-gnu
sha256sum -c SHA256SUMS
```

Checksums verify integrity, not publisher signatures. See
[Linux installation and data](../linux-packaging-data.md) for dependencies,
tarball setup and safe removal.
