# Suzaku 0.6.8 · Linux Alpha bilingual candidate continuity patch

For **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**. This remains an Alpha;
keep a fallback input method. Other platforms are not release-qualified.

This patch includes audit rounds 40–44 (N50–N53) and stricter Linux application-test
synchronization. Chinese and English remain the priorities. Existing shortcuts, the Japanese
input plugin and the eight interface/translation languages remain available. Space continues
the draft; Enter or a deliberate candidate click submits.

## Highlights

- **N50 — English next words before Space:** a single word after a known complete word is
  classified consistently before and after a typed space. Sentence-only model replies can also
  supply the next-word choice, keeping the full sentence separately selectable. Text is taken
  directly from the returned prefix; unknown spellings, URLs and identifiers are not invented
  into word completions. No additional model request or automatic submission is introduced.
- **N51 — Pinyin tone digits at punctuation:** optional tone numbers no longer leak into
  converted text before sentence punctuation or closing delimiters. `ni3hao3，shi4jie4！`
  becomes `你好，世界！`. Decimals, time, grouped numbers and fractions remain literal.
  Number keys still adopt candidates; Alt+digits still enter literal digits.
- **N52 — Exact model prefixes:** known local CJK conversions retain indentation, repeated
  spaces and Unicode horizontal spacing through provider validation and candidate merging.
  Correct long replies retain their prefix-based length allowance. Built-in HTTP providers
  reject replies that lose the prefix; they do not silently reconstruct missing text.
  Unconverted phonetic input and custom-provider interfaces retain their existing behavior.
- **N53 — Long Chinese draft continuation:** the decoder no longer exhausts a fixed 128-round
  search before reaching Pinyin after a long adopted prefix, or before collecting an exact
  conversion. Search rounds follow the already bounded input; the 256-code-point input limit,
  beam width, dictionary and candidate limits do not increase. Shortening an over-limit draft
  restores conversion. Exact spelling undo and continued typing remain available.
- **Stricter real-editor checks:** the 0.6.7 CI saved-document failure prompted an owned-buffer
  and save-completion observer. Test editors use disposable preferences to keep background
  draft saving out of the unchanged test deadline. Each verification still sends only one
  Ctrl+S and checks both the real buffer and saved bytes. Personal editor settings and Suzaku's
  input routing are unchanged. Fourteen deterministic checks and a two-editor gate are in CI.

## Validation and compatibility

Local release checks against the 0.6.8 sources passed:

- Full-feature Rust tests: **871 passed, 0 failed, 27 ignored**. The opt-in native checks
  below cover additional cases, not every ignored test.
- Strict Clippy for all features/all targets and the GPU-only configuration, Rust formatting,
  and warning-as-error syntax checks for the Linux C bridges.
- Native IBus checks with both default and inline preedit, including next-word, tone-boundary,
  exact model-prefix and long-draft adoption/undo/continuation checks; **17** window/startup checks.
- **14** deterministic editor-observer checks, the **2-editor** observation gate, **11** real GTK
  workflow groups and **46** stock candidate-popup checks, including **17** ordinal-glyph checks.
  These ran on isolated desktop sessions with synthetic documents.
- Shell syntax/lint, syntax for **17** Python files, CI/issue-template YAML, all version/build
  metadata and the rebuilt command-line version. Dependency lock entries are unchanged.
- **199** source-tree audit links resolve, all **44** audit reports are in the packaging manifest,
  and the standalone/embedded functional-network diagrams match.

Binary package building/installation, the wider browser/Qt application matrix, the separate
physical-keyboard/lifecycle gates and live-model quality checks were not repeated for this source
release. Earlier audit runs remain documented separately. Remote CI is separate from these results.

The 0.6.7 remote CI failure remains a historical failure; this patch does not retroactively
turn it green. The editor-observation change addresses reproduced test synchronization
problems, not all possible application or desktop timing issues.

Routine checks use synthetic text, isolated configurations and controlled model fixtures.
The offline lexicons are still small, not general Chinese/English language-quality benchmarks.
The patch does not qualify arbitrary mixed-language or long-sentence conversion, native Wayland,
hardware keyboard LEDs, arbitrary remappers or real-model semantics/latency. Japanese offline
segmentation is unchanged. Native replacement still rejects control characters; core newline
tests do not add native multiline editing.

Rust/lockfile, macOS bundle and Android app metadata use **0.6.8**. Bundle build numbers and
the Android version code are **22**. Metadata alignment does not expand platform support.

## Install and upgrade

This is a source commit/tag, not an attached binary package or an installation update.
Once matching assets are available, verify `suzaku_0.6.8_amd64.deb` with
`sha256sum -c suzaku_0.6.8_amd64.deb.sha256`, fully quit Suzaku, then install using
`sudo apt install ./suzaku_0.6.8_amd64.deb`. Existing configuration is retained.

Upgrade panel and host together. No setting migration, automatic service registration, model
download, cloud consent change or desktop keyboard remapping is added. Existing shortcut
preferences are retained; absent preferences still use the standard profile.

Hosts registered before 0.6.5 still need explicit re-registration for the N43 retry policy.
After upgrading and fully quitting, run the matching new tool as the desktop user, without sudo:

```bash
/usr/bin/suzaku-tool linux-register install
/usr/bin/suzaku-tool linux-register verify
```

These are `.deb` paths; source/user installations should use their corresponding new tool.
See [Linux installation and data](../linux-packaging-data.md). Source checks do not imply
remote CI success or publication of downloadable assets.
