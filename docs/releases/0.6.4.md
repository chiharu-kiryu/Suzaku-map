# Suzaku 0.6.4 · Linux Alpha build and test maintenance patch

For **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**. This remains an Alpha;
keep a fallback input method. Other platforms are not release-qualified.

This maintenance patch reduces development-cache growth and fixes temporary settings left by
theme tests. Input rules, candidate payloads, model behavior and release build settings are
unchanged. The [0.6.3 popup fixes](0.6.3.md) remain included.

## Highlights

- **Smaller development/test builds:** both profiles default to `debug = 0` and
  `incremental = false`, matching CI. Dependency caching, debug assertions and overflow checks
  remain enabled. This saves cache space but can make subsequent edits slower to compile;
  it is not a runtime-memory or distributable-size claim.
- **Explicit debugging opt-in:** `CARGO_PROFILE_DEV_DEBUG=2` or `CARGO_PROFILE_TEST_DEBUG=2`
  restores debugger information for the corresponding profile. `CARGO_INCREMENTAL=1` opts
  back into larger incremental caches. Release optimization settings are not changed.
- **Owned test-fixture cleanup:** theme-setting tests keep a guard for each newly created
  temporary directory and remove it on drop, including during unwinding. The guard is acquired
  only after exclusive directory creation, and tests verify settings stay inside that directory.
  A regression checks that dropping the fixture removes it.
- **Cache hygiene:** Kotlin's project-local cache is ignored. The
  [contribution guide](../../CONTRIBUTING.md#keeping-local-disk-use-bounded) explains scoped Rust
  cleanup, rebuildable Android outputs and which dependencies/configuration must be preserved.

The one-off local cleanup that preceded this patch is **not** an application feature or an
installer action. Startup and upgrades do not delete user files, global caches, models or SDKs.
Rebuilding and testing will still create useful local caches; this is not a fixed disk-use limit.

## Validation and compatibility

- All-feature tests: **827 passed, 0 failed, 24 opt-in tests skipped** by the ordinary command.
  Skipped tests are not counted as passed. The new fixture-cleanup regression passes, and no
  theme-setting temporary directories remain after the suite.
- Strict Clippy passes for both all-feature and GPU-only targets with `-D warnings`.
- The complete private native IBus chain passes in the default candidate-area mode, including
  English/Chinese/Japanese input, exact commits, controlled model timing and host restart.
- **8 real GTK application workflow groups** pass, including continuous drafting, candidate
  adoption/undo, focus and password boundaries, and the no-focus companion.
- Formatting, whitespace, version metadata, source documentation links and functional-graph
  parity pass. The rebuilt tool reports 0.6.4; no incremental artifacts are created by the
  default build/test configuration. Staged secret scanning found no leaks.

These checks were rerun with the **0.6.4** metadata. No new distribution package or installation
was produced during this source-release validation.

Native checks use owned private D-Bus/IBus/Xvfb sessions and synthetic fields. Controlled model
fixtures only use loopback; no personal desktop input, real model or microphone is involved.
The broader popup, Chrome/Qt, lifecycle and UI acceptance recorded in 0.6.3 remains historical
coverage, not a claim that every one of those suites was rerun for this maintenance patch.

Rust/lockfile, macOS bundle and Android app metadata all use **0.6.4**. The bundle build number
and Android version code are **18**. Metadata alignment does not expand platform support.

## Install and upgrade

This source patch is not an attached binary package. Once matching assets are available, verify
`suzaku_0.6.4_amd64.deb` with `sha256sum -c suzaku_0.6.4_amd64.deb.sha256`, fully quit Suzaku,
then install using `sudo apt install ./suzaku_0.6.4_amd64.deb`. Existing configuration is retained.
See [Linux packaging/data](../linux-packaging-data.md) for source builds and package validation.

Preparing this patch does not install or rebuild distribution packages, run container upgrade/
removal checks, publish assets or imply that remote CI has run. It adds no data migration,
model download, cloud authorization or automatic disk cleanup.

See [input rules](../ibus-candidates.md), [limitations](../known-limitations.md),
[privacy](../privacy.md) and the [functional network](../functional-network.md).
