# Suzaku 0.6.1 · Linux Alpha input-target reliability release

For **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**. This remains an Alpha;
keep a fallback input method. Other platforms are not release-qualified.

This patch collects functional-network fixes **N33–N37** after 0.6.0. It protects new drafts
from delayed old input while preserving continuous writing and acknowledged companion actions.

## Highlights

- **Privacy and input-purpose boundaries (N33/N34):** independent-panel direct text sends are
  rejected in PRIVATE fields, while native local conversion remains available. A change between
  public, private and bypass input invalidates old sends and keyboard targets, even when a brief
  round trip is hidden by coalesced snapshots. Ordinary hints and stale engine events do not
  disrupt the active field; password/PIN/numeric bypass behavior remains unchanged.
- **Language changes (N35):** a successful change through language selection or configuration
  reload retires the previous target. Delayed sends cannot clear a new-language draft; changing
  away and back does not revive old keys or presses. Same-language aliases, provider-only reloads
  and failed changes keep their existing target and behavior.
- **Whole-draft cancellation (N36):** Esc cancellation and the focused engine's Reset revoke old
  pending work before publishing the empty draft. Compose-only cancellation, ordinary deletion,
  application shortcuts and confirmed companion edits still allow normal continuous input.
- **External commits (N37):** successful physical Enter/keypad Enter, native candidate clicks and
  independent direct sends retire old work so late text cannot overwrite the next draft. A
  revision-bound companion commit retains its acknowledgement-based follow-up typing. Empty or
  rejected commits, Space, number-based adoption and Shift+Enter do not create this boundary.

Target retirement does not clear the current field's exact candidate-commit history. Late model
replies cannot restore canceled/committed candidates; new predictions remain available. No protocol
format, dictionary, model consent or surrounding-text access is added. Independent direct sends
are not newly added to the host's model-context history.

## Validation and compatibility

- Feature-enabled regression suite: **825 passed, 0 failed, 24 opt-in tests skipped** by the ordinary
  command. Skipped tests are not counted as passed.
- Private runners passed **16 panel UI groups and 1 executable-startup group**, **3 settings groups**,
  and the complete native IBus chain. These checks were rerun with the 0.6.1 metadata.
- Strict Clippy passed for both `--all-features --all-targets` and `--features gpu --all-targets`
  with `-D warnings`. Formatting, whitespace, native-fixture syntax and the modified packaging
  script's ShellCheck passed.
- Rust/lockfile, macOS and Android version metadata agree. The two functional graph sources agree;
  all **64 audit-document links** checked in the source tree resolve. Reports are included in the
  explicit Linux documentation package list; this is not a built-package validation.
- Staged secret scanning found no leaks.

New coverage comprises **388 native/controlled-model scenarios** and **52 panel timing scenarios**:
117 input-type cases, 96 language cases, 71 cancellation cases and 104 commit cases; panel checks
cover 20 language round trips, 20 cancellation sequences and 12 keyboard-flight/commit sequences.
These scenarios run inside existing private test groups, not as additional top-level Rust tests.
Native commit checks wait for the actual D-Bus CommitText signal, rather than assuming that a
Unix-socket response means the other transport's signal has already arrived.

Panel/settings tests use private Xvfb/D-Bus, synthetic frames and action queues; IBus tests use a
private native host and engine objects/input contexts. Model tests use owned loopback fixtures.
None operates the development desktop's input method, a real microphone or model account. These
checks do not establish full GNOME/Wayland, arbitrary-application or other-platform acceptance.

Rust, macOS bundle and Android app metadata all use **0.6.1**; the bundle build number and Android
version code are **15**. This aligns metadata without expanding native-platform support.

## Install and upgrade

This source release is not an attached binary package. Once matching release assets are available,
verify `suzaku_0.6.1_amd64.deb` with `sha256sum -c suzaku_0.6.1_amd64.deb.sha256`, fully quit Suzaku,
then install using `sudo apt install ./suzaku_0.6.1_amd64.deb`. Existing configuration is retained.
See [Linux packaging/data](../linux-packaging-data.md) for source builds and package validation.
No package is installed as part of preparing this release. Fresh distributable packaging and
container installation/upgrade/removal are not rerun for this source commit; local checks do not
imply remote CI has run or release assets exist.

Linux speech remains a simulated bridge, handwriting and offline CJK dictionaries remain limited,
and input/recovery drafts are still in memory. This release adds no migration, model download or
cloud consent. Spaces and candidate adoption remain editable; Enter/candidate-click submission
rules are unchanged.
