# Suzaku 0.7.3 · Vocabulary resources and in-memory candidate preferences

For **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**. This remains an Alpha;
keep a fallback input method. Other platforms are not newly release-qualified.

## Highlights

- **More everyday English and Chinese vocabulary:** two authored expansions bring
  the deduplicated English index to **5,251 forms**, Chinese to **1,143 readings**,
  and English/Chinese sentence examples to **238 / 256**. These are bounded word
  forms and curated examples, not unique lemmas or a general language-quality score.
  New examples cover everyday writing, errands, travel, handovers and office work.
- **Vocabulary is data, not decoder implementation:** English, Simplified Chinese
  and Japanese resources now use a validated, versioned JSON contract. Algorithms,
  phonetic conversion, indexing and ranking stay separate from vocabulary and model
  providers. Built-ins are embedded and cached per language; no input-path file or
  network reads, runtime dictionary import or hot reload are introduced. The migration
  preserves existing resource order, homophones and base ranks.
- **Learn confirmed candidate preferences in memory:** repeated word/sentence choices
  can move existing IBus candidates forward. Keys are salted fingerprints scoped to
  language, exact normalized query and candidate. At most **2,048 entries** are retained;
  effective frequency is capped at eight selections and halves every 24 hours.
  The cache does not generate text, alter the dictionary or depend on a specific model.
- **Editable adoption is not submission:** number keys, Shift+Enter, selected Space
  and companion adoption stage feedback. Only choices retained in the finally submitted
  text are learned. Undo, cancellation, focus/privacy/language boundaries and edits that
  replace the adopted word discard pending feedback. Identifier suffixes such as
  `hello2` / `hello_name` and combining-mark edits do not reinforce the old `hello` word.
- **Stable mixed candidates:** English keeps its literal first row; CJK can learn a
  preferred word conversion. Word/sentence quotas remain, displayed weights stay within
  0–100, explicit selections stay frozen, and asynchronous model refreshes never stack
  bonuses or displace the current typing anchors. Weights are not probabilities.
- **Clear from the tray:** the localized **Clear candidate preferences (memory only)**
  action removes both confirmed and pending feedback without changing the live selection,
  Compose or adoption undo. The next candidate rebuild uses defaults. Private fields
  neither learn nor use preferences; restarting the host forgets them.
- **Repeatable application QA:** the new GTK vocabulary suite exercises physical
  English/Pinyin spelling, word/sentence adoption, exact undo, continuation and saved
  application text in 12 workflows. It now runs in CI alongside the existing gates.

No preference file, input history, model installation or background persistence worker is
added. Fingerprints are not encryption or an anonymity guarantee. Other hosts and the
independent panel retain their existing candidate policy; preferences apply to the IBus
engine and its companion. Declared privacy is still required: visually masked but unhinted
fields are not automatically private. See [privacy](../privacy.md).

## Validation and limits

Before the metadata-only version bump, the final implementation passed **950 Rust tests,
0 failures, 27 opt-in skips**, strict all-feature/all-target Clippy, both complete private
IBus modes, and the isolated panel candidate-action/follow-up typing gate. Both IBus modes
include frequency learning, native/companion adoption, undo, privacy, focus, clear and
English identifier-boundary checks. The new word-boundary regression first failed for
`hello2`, then passed after the implementation fix; the failure log is retained.

Earlier vocabulary-only installation checks passed **141 isolated installed-app groups**
and **five owned GNOME desktop workflows**. Those installed programs predate the resource
refactor and preference cache; they are not full 0.7.3 installation acceptance. A source
release does not upgrade the running application. See the [staged validation record](../ibus-candidates.md).

After the version bump, **950 Rust tests passed with 0 failures and 27 opt-in skips**;
formatting, strict all-feature/all-target Clippy and all **12 real GTK vocabulary
workflows** also passed. Version metadata and both macOS plists were checked, the CI
workflow parsed, the changed shell/Python test scripts passed syntax checks, the paired
functional diagrams matched, and all **223 packaged audit links** resolved. Third-party
lockfile package versions were checked against the previous release and are unchanged.

All four Linux release binaries built successfully. Local `.tar.gz` and `.deb` packages
passed checksum, manifest, binary-version, launcher, content and non-installing CLI smoke
checks, including **207 links inside the packaged documentation**. These are worktree QA
artifacts, not published assets or clean-container installation acceptance; the existing
desktop installation was not upgraded for this release check.

Local compilation and native tests run serially with one Cargo job in task-owned user
scopes using `MemoryHigh=2G`, `MemoryMax=3G`, `MemorySwapMax=0`. No unrelated processes or
desktop-wide limits are changed. Local checks, remote CI and installation acceptance
remain separate; native Wayland, arbitrary applications and real-model quality are not
newly qualified by this release.

Rust/lockfile, macOS bundle versions and Android metadata use **0.7.3**. Bundle build
numbers and the Android version code are **27**. Serde is now a direct dependency for
resource validation, using the already locked version; third-party dependency versions
are unchanged. A source commit/tag does not attach downloadable GitHub Release assets.

## Install and upgrade

Once matching assets are available, verify `suzaku_0.7.3_amd64.deb` with
`sha256sum -c suzaku_0.7.3_amd64.deb.sha256`, finish/cancel the draft, fully quit Suzaku,
then use `sudo apt install ./suzaku_0.7.3_amd64.deb`. Upgrade **panel and host together**
before using the new companion adoption and tray cache-clear commands. Existing settings
and cloud-consent rules are retained. Source/user installations likewise need matching
binaries; embedded vocabulary changes require rebuilding and reinstalling.

Hosts registered before 0.6.5 still need explicit re-registration for the service retry
policy; see [Linux installation/data](../linux-packaging-data.md).
