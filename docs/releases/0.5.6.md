# Suzaku 0.5.6 · Linux Alpha input fixes

For **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**. This remains an Alpha;
keep a fallback input method. Other platforms are not release-qualified.

## Highlights

- Better English word and sentence completion: longer phrase context takes priority, common
  writing/collaboration phrases are expanded, and straight/curly apostrophes retain typed spelling.
  Sentence-only model replies can also supply a distinct word candidate without losing the prefix.
- Linux dead-key/Compose sequences now produce editable accents and symbols using the system
  locale/XCompose table. Cancellation, modifiers, field switches and privacy boundaries are covered
  by isolated native tests; keyboard layout and Caps Lock settings are not changed.
- Switching a standalone panel's model/provider or language clears old prediction context.
  Model continuations of long drafts are no longer rejected solely because the full replacement
  exceeds 160 characters; generated additions remain bounded.
- Whitespace-only drafts can be submitted exactly. Coalesced native snapshots and reordered
  acknowledgements no longer leave screen-keyboard edits waiting indefinitely: uncertain edits
  retain a recovery draft and are never automatically replayed.
- Strict Clippy checks now pass and run in Linux CI. The documented functional network enumerates
  56 routes, with the first four audited bugs fixed and covered by regressions.

The English quality fixtures are project-authored regression cases, not an independent benchmark
or a claim of general language accuracy. Model work remains optional and provider-independent.

## Validation and compatibility

- Local feature-enabled regression suite: **791 passed, 0 failed, 11 opt-in tests skipped**.
  The private IBus runner and all **9 isolated UI groups** passed separately.
- Strict Clippy passes with `--all-features --all-targets` and `--features gpu --all-targets`,
  using `-D warnings`; formatting and whitespace checks pass.
- Linux release binaries and local `.deb`/`.tar.gz` contents, checksums, versioned documentation
  and non-installing launcher smoke checks pass. Clean-container installation/upgrade checks
  remain part of CI; no package was installed on the development desktop for this release.
- The three exported string-release functions now require `unsafe` when called from Rust.
  C symbols/ABI are unchanged. Callers must transfer exclusive ownership of a live, unchanged
  `CString::into_raw` allocation from the library's allocator, or pass null, and free it only once.
- Linux package metadata follows 0.5.6; macOS bundle and Android app versions also match
  (build number/version code 10). This does not expand native platform acceptance.

## Install and upgrade

A source tag is not an attached binary package. Once matching release assets are available,
verify `suzaku_0.5.6_amd64.deb` using
`sha256sum -c suzaku_0.5.6_amd64.deb.sha256`, fully quit Suzaku, then install with
`sudo apt install ./suzaku_0.5.6_amd64.deb`. Existing configuration is retained.
Source builds and CI package artifacts are alternatives; see [Linux packaging/data](../linux-packaging-data.md).
Installation itself does not activate/register the input method, download models or migrate drafts.

Default no-GPU builds, arbitrary Compose tables, native Wayland, broad app compatibility,
real-model quality and non-Linux native behavior remain outside this validation.
Linux speech is simulated; Chinese/Japanese dictionaries are small; drafts are in memory.
Cloud suggestions still require explicit consent.
