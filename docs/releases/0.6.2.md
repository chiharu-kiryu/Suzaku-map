# Suzaku 0.6.2 · Linux Alpha cross-application input reliability patch

For **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**. This remains an Alpha;
keep a fallback input method. Other platforms are not release-qualified.

This patch collects functional-network fixes **N38–N40**, real-application regressions and
long-draft boundary coverage after 0.6.1. **Unconfirmed text now appears in the candidate area
and companion panel by default**, not inside the target application's inline preedit buffer.

## Highlights

- **Synchronous preedit cleanup (N38):** inline mode sends an empty, invisible preedit update
  when a draft ends. IBus 1.5.29 synchronous clients understand this where a hide-only event
  could leave stale text after commit, cancellation or focus changes.
- **Explicit submission across applications (N39):** default drafts stay in the engine and
  candidate-area auxiliary line. Tested Chrome/Qt fields no longer commit cached preedit when
  focus changes. Cancelling a replacement preserves the application's original selection.
  Long previews show the last 160 Unicode code points without truncating the draft or commit.
- **Literal numbers without a draft (N40):** ordinary/keypad digits go directly to the app when
  there is nothing to select, so `2026` and `12.5` do not start candidates or lose digits.
  Inside an active draft, 1–6 still adopts candidates; Alt+digits explicitly enters literal
  draft digits. Spaces and punctuation still continue writing; Enter/candidate clicks submit.
- **Boundary coverage:** new Unicode/Compose/length tests verify exact commits, companion
  mirror limits, late model-result rejection and resumed predictions after shortening a draft.
  These tests preserve existing limits rather than expanding them.

Advanced users can start the host with `SUZAKU_IBUS_INLINE_PREEDIT=1` to restore inline preedit.
**That option also restores the risk of client-initiated confirmation on focus changes.** It is
not the default and does not have the default mode's focus-cancellation guarantee.

Passing empty-draft digits through does not repair missing application input-purpose hints.
Unreported numeric or visually masked fields are still ordinary fields: letters, Alt+digits and
panel input may create public drafts. This patch does not classify them as private, read their
surrounding text or change model consent. Use a trusted alternative for sensitive input.

## Validation and compatibility

- Feature-enabled regression suite: **826 passed, 0 failed, 24 opt-in tests skipped** by the
  ordinary command. Skipped tests are not counted as passed.
- Complete private native IBus tests pass in both default candidate-area and opt-in inline modes,
  including English/Chinese/Japanese, synchronous cleanup, exact long commits, controlled model
  timing, privacy, target boundaries, candidate continuity and host restart.
- Real-application tests pass **115 workflow groups** across Chrome 153.0.8010.52 and Qt 5.15.13 /
  6.4.2 (Qt synchronous and asynchronous modes), plus **8 GTK groups** using Text Editor/Zenity.
  Focus cancellation and numeric input are strict assertions, not accepted known failures.
- Isolated UI runners pass **16 panel groups and 1 executable-startup group**.
- Strict Clippy passes for both `--all-features --all-targets` and `--features gpu --all-targets`
  with `-D warnings`; formatting, whitespace, script syntax and ShellCheck pass.
- Rust/lockfile, macOS and Android metadata agree. All **85 audit-document links** resolve in the source tree and
  the two functional graph sources agree. Reports are in the explicit Linux packaging list;
  source-link checks are not built-package validation.
- Staged secret scanning found no leaks.

The regression suite, both native draft modes, application/UI runners and strict Clippy checks
above were rerun with the 0.6.2 metadata.

Application tests use owned Xvfb/D-Bus sessions, synthetic fields and a temporary Chrome profile;
model tests only use owned loopback fixtures. No personal desktop input, browser profile, real
model or microphone is used. CI now includes GTK/Qt workflows and both native draft modes;
Chrome testing is local, not a remote CI gate. These checks do not qualify Firefox/Electron,
native Wayland, every web editor or every masked widget.

Rust, macOS bundle and Android app metadata all use **0.6.2**; the bundle build number and Android
version code are **16**. Metadata alignment does not expand native-platform support.

## Install and upgrade

This source release is not an attached binary package. Once matching release assets are available,
verify `suzaku_0.6.2_amd64.deb` with `sha256sum -c suzaku_0.6.2_amd64.deb.sha256`, fully quit Suzaku,
then install using `sudo apt install ./suzaku_0.6.2_amd64.deb`. Existing configuration is retained.
See [Linux packaging/data](../linux-packaging-data.md) for source builds and package validation.
No package is installed as part of preparing this patch. Fresh 0.6.2 packaging and container
installation/upgrade/removal are not rerun for this source commit; local validation does not imply
remote CI has run or release assets exist.

Linux speech remains a simulated bridge; handwriting and offline CJK dictionaries remain limited.
Drafts stay in memory and can be lost on cancellation, focus change, exit or crash. This patch
adds no data migration, model download or cloud authorization.
