# Suzaku 0.8.3 · Model-independent prediction and multilingual input polish

Release target: **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**. Suzaku
remains an Alpha; keep another input method available. Chinese and English
remain the core, with gradual, bounded Japanese support. Other platforms are
not newly release-qualified by this version number.

## Highlights

- **Model-independent prediction protocol v1:** versioned requests/responses,
  caller-owned request IDs, typed word/sentence candidates, explicit complete-draft
  replacement semantics, bounded output and cooperative cancellation. Both the
  standalone panel and Linux host use the contract; existing completion providers
  retain a compatibility adapter. Model names, credentials, endpoints and UI
  annotations stay outside the protocol. Existing HTTP services retain their
  transport format, consent rules and budgets; translation remains separate.
  The legacy adapter also preserves English indentation for resolved aliases
  such as `en-US` and `en_GB`, not just the canonical `en` language ID.
- **Safer candidate adoption:** shared worker validation rejects dropped English
  prefixes/indentation, unchanged drafts and generated request-field echoes
  before display limits. Bad semantic rows do not hide valid siblings. Missing
  fallback vocabulary alone does not reject model suggestions; CJK conversion
  and alternative homophones remain allowed. Failures retain immediate local
  candidates, and stale results cannot replace newer drafts.
- **English word and sentence continuity:** model sentences with extra horizontal
  whitespace still yield separate word choices without normalizing their payload.
  Brackets/quotes embedded inside paths and identifiers no longer fabricate normal
  phrase context. Normal wrappers, adopted text, explicit commit and undo remain.
- **Chinese partial Pinyin:** word/sentence completions survive trailing spaces
  after unfinished readings and adopted Han text. Preserve literal spacing,
  long frozen prefixes, internal reading boundaries and required separators.
- **Japanese input boundaries:** allow Hiragana to start a native IBus draft in
  Japanese mode, retain unfinished Romaji choices after horizontal separators,
  preserve recognized mixed-script words such as `同じ` during continued typing,
  and keep authored continuations reachable on the first page. Unknown text,
  line boundaries, literal choices and prior homophone order remain protected.
- **Daily comparisons and choices:** each language gains 24 contexts and
  48 authored sentences; Chinese adds 65 readings and Japanese adds 48 readings.
  Totals: **English 6,127 indexed forms / 521 contexts / 1,006 sentences;
  Chinese 2,432 readings / 515 contexts / 1,028 continuations;
  Japanese 122 readings / 62 contexts / 123 continuation records**.

Vocabulary remains independent JSON and a fallback when models are unavailable,
not open-ended generation. All eleven optional data-only collections remain
opt-in and unchanged. No model or personal input history is bundled. Restart
both panel and host after pack changes; there is no live reload or executable
plugin loading. Space still continues writing; only explicit submission commits.

## Validation and release gate

Before release metadata, the final development snapshot passed **1,226
all-feature Rust tests**, with zero failures and **27 opt-in/fixture tests
ignored**, strict all-target Clippy, formatting and 21 tensor-validator tests.
The new protocol uses controlled providers and loopback HTTP fixtures; these
results do not establish real-model quality or latency.

After synchronizing 0.8.3 metadata and the legacy language-alias fix, the same
1,226 Rust tests and strict Clippy pass again. Formatting, source-digest,
21 tensor checks, six signal-lifetime checks, 23 private diagnostic checks,
shell/Python syntax, metadata consistency and full-history/staged secret scans
also pass. Local ShellCheck is unavailable; its required CI step is unchanged.
Rust, macOS and Android metadata use 0.8.3, with platform build number 33;
third-party locked dependencies are unchanged.

Earlier focused private IBus checks passed Japanese boundaries in both preedit
modes and all 102 bilingual workflows in both modes. The subsequent protocol
changes still require the exact release commit's complete native CI gates.
These earlier results are not a final-snapshot GTK, physical-keyboard or
personal-desktop acceptance. Original failures remain in the
[development record](../../DEVELOPMENT.md); maturity scores are unchanged.

At release preparation, **exact-commit CI and package acceptance are pending**.
Publish `.deb`, binary `.tar.gz` and both SHA-256 files only after the same
clean tagged commit passes full Ubuntu 24.04 CI, package-content checks and
clean-container installation/upgrade/removal. A source tag or expiring artifact
alone does not complete a release; see the [Linux release gate](../linux-packaging-data.md).

The [first 0.8.3 CI](https://github.com/chiharu-kiryu/Suzaku-map/actions/runs/37462265391)
passed Rust, Clippy, formatting, secret scanning and desktop compile checks,
but the full native IBus session reached its 120-second limit (exit 124).
No package was generated or published. The subsequent development fix removes
discarded whole-draft decoding and redundant gated-fixture delay without changing
timeouts or assertions; see the 2026-10-07 [development record](../../DEVELOPMENT.md).
That work does not relabel the failed run as successful or move the v0.8.3 tag.

The intermittent local IBus daemon abort investigated on Ubuntu 26.04 /
IBus 1.5.34-rc2 / GLib 2.88 remains **unresolved and deferred**, not fixed.
There is no new streaming prediction, model installation, broader text
collection, full Japanese morphology or expanded Japanese long-draft window.
Native Wayland, arbitrary multi-monitor/DPI and other desktop environments are
not newly validated. See [known limitations](../known-limitations.md).

## Install / upgrade

After approved 0.8.3 assets appear on the GitHub Release, finish or cancel the
current draft, fully quit Suzaku, and verify/install on Ubuntu 24.04 amd64:

```bash
sha256sum -c suzaku_0.8.3_amd64.deb.sha256
sudo apt install ./suzaku_0.8.3_amd64.deb
/usr/bin/suzaku-panel
```

For first installation, explicitly register as your desktop user, **without
sudo**: `/usr/bin/suzaku-tool linux-register install`. Package installation alone
does not activate input or register/start a user service. Upgrade host and panel
together; configuration, cloud consent and user pack data remain. Keep original
pack JSON files for recovery.

For the tarball, verify `suzaku-0.8.3-x86_64-unknown-linux-gnu.tar.gz.sha256` and
the extracted `SHA256SUMS`, then run `./bin/panel`. It is not a universal static
Linux binary. Source/user-level installations need their own rebuild/reinstall;
publishing this release does not update the personal desktop installation.
See [installation and data](../linux-packaging-data.md),
[input behavior](../ibus-candidates.md) and [privacy](../privacy.md).
