# Suzaku 0.8.2 · Adaptive panels and continuous multilingual fallback

Release target: **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**. Suzaku remains
an Alpha; keep another input method available. Chinese and English remain the
core, with a bounded everyday Japanese expansion. Other platforms are not newly
release-qualified by this version number.

## Highlights

- **Panel layout and placement:** choose Auto, Follow caret or Bottom dock in
  Appearance settings. Auto conservatively prefers caret following on desktops
  and the bottom layout for explicitly identified mobile sessions/devices.
  Bottom dock offers larger keyboard controls and candidates above the keyboard;
  it is an overlay, not a system-reserved keyboard area. Settings retain the
  detected choice and explicit overrides.
- **Reachable, consistent candidates:** native pages display all six slots, with
  visible paging controls and caret-relative placement. Keyboard and panel page
  changes agree on the next page's first row; attempts beyond either end are
  inert. Numbered native cards submit their full text with one click, including
  long labels. Zero/nonfinite wheel and pinch deltas no longer trigger unwanted
  paging, scaling or settings scrolling.
- **More reliable continuous input:** fix the exact 256-scalar local-window
  boundary without enlarging decoder/model budgets. English word and sentence
  completion works after em dashes and Chinese prose punctuation while retaining
  the preceding text and protecting technical tokens. Preference learning now
  distinguishes continued words/domains from completed choices. Pinyin tone
  digits before aside punctuation and em dashes retain the intended conversion.
- **Everyday bilingual vocabulary:** append clarification, coordination, social
  replies, belongings, borrowing, quantities and sizes. Since 0.8.1, each language
  gains 72 contexts and 144 authored sentences; Chinese adds 192 readings.
  Totals are **6,124 English indexed forms / 497 contexts / 958 sentences** and
  **2,367 Chinese readings / 491 contexts / 980 continuations**. Older ranks and
  homophone order remain protected; shipped optional collections are unchanged.
- **Gradual Japanese support:** add 48 readings and 48 continuations, reaching
  **74 readings / 38 contexts / 75 continuation records**. Improve `nn` boundaries,
  `n’`, `jya/jyu/jyo`, suffix homophones and continuation after known Katakana
  spellings. Authored sentences remain available after progress such as `予定ga`,
  `nihongo wo` and `JYUNBI GADEKI`. Unknown prefixes/conflicting tails are not
  discarded, and line boundaries are preserved. The same behavior works with
  the optional rail pack; this is not full Japanese morphological analysis or
  arbitrary sentence-level Romaji-to-Kanji conversion.
- **Safer data and better diagnostics:** reject duplicate registry fields without
  overwriting corrupt data; enforce native payload limits on actual candidates,
  retaining literal input and commit-index agreement. Recovery fixtures preserve
  daemon diagnostics and the first failure through asynchronous cleanup. These
  diagnostics are test infrastructure, not new input telemetry.
- **Inspectable capability inventory:** add a validated architecture/function/
  implementation/maturity dataset covering 10 architecture domains, 68 functions,
  47 implementation slices and 77 relationships. Implementation, regression,
  real-environment acceptance and delivery evidence remain separate; unknown
  scores are not represented as successful acceptance.

Vocabulary remains model-independent JSON and a fallback when generation is
disabled, unavailable, failed or empty—not a replacement for open-ended model
generation. Eleven optional collections remain opt-in. No model, input history
or personal data is bundled. Restart both host and panel after pack changes;
there is no live reload or executable-plugin loading.

## Validation and release gate

The latest development snapshot, **before this release's metadata and exact
commit acceptance**, passed **1,155 non-ignored all-features Rust tests**, strict
all-target Clippy, formatting and 21 functional-tensor checks. The **27 opt-in
Rust tests** remain separately enabled gates, not additional passes.

During development, complete default/inline private IBus gates covered bilingual
input, paging and long-draft boundaries. The final Japanese sentence-progress
changes passed focused private IBus checks in both preedit modes and four focused
GTK/XTest workflows, including editable word adoption, continued typing, undo and
observed exact editor saves. These focused results do **not** mean the complete
IBus or 89-workflow GTK vocabulary gates were rerun on that final snapshot.
Earlier failures and their subsequent fixes remain in the
[development record](../../DEVELOPMENT.md).

After synchronizing 0.8.2 metadata, all **1,155 Rust tests** passed again, with
0 failures and 27 opt-in skips; strict all-target Clippy, formatting, shell syntax,
21 tensor tests and full-history/staged secret scans passed. Local ShellCheck
was unavailable; its required CI step is unchanged. Rust/lockfile, macOS bundles
and Android use **0.8.2**, with platform build numbers **32**. Third-party locked
versions are unchanged. These checks do not replace complete exact-commit CI.

**At release preparation, exact-commit CI and package acceptance for 0.8.2 are
still pending.** Publish the `.deb`, binary `.tar.gz` and both SHA-256 files only
after the exact clean tagged commit passes Ubuntu 24.04 CI, package-content
checks and clean-container installation/upgrade/removal checks. Source tags or
expiring CI artifacts alone do not satisfy the release requirement; see the
[Linux release gate](../linux-packaging-data.md#从-080-开始的发布要求).

An investigated private IBus daemon abort on Ubuntu 26.04 / IBus 1.5.34-rc2 /
GLib 2.88 is **not declared fixed** by this release. Passing isolated Xvfb/XTest
checks also does not establish personal-desktop, physical-keyboard/touchscreen,
native Wayland, arbitrary multi-monitor/DPI or live-model quality acceptance.
Japanese still has no extended long-draft local window. See
[known limitations](../known-limitations.md).

## Install / upgrade

After approved 0.8.2 assets have been attached to the GitHub Release, finish or
cancel the current draft, fully quit Suzaku, and verify/install on Ubuntu 24.04
amd64:

```bash
sha256sum -c suzaku_0.8.2_amd64.deb.sha256
sudo apt install ./suzaku_0.8.2_amd64.deb
/usr/bin/suzaku-panel
```

For a first installation, explicitly register as your desktop user, **without
sudo**: `/usr/bin/suzaku-tool linux-register install`. Package installation alone
does not activate input or register/start a user service. Upgrade host and panel
together; existing configuration, cloud consent and user pack data remain.
Keep original pack JSON files for recovery.

For the tarball, verify `suzaku-0.8.2-x86_64-unknown-linux-gnu.tar.gz.sha256` and
the extracted `SHA256SUMS`, then start `./bin/panel`. It is not a universal static
Linux build. Source/user-level installations need their own rebuild/reinstall;
preparing this release does not update the personal desktop installation.
See [installation and data](../linux-packaging-data.md),
[input behavior](../ibus-candidates.md) and [privacy](../privacy.md).
