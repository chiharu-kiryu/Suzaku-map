# Suzaku 0.5.8 · Linux Alpha lifecycle and input-target patch

For **Ubuntu 24.04 amd64, IBus, X11 / GNOME XWayland**. This remains an Alpha;
keep a fallback input method. Other platforms are not release-qualified.

This patch collects functional-network fixes **N19–N23** after 0.5.7. It does not add a model
dependency, change the continuous-writing keys, or automatically submit tool results.

## Highlights

- **Reliable quit retries (N19):** stopping the host no longer causes a later Quit to skip an
  unfinished input-method restoration. The observed fallback is retained until recovery is confirmed,
  including when a stop completes after its acknowledgement is lost. A valid manually chosen input
  method still takes precedence; the controller never guesses a default.
- **Queued service cleanup (N20):** an inactive managed service can still have a pending start job.
  Suzaku retains cleanup responsibility until stop/cancellation is acknowledged or the unit is gone,
  so an unconfirmed startup is not abandoned when the panel quits. Custom hosts remain independently owned.
- **Single-instance startup (N21):** a failed lock or handoff to an existing panel now rejects the
  extra launch instead of opening another unguarded window. Normal duplicate launches still request
  that the existing panel be shown; sending that request is not a display acknowledgement.
- **Candidate wakeups (N22):** switching to a new input field or host can show the hidden companion
  even when its latest-only update queue merges the intermediate empty state. Manual hiding remains
  bound to the old field; privacy, panel focus, settings and no-focus-backend protections remain intact.
- **Tool adoption gestures (N23):** pressing a voice-insertion button or handwriting candidate in one
  field and releasing after a target change no longer inserts into the new field. Host/context/language
  changes, disconnection and observed privacy/focus transitions invalidate the old gesture. Sources are
  retained for a fresh click; same-field refreshes and independent local editing continue to work.

## Validation and compatibility

- Feature-enabled regression suite: **823 passed, 0 failed, 22 opt-in tests skipped** by the ordinary
  command. Skipped tests are not counted as passed.
- Private runners passed **14 panel UI groups and 1 executable-startup group**, plus the native IBus
  chain. The new tool-gesture regression covers **64 combinations** of mouse/touch, tool and target
  transitions, alongside existing automatic-insertion and caret-boundary regressions.
- Lifecycle failure timing uses synthetic backends; GUI and IBus checks use private Xvfb/D-Bus and
  synthetic drafts. They do not operate the development desktop's input method, real microphone or
  model accounts, or establish full GNOME/systemd fault, native Wayland or other-platform acceptance.
- Strict Clippy is checked for both `--all-features --all-targets` and `--features gpu --all-targets`
  with `-D warnings`. Audit reports are included in the explicit Linux documentation package list.
- Formatting, whitespace and Linux script lint pass; staged secret scanning reports no leaks.
  All **26 audit-document links** checked in the source tree resolve. This is not a built-package check.

Rust, macOS bundle and Android app metadata all use **0.5.8**; the bundle build number and Android
version code are **12**. This aligns metadata without expanding native-platform support.

## Install and upgrade

This source patch is not an attached binary package. Once matching release assets are available,
verify `suzaku_0.5.8_amd64.deb` with `sha256sum -c suzaku_0.5.8_amd64.deb.sha256`, fully quit Suzaku,
then install using `sudo apt install ./suzaku_0.5.8_amd64.deb`. Existing configuration is retained.
See [Linux packaging/data](../linux-packaging-data.md) for source builds and package validation.
No package is installed on the development desktop as part of preparing this patch. Container
installation/upgrade/removal and fresh distributable packaging were not rerun for this source commit;
the local tests do not imply that remote CI has run or release assets exist.

Linux speech remains a simulated bridge, handwriting and offline CJK dictionaries remain limited,
and input/recovery drafts are still in memory. This patch adds no migration, automatic model download,
new cloud consent or change to Enter/candidate-click submission.
