## 失败与定位

[0.6.7 远端 CI](https://github.com/chiharu-kiryu/Suzaku-map/actions/runs/35999054457)
的 Rust、两种原生预编辑、界面、GTK 及物理键盘步骤通过，系统候选弹窗步骤在第二页
序号点击后的文件检查失败，后续打包步骤未执行。该次 CI 仍是失败，不追认为通过。

本地原夹具先完整通过一轮，下一轮也在候选提交后的文件检查失败。增加仅针对自有
合成文件的诊断后，再次复现清空后的保存失败：文件仍为 `help me with this, please.`，
而隔离屏幕截图里的编辑器正文已经清空，标题显示未保存。这不是草稿快照就能判定的结果。

共享 `save_document` 原来发送 Ctrl+S 后只比较文件内容；内容一匹配就进入下一次编辑。
确认这是一个不完整的完成条件：GNOME Text Editor 46.3 的文件保存还包含后续异步
元数据处理，忙碌期间 Save 动作不可用。文件可读到新内容，不代表下一次保存已经可用。
源代码依据：[文档保存与 busy 生命周期](https://github.com/GNOME/gnome-text-editor/blob/46.3/src/editor-document.c)、
[Save 动作启用条件](https://github.com/GNOME/gnome-text-editor/blob/46.3/src/editor-window-actions.c)。

首版仅增加进度条等待仍复现了一次 `正文=help、文件为空`，不能算作修复完成。
随后用只在自有测试进程加载、原样转发调用的临时追踪器观察 Save 启用状态与文件保存
开始时间。恢复旧文件校验路径做负向对照，再次捕获失败：在保存清空结果的按键发出后
约 2 ms，编辑器自行开始后台保存并短暂禁用 Save；原文文件仍有 `日本語`，同一时刻
更新的编辑器草稿备份却为 0 字节。结合上述源码，这支持保存按键撞上后台草稿保存的定位。
该追踪器仅作诊断，没有修改系统二进制或进入正式测试/安装；临时旧校验开关已移除。

后台保存可以在「看到空闲」之后、按键到达之前启动，单纯等进度条或拉长 sleep 并不能
消除这个窗口。仍不能把第三十八/三十九轮每次历史异常都归为同一原因，也没有证据将
它们全部归为 Suzaku 候选提交缺陷。

## 修复与边界

- 仅对运行器直接启动的 GNOME Text Editor 进程启用无障碍观测，按已登记 PID 与
  自有文件名限定正文窗口。没有读取个人窗口、使用剪贴板或执行无障碍输入动作。
- 仅这些测试编辑器使用一次性 keyfile 设置，并回读确认 `auto-save-delay=300`；
  运行器原有 240 秒总期限不变，避免编辑器后台草稿备份与用于校验的 Ctrl+S 竞争。
  配置路径不是自有临时目录或设置未生效时直接失败。个人编辑器、Suzaku 宿主及其他
  测试进程的设置不变，实体 Ctrl+S 的手动保存逻辑不变。
- 编辑器另用独立的临时配置目录，只对它关闭 GTK 装饰动画，避免每次状态检查都等
  保存进度条的一秒淡出；测试期限仍为 240 秒，不改变产品动画或其他应用配置。
  通过编辑器进程的 `XDG_CONFIG_DIRS` 添加 GTK 默认值，保持与测试 IBus 共用的
  `XDG_CONFIG_HOME` 不变；不能隔离掉其重连依赖的发现文件。
- 一次实体 Ctrl+S 前，等待实际编辑器正文与预期严格一致，且加载/保存进度指示消失；
  之后同时核对正文、指示消失和保存文件。不把宿主的空草稿快照视为应用已保存。
- 只按 GtkSourceView 的既有约定计算隐含末尾换行；空格、Unicode、制表和额外换行
  不剥离、不规范化，正文缺字或旧文件匹配都不能误通过。
- 每次只发送一个保存组合键，不重发文本、点击或提交，不重试失败的保存。每个状态
  等待沿用有界观察；没有为通过测试增加固定延迟或降低断言要求。
- 观察缺失、编辑器退出、目标歧义、正文或文件不符均失败；失败信息只包含自有合成
  文档。共享检查用于 GTK、键盘、候选弹窗、生命周期与总线重启场景。
  对自有编辑器关闭状态缓存，并按控件身份去重，避免旧状态或重复节点被误当作当前目标。
- GTK3 候选窗只在读取其自有应用树前清除缓存，重启后也必须观察到真实可见候选；
  不清整个桌面，不替代鼠标操作。无障碍桥只在目标编辑器/候选窗启用，不在测试控制器
  及其他子进程全局启用。页检查失败会报告预期与实际可见标签。

进度指示是针对当前 GTK 编辑器版本的测试同步点，不是对所有应用/Wayland 的保存协议。
没有修改系统编辑器或 IBus，也不把经过隔离的检查称为编辑器默认自动保存/动画时序验收。
GTK 配置位置与缓存清理范围分别依据
[GtkSettings 文档](https://docs.gtk.org/gtk4/class.Settings.html) 和
[AT-SPI clear_cache 文档](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/method.Accessible.clear_cache.html)；
IBus 对发现文件变化的重连监听见
[IBus 1.5.29 总线实现](https://github.com/ibus/ibus/blob/1.5.29/src/ibusbus.c)。

## 验证

- 新增 **14 项**不依赖显示的确定性测试，通过。涵盖保存忙碌、旧文件假阳性、正文
  不一致、保存后正文变化、错误不重试、观测丢失、换行约定、已退出进程拒绝、PID/标签范围、
  缓存别名去重、候选窗可见状态刷新及配置隔离/回读校验。
- 初版观察器在第二编辑器启动时发现重复文字区：日志确认是同一 AT-SPI 对象被遍历
  两次，不是两个文档。现按对象身份去重并防止循环，不按内容/名字合并不同对象；
  只认已登记窗口内实际获得焦点的多行正文，对真正的多个目标仍失败，新增确定性回归。
- 探索性方案没有全部通过：整体缓存清除/GTK3 全禁缓存尝试出现启动阻塞；保留每次
  保存淡出动画的版本使键盘测试超过原有期限。已撤去这些方案，不延长期限掩盖超时。
  仅清自有候选窗缓存前，重启实测还出现过「截图已有 fresh，观察器却读不到」的失败。
- 初版将编辑器 `XDG_CONFIG_HOME` 一并分开，打断其原有 IBus 发现文件监听，导致
  总线重启检查停在默认假焦点而非应用上下文。现保留共享的私有发现路径，仅附加 GTK
  配置目录，并在确定性测试中锁定这一约束；没有增加应用重启或重新点击来掩盖问题。
- 最终版本在本机 Ubuntu 24.04、GNOME Text Editor 46.3、私有 Xvfb/D-Bus/IBus 中
  复验通过：双编辑器正文/焦点返回 **2** 组、GTK 应用输入 **8** 组、物理键盘 **44**
  组、实际生命周期 **21** 组、私有总线启动/重启 **13** 组。
- 最终版本的系统候选弹窗检查完成 **3 次全量通过，每次 46 组**，每次均含 **17**
  组上标字形点击；正文、上标点击与真实保存断言保留，没有通过重发事件把失败变通过。
- `functional_network_audit` **7** 项通过；**17** 个 Python 源文件与 CI YAML 解析、
  两个改动 shell 脚本的语法/ShellCheck、**174** 条打包审计链接、功能图对应关系、
  **40** 份审计的打包清单及 `git diff --check` 通过。变更内容密钥扫描未发现泄漏。

这些应用检查复用现有 debug 二进制，产品源码未变。本轮没有重跑全量 Rust/Clippy、
浏览器/Qt/真实模型质量、打包安装或原生 Wayland 验收；新增 CI 步骤尚未在远端执行。
临时追踪器与本轮保留的合成测试目录已清理，未删除个人文件。

旧版完整流程也曾连续通过三轮，因此单次新通过不足以证明所有低概率异常消失。
本轮不修改旧版本审计的失败记录，不冒充远端 CI 复跑或实机安装验证。
