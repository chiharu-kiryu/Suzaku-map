## N46：旧结果作废了，旧推理仍占住工作线程

原 [预测线程](../src/ime/prediction.rs) 只有一个后台任务和一个可替换待办。编辑后虽然旧
修订的结果不会回填，但 `generate_checked` 仍等待完整响应/超时；最新待办无法开始。
因此前台能继续打字，不代表当前草稿能及时开始获取模型候选。

先用自有回环服务复现：第一条 `old` 请求不回复，观察连接一秒后才由夹具关闭；此时输入
`h` → `he` → `hel`，下一条请求会立即得到完整的合成候选。修复前断言失败：旧连接没有
自行关闭，最新草稿等了 **1057 ms**。修复后同一回归通过，一次定向观测为 **124 ms**，
基本只剩原有 120 ms 防抖。这里是确定性排队回归，不是模型生成性能基准。

## 修复范围与不变的边界

- [提供器接口](../src/languages/llm.rs) 增加每请求的单向取消标记。前台只设置标记，不等待
  网络、不加入线程；保留一个工作线程、一个待办和一个结果槽，不随按键创建请求线程。
- 编辑、明确取消、提交、锁定候选、清理焦点、禁用、重载和销毁都会通知旧候选任务取消；
  修订检查仍是结果发布的最后一道保护，旧的取消错误不污染新草稿状态。
- [本地传输](../src/languages/model.rs) 在已连接的读写过程中使用最多 50 ms 的检查间隔。
  短暂静默不等于请求超时；每次仍检查同一个绝对期限。部分写入只推进已有请求的偏移，
  不重新连接、重发整个请求或自动重试。
- [模型发现](../src/languages/model/runtime.rs) 使用相同取消标记。取消的发现不写入 5 秒
  失败缓存，取消的生成也不清除有效清单；新输入能立即重新发现/复用已有解析结果。
- 完整 HTTP/JSON、Ollama 完成状态、compatible 完成原因、Unicode、前缀和长度限制不变。
  不从半截响应提取看似完整的候选，不增加默认期限、预热、模型切换或云端回退。

**不是全链路 50 ms 保证**：操作系统调度、连接建立和共享发现锁等待仍可能增加延迟。
[云端阻塞 HTTPS](../src/languages/model/transport.rs) 及未覆盖协作取消方法的既有自定义
提供器仍等待原调用完成/超时，然后丢弃结果；没有用脱离管理的并发请求模拟取消。
翻译使用自身异步流程，本轮没有为翻译接入传输层在途取消。
连接关闭不能撤回已经发出的输入，也不能保证任意兼容服务立即停止计算。

## 验证

### 1. 合成套接字与既有提供器

新增 [8 项回归](../src/languages/model/cancellation_tests.rs)，覆盖：

- 最新草稿不再被旧生成阻挡；快速编辑只保留最后一个待办。
- 清空、取消、提交、切框、选择、禁用、重载和销毁时实际关闭旧连接；前台操作不等待。
- 旧接口提供器的进入/返回取消保护，以及独立新请求不会继承旧取消状态。
- 预先取消的本地/已授权云端请求不建立连接。
- 跨多个静默检查间隔的完整响应，以及分片 UTF-8、Content-Length/chunked 响应正常返回。
- 有完整 JSON 内容但 HTTP 长度/终止块不完整时取消，不能把局部内容当成成功候选。
- 静默与持续滴流都受同一个总期限约束；不因轮询/新字节而无限延长。
- 发现取消后立刻重新发现成功，生成取消后复用清单，不发多余清单请求。

完整全功能 Rust 测试 **848 通过、0 失败、27 忽略**；原有 14 项预测集成回归也通过。
这些测试不需要外部服务，有限监听器均由测试自身创建。

### 2. 私有原生 IBus 与面板

[原生运行器](../scripts/test-native-sync.py) 新增 8 个真实宿主边界：编辑、Esc、Enter、
语言切换、密码用途、关闭联想、模型重载、活动引擎销毁。夹具先确认请求已到达，保持
不回复，再验证 500 ms 内连接关闭；编辑和重载后还要求新请求正常产生模型候选。
一次完整运行的关闭耗时为 **49.3–59.4 ms**，提交载荷和草稿清理断言均通过。

既有延迟回复夹具同步识别对端关闭，并允许回复阶段出现 BrokenPipe/ConnectionReset；
“已尝试结束旧回复”不等于“成功返回模型候选”，Ready 场景仍独立要求有效模型来源。
完整 `scripts/test-linux-ci.sh ibus` 及 `ui` 的 **17 项**私有窗口/入口测试通过。
只使用自有 D-Bus、Xvfb 与临时配置，不操作个人桌面输入源。

### 3. 真实 Chrome → IBus → 本机 LLaMA

用已有的 `llama3.2:3b`，经 [透明观察转发器](../scripts/test-linux-model-live.py) 转到
`127.0.0.1:11434`；不合成模型回复、不下载权重、不修改或重启用户的模型服务。
开启 `SUZAKU_MODEL_QA_REQUIRE_CANDIDATE=1` 后，**7 组流程通过**。

| 实际输入边界 | 关闭上游连接耗时 |
| --- | --- |
| `hel` 推理中继续输入 | 41.1 ms |
| `please sen` 推理中 Esc | 39.8 ms |
| `good m` 推理中切到密码框 | 91.8 ms |
| `public again` 推理中关闭联想 | 41.1 ms |

这四项都要求在请求实际发出 250 ms 内触发边界，并在其后 500 ms 内观察上游连接关闭；
自然完成或等待原 1200 ms 期限不能当作取消通过。密码内容不产生请求，观察记录只含合成
文本；服务端是否同时停止计算未作断言。

严格正向组仍仅将私有测试预算设为 5000 ms，`Could you sh` 获得来源为 model 的
`Could you show` / `Could you shift`。数字采用、撤回、重新采用当前模型候选、续写
` today` 和 Enter 精确单次提交通过。整轮观察到 7 次实际请求、5 次上游连接关闭。

**默认期限问题仍保留**：本次默认 1200 ms 的 `hel` 为 Unavailable，离线候选选择、撤回和
提交仍通过；不能算实模生成成功。本轮解决旧任务排队，不改变单次 CPU 推理速度，也不
推翻上一轮的超时和翻译质量限制。
