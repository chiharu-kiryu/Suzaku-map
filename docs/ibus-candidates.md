# IBus 词句候选体验

本轮针对 Linux 原生 IBus 候选窗；英、中、日语言仍由托盘的「输入语言」切换。
不启动新的键盘监听器，不切换其他应用的输入焦点。

## 输入与候选

| 模式 | 输入 | 本地词候选示例 | 本地句子候选示例 |
| --- | --- | --- | --- |
| English | `hel` | `hello`、`help` | `hello, how are you?` |
| 中文拼音 | `nihao` / `ni hao` | `你好` | `你好，很高兴认识你。` |
| 日本語・ローマ字 | `nihongo` / `niho` | `日本語` | `日本語を勉強しています。` |

英文保留大小写、空格和原始字母。中文支持连续拼音和分隔拼音；日文支持罗马音补全、
假名转换，以及小词库的分段汉字转换，例如 `nihongo wo benkyoushitai` → `日本語を勉強したい`。
原文始终保留为可选项，未知标识符不会被随意拼接成本地英文句子。

英语的本地词与句子候选共用明确的常用搭配。空格、逗号后的续写和下一个词的半截拼写
不会把已经匹配的句子候选丢掉，例如 `please send ` → `please send me` / `please send me the details.`，
继续写到 `please send me the d` 仍可选完整词或句子；`let me know ` 也能接上 `what` / `if`。
只补充明确匹配的后续文本，不强制纠错、不改写已输入的大小写或重复空格，不把之前已提交的
上下文重新塞入草稿。不认识的拼写、URL、路径和标识符仍保持原文；这不是完整语法检查器。

0.5.6 还统一了英文直撇号与弯撇号的词库匹配：`we'` → `we're`、`we’` → `we’re`，
不会替换已输入的符号或大小写。单引号中的 `'hel` 和 `He said 'please sen` 也能补词和续句；
不会自动补闭合引号，也不会把缩写、标识符中间的撇号当成新单词的起点。
这些改进已纳入 0.5.6 源码，0.5.5 安装包不包含。

末词还没有拼完时，也会保留前面已经识别的内容，例如 `woxihuanbei` → `我喜欢北京`、
`watashihanihong` → `私は日本語`，同时提供已覆盖的短句搭配。`ᵂ` 在这种情况下表示
补全最后一个词，提交/补全的替换文本仍包含整个预编辑，不能丢掉前缀。
接受转换后还能继续字母输入，例如 `日本語` 后接 `wobenky` → `日本語を勉強`。
中文空格和撇号明确保留音节边界：`xi an` / `xi'an` → `西安`，与 `xian` → `先` 区分。

离线句子来自明确的常用搭配，不是假装由模型生成。启用「LLM 联想」后，本地/云端模型
异步补充候选，统一接口请求词和短句两类输出，不依赖 LLaMA 或其他特定模型名称。
没有模型、超时或结果无效时，离线候选仍可使用。

这是基础词库和短句联想，不是完整中日文词典、日文形态分析器或任意长句转换系统。
不是每个未知拼写都能生成两类有效候选；有结果才显示，不用无关句子凑满列表。

### 英文补全质量回归（0.5.6）

优先使用匹配更长上下文的明确搭配，而不是只看最后一个词。例如 `how can I ` 优先补 `help`，
不会被孤立的 `I → am` 抢位；`I would like to ` 优先 `know` / `ask` / `schedule`，
`we need to t` 优先 `test`，不套用泛化的 `to → the`。同样长的搭配仍保留自己的顺序和备选。
前文只参与排序，替换文本不重复已提交内容。单独输入 `can` 时仍保留 `can't` 等词尾补全。

补充了缩写、请求、回复和开发协作的常用短句，例如 `I’m w` → `I’m working` / `I’m working on it.`，
`could you sh` → `could you share` / `could you share the link?`，以及 review changes、run tests、
fix the bug 等搭配。这些是项目编写的有限离线词句，不是模型训练、自动学习或完整语法理解。

若英文模型仅返回 `please reconsider the proposal.` 这样的长句，而当前输入为 `please rec`，
会额外提取已经出现在句子中的 `please reconsider` 作为词候选，原句仍可单独选择。
空格后的下一个词也适用；不改写输入前缀、不把 URL、路径或连字符表达式拆成假词。
提取项保留 AI 来源、去重后参与原有混排；若与离线词相同，仍保留本地来源和固定位置。
数字采用、立即退格撤回、空格继续写和 Enter 提交的边界不变。

固定样例位于 [english_completion_quality.rs](../tests/english_completion_quality.rs)：

| 同一组 40 条项目编写的写作场景 | 本轮修改前 | 本轮修改后 |
| --- | --- | --- |
| 目标词出现在首页前三个非原文词候选中 | 15 / 40 | 40 / 40 |
| 目标短句出现在首页六项中 | 13 / 40 | 40 / 40 |

这是针对明确场景的回归集，词句与测试均由项目编写，**不是独立语料测评或通用英文准确率**。
模型链路用隔离模拟服务验证，不代表任意真实模型的语言质量。另有原文、代码/URL、结束标点、
候选去重、模型词句拆分和提交上下文隔离测试；实际 IBus 测试覆盖数字采用、撤回、续写与独立提交。
以上改进已纳入 0.5.6 源码，0.5.5 安装包不包含。

## 上下标和排序

例如 `hello ᵂ₉₂`、`hello world ˢᴬᴵ₈₅`：

- `ᵂ`：词补全；`ˢ`：短语/句子；`ᴿ`：原文。
- `ᴬᴵ`：由模型新增的候选。本地候选与模型重复时只调整权重，不改写本地来源。
- 下标 `₀`–`₁₀₀`：排序权重，**不是正确率、置信概率或持久化学习统计**。
- 行号 `¹`–`⁶`：当前页的选择编号，与右侧权重无关。

无法可靠分类的日文未完成读音仅显示权重，不把半截假名标成句子。

候选最多 12 个，每页 6 行。英文原文与最佳本地词补全、中文/日文首个本地转换保持固定，
以免模型返回后 Space/Tab 的目标变化。其余项按有界权重排序；首页在可用时预留两项词和
两项句子的位置，因此类型覆盖与固定首项优先于全列表严格降序。无法满足配额时不填假项。
开始选择后锁定列表，直到下一次编辑；旧请求不能覆盖新输入。

预览包含上下标最多 42 个 Unicode 码点，超长句加省略号。提交使用独立的完整原文，
不会提交行号、上下标、省略号或 AI 标记。伴随面板也继续接收完整文本和选择索引，
新类型/来源/权重字段是协议 v1 的可选扩展，旧帧仍可解析。
连续提交时也逐次使用候选原文，不从累计上下文裁剪；候选自带的前导、末尾和全角空格
都不会因此丢失。Space 是当前草稿中的分隔空格，不再触发提交。

英文长草稿优先省略与当前预编辑相同的前缀，让候选末词和新续写能看清，例如几行很长的
`For the next release ... docu` 不再都截成相同的开头。省略只发生在预览；模型若改写了开头，
仍显示不同的开头，不把差异藏起来。IBus 与伴随协议使用同一预览规则，原文载荷完全不变。

使用 Unicode 上下标，而非依赖自定义字体大小或 HTML 标记。
[IBus 标准文本属性](https://github.com/ibus/ibus/blob/main/src/ibusattribute.h)
不提供任意垂直偏移属性；具体字形、字号和候选窗外观仍由桌面 IBus 面板及系统字体决定。

## 键盘

| 操作 | 效果 |
| --- | --- |
| Tab / Shift+Tab、方向键 | 下一项 / 上一项 |
| PageDown / PageUp | 下一页 / 上一页，每页 6 项 |
| 1–6 | 三种语言均采用当前页对应候选，完整文本留在草稿中继续联想，不上屏 |
| Alt+0–9 | 输入普通数字，不选择候选；保留 Shift+数字原有的 `! @ #` 等键盘布局符号 |
| Space / Shift+Space | 已显式选中候选时采用该候选，再加分隔空格；否则仅插入分隔空格，继续连写 |
| Shift+Enter（含小键盘 Enter） | 将当前候选放回预编辑，不上屏、不加空格；词与完整 AI 句子均可继续编辑 |
| 补全后立即 Backspace | 撤回刚才的补全，恢复原拼写；普通输入或再次选择候选后恢复逐字符退格 |
| 英文草稿中 Ctrl+Backspace | 删除末尾按空白分隔的一个词及其后空格；缩写、附着标点和 Unicode 字符一起删除，不动应用内已提交的文字 |
| Enter（含小键盘 Enter）/ 左键点击候选 | 提交所选项并结束本次草稿，不额外添加空格 |
| 标点 | 保留在当前草稿中，不自动提交 |
| Esc | 清空本次预编辑和候选；有未完成的 Compose 组合时先仅取消组合 |

这是连续写作输入模式：空格、数字选词和标点都不是提交边界。例如英文输入 `please`，Space，再输入 `sen`，会保留 `please sen` 并给出
`please send` 和短句。日文分隔空格不进入转换后的日文，但完整罗马音原文仍可选择。
输入 `hel` 后按 `2` 采用 `hello`，Space 后接 `world!`，整个 `hello world!` 始终可编辑，
直到 Enter 或左键点击候选才一次性上屏。Tab 选中 `hello` 后直接 Space 同样得到 `hello `。
这些续写操作不会生成应用提交事件、不会加入已提交上下文，也不会带入候选展示标记。
开发版对已经接受的纯空格草稿保留字面候选：Enter 或候选左键点击会精确提交这些空格并清稿，
包括屏幕键盘输入和英文删词后只剩空格的情况。纯空白不触发模型请求；空草稿上的实体 Space
仍直接交给应用，不改变数字/密码字段的直通策略。
有候选时，主键区没有对应行的数字键不插入数字（包括当前六行布局未使用的 `0/7/8/9`）；
没有草稿/候选时数字可直接起笔，小键盘数字始终按字面输入。需要连续输入 `2026`、版本号、
标识符中的数字时使用 Alt+数字或小键盘；不修改系统布局、Caps Lock 或其他应用的快捷键配置。
仅保留一步临时撤回内容；清空、切换语言、切换隐私状态和失去焦点都会清除它，不写入磁盘。
除明确保留的 Alt+数字外，AltGr、Ctrl/Alt 组合应用快捷键不作为选词键。Super/Meta/Hyper 及桌面传入的 Mod4
组合键直接交还应用，不改写、翻页或提交当前候选；Caps Lock、Num Lock 不阻断普通输入。
原生候选只接受不带应用快捷键修饰的左键点击；右键、中键、滚轮和按键释放事件不会提交。
密码/PIN，以及应用明确标记为数字、数值或电话用途的输入框，直接绕过引擎，
包括普通数字、正负号、小数点、电话符号、小键盘与编辑按键；也拒绝面板注入。
未正确标记用途的输入框仍按普通文本处理。
隐私字段不请求模型，也不向伴随面板暴露候选。

Ctrl+Backspace 只在已有英文预编辑时由 Suzaku 处理；空草稿、中日文模式、密码字段以及
带 Shift/Alt/AltGr/Super 的其他组合仍交还应用。它是删词，不是补全撤回；不会恢复已清掉的旧拼写。

新的 FocusIn 会建立空白输入会话，清除之前的预编辑、补全撤回和模型上下文，即使旧
FocusOut 尚未到达。未获焦的引擎对象不能通过迟到按键、翻页或选词改变当前输入框；
旧对象的 Reset/Disable/FocusOut 也只清理自身。当前输入框内连续提交的上下文仍可用于联想。

### 重音字母与 Compose（0.5.6）

Linux IBus 现在使用 [libxkbcommon Compose](https://xkbcommon.org/doc/current/group__compose.html)
完成重音键和 Compose 序列，再将结果追加到当前草稿，例如 `caf` + `dead_acute` + `e` → `café`，
Compose + `'` + `e` → `é`，Compose + `1` + `2` → `½`。这里的 Compose 指键盘布局配置的
组合键，不是同时按下这些字符。英文模式也允许直接用 `é`、`É` 等拉丁字母起笔。

组合过程中显示 `Compose…`，临时隐藏原生候选；数字和空格先用于完成组合，不选择旧候选。
组合完成后仍然可继续打字、空格、退格，只有 Enter 或点击候选才提交。
Esc / Backspace 先取消未完成的组合而不删除原草稿；不匹配序列的最后一个可打印字符按字面保留，
不会意外变成数字选词。Shift、Caps Lock 和按键释放不会吃掉正在组合的重音；应用快捷键取消组合后交还应用。
重置、语言/隐私切换、失焦或新的 FocusIn、面板替换草稿都会清除未完成序列，不带入下一个输入框。

组合表按系统语言环境及 XCompose 配置加载，宿主进程中只读取一次；修改组合表后需重启宿主。
不修改系统键盘布局、Caps Lock 或其他应用设置。未完成的按键序列不传给模型；组合后的草稿仍遵循原有
模型授权和隐私规则。缺少有效组合表时此能力不可用；仅支持最长 255 个 UTF-8 字节的可打印结果
（系统库可能有更小的限制），
不截断、不当成快捷键执行。未被组合表接受的序列仍按上述规则保留最后一个可打印字符。
0.5.6 源码包含此修复，0.5.5 不包含；任意桌面/布局仍需实际验证。

## 原生镜像的屏幕键盘

快速连续点击会先保留完整的本地草稿，同一时刻只发送一个替换请求。收到成功确认与
对应的新草稿快照后，才发送积累的后续编辑；确认和快照乱序到达也不会吞掉后一个字符。
退格和空格同样参与合并。相同输入框内只更新候选权重，不会取消按住的稳定字母键；
切换输入框、语言、宿主或隐私状态则取消旧按压和待发送内容，不跨输入框回放。

请求超时、被拒绝或物理键盘改写草稿时，不自动重发，也不覆盖新输入。
可点击面板输入框，把保留的键盘草稿取回独立编辑；取回本身不上屏。
确认期间候选与清空/提交动作暂缓，避免把未确认文本误作已发送。请先检查目标应用，
因为确认丢失不代表文本一定没有送达。草稿仅在内存中，不提供崩溃恢复。

## 独立面板的发送确认

未处于原生候选镜像时，面板发送自己展示的候选文本，不替换成进程内另一引擎的候选，
也不发送累计历史。确认送达后才清空当前草稿并记入本地上下文，下一次输入从空草稿开始。
发送被拒绝或确认连接中断时保留草稿，不记作成功提交、不自动重发；确认丢失并不能证明
应用没有收到内容，因此手动重试前应先检查目标应用。
面板候选区的数字快捷键也只把完整候选带回草稿，Space 用于续写，Enter/点击发送。
独立草稿文本框和设置搜索框仍按文本编辑器处理数字，不把编辑动作解释为输入模式切换。

## 验证范围

运行 `bash scripts/test-linux-ci.sh ibus`，在独立 D-Bus/IBus 会话中验证三语候选、
上下标/字体回退、6 项翻页、中日文末词补全、连续输入、预编辑补全/撤回、数字与 Alt 快捷键、长句完整提交、异步选择锁定、
隐私边界、连续提交的空白保真和宿主重启。独立引擎对象还覆盖乱序焦点通知、迟到按键/
翻页/点击、跨输入框模型上下文隔离、两页的鼠标按键和桌面快捷键兼容性。
模型请求还验证：数字选词、连续空格和标点始终属于完整的 `raw_composition`，
只有显式提交后才进入下一次请求的 `committed_context`。
`bash scripts/test-linux-ci.sh ui` 另验证独立面板
词/句发送的确认门槛、准确载荷，以及拒绝或确认丢失时的草稿保留。
IBus 测试还覆盖托盘控制器的三语激活/输入/释放、重复操作和清理时恢复；测试只允许在
私有会话中执行。错误配置（含 FIFO 和指向 FIFO 的链接）重载后仍必须能继续编辑并提交。
模型路径使用固定本地测试服务，不上传真实输入，也不加载实际模型。
不同桌面外观和实际模型联想质量仍需对应环境实测。
英语额外验证逐词续写时首页同时保留词/句候选、长候选的可区分预览和完整发送，以及
Ctrl+Backspace 对当前草稿的边界、Unicode/空格处理和应用快捷键兼容性。
